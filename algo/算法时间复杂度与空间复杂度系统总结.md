## 1. 基本概念

### 1.1 什么是算法复杂度？

算法复杂度分析的是：**输入规模增大时，计算资源需求的增长规律**。

- **Time Complexity**：执行的基本操作数量如何增长。
- **Space Complexity**：内存使用量如何增长。
- 复杂度 **不是**实际耗时秒数，也不是精确字节数。
- 默认的抽象模型通常将固定机器字上的简单运算、比较、数组下标访问等视为常数成本；对长整数、字符串比较、动态分配等不能无条件做此假设。

示例：

~~~cpp
int findMax(const std::vector<int>& nums) {
    int ans = nums[0];
    for (int x : nums)
        ans = std::max(ans, x);
    return ans;
}
~~~

数组包含 n 个元素，遍历 n 次，只增加固定数量局部变量：

- 时间：**Θ(n)**
- 辅助空间：**Θ(1)**

### 1.2 先定义输入规模

| 问题 | 输入规模 |
|---|---|
| 数组 / 字符串遍历 | n = 元素或字符数 |
| 矩阵 | R = 行数，C = 列数 |
| 两个数组 | n、m 为独立规模 |
| 图 | V = 节点数，E = 边数 |
| 0/1 背包 | n = 物品数，C = 容量值 |
| 整数数值算法 | 值 N 与编码位数 b = Θ(log N) 需区分 |

~~~cpp
for (int i = 0; i < n; ++i)
    for (int j = 0; j < m; ++j)
        doWork();
~~~

时间为 Θ(nm)，不能没有条件地写成 Θ(n²)。

> **基本原则**：先确定规模变量、基本操作成本、分析的输入场景，再推导。

### 1.3 为什么忽略常数及低阶项？

对于 T(n) = 3n² + 5n + 10，渐近增长由 n² 主导，因此 T(n) = Θ(n²)。

- 5n = Θ(n)
- n² + n = Θ(n²)
- 100n² + 20n + 3 = Θ(n²)

“忽略常数”只发生在**渐近分类**中。现实中 1000n 和 n² 在小 n 时谁快，需要看常数、CPU、内存访问等。

## 2. 数学记号与增长阶

### 2.1 O、Ω、Θ 的定义

令 T(n) 与 f(n) 在足够大的 n 上非负。

**Big-O：渐近上界**

$$
T(n)=O(f(n))
\iff
\exists c>0,n_0,\;\forall n\ge n_0:\;T(n)\le c f(n).
$$

**Big-Omega：渐近下界**

$$
T(n)=\Omega(f(n))
\iff
\exists c>0,n_0,\;\forall n\ge n_0:\;T(n)\ge c f(n).
$$

**Big-Theta：渐近紧确界**

$$
T(n)=\Theta(f(n))
\iff
\exists c_1,c_2>0,n_0,\;\forall n\ge n_0:
c_1f(n)\le T(n)\le c_2f(n).
$$

由此有：Θ(f) = O(f) ∩ Ω(f)（按函数集合意义理解）。

例：T(n) = 3n² + 5n + 10

- T(n) = O(n²)，也属于 O(n³)，但后者不够紧。
- T(n) = Ω(n²)。
- **T(n) = Θ(n²)** 最精确。

严格小阶符号：

$$
f(n)=o(g(n)) \iff \lim_{n\to\infty}\frac{f(n)}{g(n)}=0.
$$

例如 2ⁿ = o(3ⁿ)，n² = o(n³)。

### 2.2 Big-O 不等于 Worst-case

两者描述的是不同维度：

- **Worst-case / Best-case / Average-case**：针对哪类输入或哪种分布。
- **O / Ω / Θ**：该成本函数相对于什么函数有上界、下界或紧界。

线性搜索：
- 最好：Θ(1)（第一个元素命中）。
- 最坏：Θ(n)（末尾命中或不存在）。
- 若目标必存在且位置均匀分布：平均 Θ(n)。

面试问 “time complexity” 时，常规做法是报告**最坏情况的紧渐近上界**，并解释条件。

### 2.3 常见增长阶排序

对于 n → ∞：

$$
1 \prec \log n \prec \sqrt n \prec n \prec n\log n
\prec n^2 \prec n^3 \prec 2^n \prec 3^n \prec n!.
$$

| 增长阶 | 常见称呼 | 典型示例 |
|---|---|---|
| Θ(1) | Constant | 数组已知下标访问 |
| Θ(log n) | Logarithmic | 二分查找 |
| Θ(√n) | Sublinear | 试除法 |
| Θ(n) | Linear | 遍历数组 |
| Θ(n log n) | Linearithmic | Merge Sort |
| Θ(n²) | Quadratic | 完整双重循环 |
| Θ(n³) | Cubic | Floyd–Warshall |
| Θ(2ⁿ) | Exponential | 枚举子集 |
| Θ(3ⁿ) | Exponential | 三选一搜索 |
| Θ(n!) | Factorial | 枚举排列的叶节点数量 |

### 2.4 对数与指数的关键区别

换底公式：

$$
\log_a n=\frac{\log_b n}{\log_b a}.
$$

对任意**固定** a,b > 1，底数转换只产生常数倍：

$$
\log_2 n=\Theta(\log_3 n)=\Theta(\ln n).
$$

指数不同：

$$
\frac{3^n}{2^n}=(3/2)^n\to\infty,
$$

因此 2ⁿ 和 3ⁿ **不是同阶**。

重要恒等式：

$$
a^{\log_b n}=n^{\log_b a}.
$$

推导：令 k = log_b n，则 n = bᵏ，

$$
n^{\log_b a}=(b^k)^{\log_b a}
=(b^{\log_b a})^k=a^k=a^{\log_b n}.
$$

## 3. 循环复杂度与求和

### 3.1 顺序执行：相加

~~~cpp
for (int i = 0; i < n; ++i) doWork();           // Θ(n)
for (int i = 0; i < n * n; ++i) doWork();       // Θ(n²)
~~~

总成本 Θ(n + n²) = **Θ(n²)**。

### 3.2 独立嵌套循环：相乘

~~~cpp
for (int i = 0; i < n; ++i)
    for (int j = 0; j < m; ++j)
        doWork();
~~~

总成本 **Θ(nm)**（假设 doWork 为 Θ(1)）。

### 3.3 非规则嵌套循环：求和

~~~cpp
for (int i = 1; i <= n; ++i)
    for (int j = 1; j <= i; ++j)
        doWork();
~~~

$$
T(n)=\sum_{i=1}^n i=\frac{n(n+1)}2=\Theta(n^2).
$$

### 3.4 倍增与减半

~~~cpp
for (int i = 1; i < n; i *= 2) doWork();
~~~

i = 1,2,4,...,2ᵏ；k = Θ(log₂ n)，总成本 **Θ(log n)**。

~~~cpp
for (int i = n; i > 0; i /= 2) doWork();
~~~

同样是 **Θ(log n)**。

注意整数溢出、边界 n <= 1 等实现细节不属于大 O 本身，但会影响代码正确性。

### 3.5 调和级数：Θ(n log n)

~~~cpp
for (int i = 1; i <= n; ++i)
    for (int j = 1; j <= n; j += i)
        doWork();
~~~

第 i 次外层循环运行 ceil(n/i) 次，因此：

$$
T(n)=\sum_{i=1}^n\left\lceil\frac ni\right\rceil
=\Theta\left(n\sum_{i=1}^n\frac1i\right)
=\Theta(n\log n).
$$

核心数学事实：

$$
H_n=\sum_{i=1}^n\frac1i=\Theta(\log n).
$$

### 3.6 双指针：即使嵌套也可能是 O(n)

~~~cpp
int right = 0;
for (int left = 0; left < n; ++left) {
    while (right < n && condition(left, right))
        ++right;
}
~~~

假设 condition 为 O(1)，right **单调增加且不重置**：

- left 最多移动 n 次。
- right 在整个程序中最多移动 n 次。

故总成本 **O(n)**，不是 O(n²)。

### 3.7 if/else 与隐藏操作

一次执行只走一个分支，最坏成本取可能发生分支的最大量级。

~~~cpp
for (int i = 0; i < n; ++i)
    std::sort(v.begin(), v.end());  // v.size() == m
~~~

标准比较排序成本为 O(m log m)，故整个循环为 **O(nm log m)**；不能忽略库函数调用成本。

常见隐藏成本：vector/string 复制、insert/erase、sort、hash/比较、分配、内存初始化、遍历容器等。

## 4. 递归与分治

### 4.1 时间递归关系式

常见形式：

$$
T(n)=aT(n/b)+f(n)
$$

- a：递归产生的子问题数量。
- b：子问题规模缩小倍数。
- f(n)：当前节点自己的工作量（不含递归调用）。

**递归树统一公式：**

$$
T(n)=\sum_{\text{各层}}\bigl(\text{节点数}\times\text{单节点成本}\bigr).
$$

### 4.2 模式 A：2T(n/2) + Θ(1)

~~~cpp
void f(int n) {
    if (n <= 1) return;
    f(n / 2);
    f(n / 2);
}
~~~

假设 n = 2ᵏ，第 i 层节点数为 2ⁱ，深度为 log₂n，节点总数：

$$
1+2+4+\cdots+2^{\log_2n}=2n-1.
$$

每个节点常数工作：

- 时间：**Θ(n)**
- 递归栈空间：**Θ(log n)**

为什么空间不是 Θ(n)？因为 DFS 式递归调用不会让整棵树的所有函数栈帧同时存在；同时活跃的只有当前调用链。

### 4.3 模式 B：2T(n/2) + Θ(n)

~~~cpp
void f(int n) {
    if (n <= 1) return;
    for (int i = 0; i < n; ++i) doWork();
    f(n / 2);
    f(n / 2);
}
~~~

第 i 层有 2ⁱ 个节点，每节点成本 n/2ⁱ，因此整层为 Θ(n)；共有 Θ(log n) 层。

- 时间：**Θ(n log n)**
- 栈空间：**Θ(log n)**（假设循环没有另行分配随 n 增长的内存）

### 4.4 模式 C：3T(n/2) + Θ(1)

深度 log₂n，第 i 层 3ⁱ 个节点；总数与最后一层同阶：

$$
T(n)=\Theta(3^{\log_2n})
=\Theta(n^{\log_2 3})
\approx\Theta(n^{1.585}).
$$

栈空间仍为 **Θ(log n)**。

### 4.5 Master Theorem（标准三类）

对 T(n) = aT(n/b) + f(n)，设 p = log_b a（a ≥ 1，b > 1 为常数）。

| 情况 | 条件 | 结论 |
|---|---|---|
| 1：递归叶子主导 | f(n) = O(n^(p−ε)) | Θ(n^p) |
| 2：每层工作相当 | f(n) = Θ(n^p) | Θ(n^p log n) |
| 3：根部工作主导 | f(n) = Ω(n^(p+ε))，并满足正则条件 | Θ(f(n)) |

这里 ε > 0。第三类常用正则条件：存在 c < 1，使足够大 n 有 a f(n/b) ≤ c f(n)。

常见结果：

| T(n) | 时间 |
|---|---|
| T(n/2) + Θ(1) | Θ(log n) |
| T(n/2) + Θ(n) | Θ(n) |
| 2T(n/2) + Θ(1) | Θ(n) |
| 2T(n/2) + Θ(n) | Θ(n log n) |
| 2T(n/2) + Θ(n²) | Θ(n²) |
| 3T(n/2) + Θ(1) | Θ(n^(log₂3)) |

Master Theorem 并非适用于所有递归：例如 T(n−1)、不等规模子问题、多个状态变量等，通常需要递归树、代换、Akra–Bazzi 或其他方法。

## 5. 回溯与搜索树

### 5.1 二叉回溯：T(n) = 2T(n−1) + Θ(1)

~~~cpp
void dfs(int i, int n) {
    if (i == n) return;
    dfs(i + 1, n);
    dfs(i + 1, n);
}
~~~

每个元素有两种选择，深度 n，节点数：

$$
1+2+4+\cdots+2^n=2^{n+1}-1.
$$

- 时间：**Θ(2ⁿ)**
- 栈空间：**Θ(n)**

### 5.2 三叉回溯：T(n) = 3T(n−1) + Θ(1)

~~~cpp
void dfs(int i, int n) {
    if (i == n) return;
    dfs(i + 1, n);
    dfs(i + 1, n);
    dfs(i + 1, n);
}
~~~

- 时间：**Θ(3ⁿ)**
- 栈空间：**Θ(n)**

与分治比较：

| 形式 | 深度 | 时间（节点常数工作） | 栈空间 |
|---|---|---|---|
| 2T(n/2) + Θ(1) | log n | Θ(n) | Θ(log n) |
| 3T(n/2) + Θ(1) | log n | Θ(n^(log₂3)) | Θ(log n) |
| 2T(n−1) + Θ(1) | n | Θ(2ⁿ) | Θ(n) |
| 3T(n−1) + Θ(1) | n | Θ(3ⁿ) | Θ(n) |

**重点不是只看分支数，而是同时看每次问题规模减少多少。**

### 5.3 搜索树节点数 × 单节点成本

~~~cpp
void dfs(int i, int n, std::vector<int> path) {
    if (i == n) return;
    path.push_back(i);
    dfs(i + 1, n, path);
    dfs(i + 1, n, path);
}
~~~

vector **按值传参**：第 i 层 2ⁱ 个调用，每次需要复制 Θ(i) 个元素（假设元素复制常数成本）。总复制工作：

$$
\sum_{i=1}^n i2^i=(n-1)2^{n+1}+2=\Theta(n2^n).
$$

推导不必死记公式，可用上下界：

$$
n2^n \le \sum_{i=1}^n i2^i
\le n\sum_{i=1}^n2^i<2n2^n.
$$

故**时间 Θ(n2ⁿ)**。

同时活跃的调用链上存在长度约为 0,1,...,n 的 vector 副本：

$$
\sum_{i=0}^n i=\Theta(n^2).
$$

故**辅助空间 Θ(n²)**（按通常 vector 容量增长规则及不存全部输出计）。

改为引用并回溯：

~~~cpp
void dfs(int i, int n, std::vector<int>& path) {
    if (i == n) return;
    path.push_back(i);
    dfs(i + 1, n, path);
    dfs(i + 1, n, path);
    path.pop_back();
}
~~~

在不保存所有路径的前提下：时间 Θ(2ⁿ)，额外空间 O(n)。

### 5.4 全排列：n! 与 n × n!

n 个互异元素的全排列共有 n! 种，搜索树的叶节点数为 n!。

- 仅用交换式回溯遍历搜索树，并且每节点只做常数额外工作：**Θ(n!)**。
- 若每个节点都扫描整个 n 元素的 used 数组，成本可能达到 **Θ(n · n!)**。
- 若复制并保存所有完整排列，输出元素总数为 n · n!，故时间和结果空间至少为 **Ω(n · n!)**。

**不要把“输出数量”误当成“实际实现的全部工作量”。**

### 5.5 剪枝与最坏界

容量检查、排序、Bound 等剪枝能够显著降低实际节点访问数量，但不一定改变最坏情况的指数上界。不可把“平均分支数约 1.5”直接当成已证明的最坏复杂度 O(1.5ⁿ)。

## 6. 空间复杂度

### 6.1 总空间与辅助空间

- **Total Space**：输入、输出和算法额外存储的总空间。
- **Auxiliary Space**：一般不计输入及输出结果本身的额外存储。
- 面试必须说明口径，尤其是递归、返回大结果、原地算法。

示例：

~~~cpp
long long sum(const std::vector<int>& a) {
    long long ans = 0;
    for (int x : a) ans += x;
    return ans;
}
~~~

输入为 Θ(n)，但**辅助空间 Θ(1)**。

### 6.2 常见存储

| 代码/结构 | 额外元素存储 |
|---|---|
| 固定数量局部标量 | Θ(1) |
| vector<int>(n) | Θ(n) |
| n × m 矩阵 | Θ(nm) |
| n × C1 × C2 DP | Θ(nC1C2) |
| DFS 调用深度 d、每帧常数空间 | Θ(d) |
| BFS 队列、visited | O(V) |

实际空间还受 vector capacity、容器对象、分配器元数据、哈希表 bucket、对齐等影响。

### 6.3 空间看峰值，不是累计分配量

**Peak Live Memory**：执行过程中某一时刻仍然存活的内存最大值。

例如二叉递归调用次数可能为 Θ(2ⁿ)，但函数栈同时只保留一条长度 O(n) 的路径，故栈空间不是 Θ(2ⁿ)。

### 6.4 输出空间

n 个元素的所有子集：数量 2ⁿ，所有子集中的元素总数为 n2^(n−1)。

如果真正保存为 vector<vector<int>>：

- 输出占用 **Θ(n2ⁿ)** 个 int 存储量级（未计容器元数据）。
- 即使生成器自身辅助空间只有 O(n)，实际完整返回结果仍然占指数空间。

## 7. 动态规划

### 7.1 核心计数方法

$$
\text{DP Time}=\sum_{\text{被计算状态}}\text{该状态转移成本}.
$$

对于每个状态成本一致的密集 DP，通常简化为：

$$
\text{状态数量}\times\text{单状态转移成本}.
$$

空间看同时保存的状态数量与每状态大小，另外计递归栈和其他缓冲区。

### 7.2 一维与二维 DP

~~~cpp
for (int i = 1; i <= n; ++i)
    dp[i] = dp[i-1] + 1;
~~~

n 个状态，转移 Θ(1)：

- 时间 Θ(n)，完整数组空间 Θ(n)。
- 只依赖前一状态时可压缩为 Θ(1) 空间。

~~~cpp
for (int i = 1; i <= n; ++i)
    for (int j = 1; j <= m; ++j)
        dp[i][j] = std::max(dp[i-1][j], dp[i][j-1]);
~~~

- 时间 Θ(nm)
- 完整表 Θ(nm)
- 若只依赖上一行/当前行，空间可降至 O(m)，前提是更新顺序正确。

### 7.3 双背包（DRW 面试讨论模型）

设 n 件不可拆分物品、正整数重量、容量 C1/C2，每件物品最多选一次，目标最多放入多少件。每件物品可选择：

1. 不放；
2. 放背包 1；
3. 放背包 2。

**不使用记忆化的纯暴力 DFS**：最多 3ⁿ 个叶节点，时间 O(3ⁿ)，递归栈 O(n)；在完全展开的情形为 Θ(3ⁿ)。

**DP 状态**：dp[i][a][b] 表示考虑前 i 件物品，两包使用容量分别为 a、b 时的最佳数量（不可达状态特别标记）。

状态数量 O(nC1C2)，每状态常数次转移：

- 时间 **O(nC1C2)**。
- 三维 DP 空间 **O(nC1C2)**。
- 如果仅依赖上一 i 层，滚动数组可降为 **O(C1C2)**。

若要写原地 DP，必须依据依赖方向选择倒序迭代，确保每件物品只使用一次。

**Pseudo-polynomial（伪多项式）**：算法依赖容量数值 C1、C2，而输入中表示容量只需要 O(log C1 + log C2) 位。容量很大时，密集 DP 也可能不可行。

### 7.4 Memoization vs Tabulation

| 角度 | Memoization | Tabulation |
|---|---|---|
| 方向 | 自顶向下、缓存结果 | 自底向上、填表 |
| 访问状态 | 只访问实际展开的状态 | 常按预设范围遍历 |
| 空间 | 缓存 + 递归栈 | DP 表 |
| 额外成本 | 递归、缓存查找 | 遍历/初始化 |
| 优化 | 稀疏可达状态 | 滚动数组、连续内存 |

两者不是普遍意义上的谁一定更快，依赖可达状态比例与实现。

## 8. 经典数据结构与排序

### 8.1 数据结构

| 结构/操作 | 常见时间 | 备注 |
|---|---|---|
| Array/Vector 下标 | O(1) | 已知下标 |
| Vector push_back | **均摊** O(1) | 单次扩容可能 O(n) |
| Vector 中间插入/删除 | O(n) | 可能移动元素 |
| Linked List 已知位置插入 | O(1) | 不含寻找位置 |
| Linked List 查找 | O(n) | |
| Hash lookup/insert | **平均** O(1) | 最坏可能 O(n) |
| Balanced BST | O(log n) | 常见 map/set |
| Binary Heap top | O(1) | |
| Binary Heap push/pop | O(log n) | |
| Bottom-up Heapify | O(n) | 不等于逐个 push |

Binary Heap 完全二叉树高度为 Θ(log n)，单次上浮/下沉不超过树高。

Bottom-up Heapify：多数节点离叶子很近。将各节点高度成本求和为：

$$
O\left(n\sum_{h\ge0}\frac{h}{2^h}\right)=O(n).
$$

### 8.2 排序算法

| 算法 | 最好 | 平均 | 最坏 | 辅助空间（典型实现） |
|---|---|---|---|---|
| Bubble Sort（未提前退出） | Θ(n²) | Θ(n²) | Θ(n²) | O(1) |
| Insertion Sort | Θ(n) | Θ(n²) | Θ(n²) | O(1) |
| Merge Sort | Θ(n log n) | Θ(n log n) | Θ(n log n) | O(n) |
| Quick Sort（经典版本） | Θ(n log n) | 通常 Θ(n log n) | Θ(n²) | 平均 O(log n)、最坏 O(n) |
| Heap Sort | Θ(n log n) | Θ(n log n) | Θ(n log n) | O(1) |

假设元素比较/移动成本为常数，Quick Sort 平均复杂度需明确枢轴策略或分布假设。普通比较排序一般存在 Ω(n log n) 的最坏比较次数下界。

**std::sort**：C++ 标准要求最坏 O(n log n) 次比较；常见实现采用 introsort 思路，不能直接以经典 Quick Sort 的最坏 O(n²) 概括。

## 9. 图算法复杂度

采用邻接表，V 个节点、E 条边；空间列通常指不计输入邻接表的额外空间。

| 算法 | 时间 | 常见额外空间 |
|---|---|---|
| BFS | O(V+E) | O(V) |
| DFS | O(V+E) | O(V) |
| Topological Sort | O(V+E) | O(V) |
| Tarjan SCC | O(V+E) | O(V) |
| Bridge / Articulation Point | O(V+E) | O(V) |
| Dijkstra，二叉堆、允许重复入堆 | O((V+E)log(V+E)) | O(V+E) |
| Bellman–Ford | O(VE) | O(V) |
| Floyd–Warshall | O(V³) | O(V²) |
| Kruskal | O(E log E) | 排序与 DSU 占用视实现 |
| Prim，indexed heap / decrease-key | O(E log V)（连通图常见形式） | O(V) 额外堆与状态 |
| Prim，lazy heap | O(E log E) | O(E) |
| DSU，路径压缩 + 按秩/大小合并 | 单操作均摊 O(α(V)) | O(V) |

### 9.1 为什么 BFS / DFS 是 O(V+E)？

- 每个顶点最多处理常数次：O(V)。
- 所有邻接表的遍历长度合计为 O(E)（无向图遍历两方向是 2E）。

虽然图遍历代码里有 while + for，不是 O(VE)，而是 **O(V+E)**。

### 9.2 Dijkstra 的 log 来自哪里？

二叉堆一次 push/pop 是 O(log H)，H 为当前堆大小。允许重复入堆时 H 最坏可达到 O(E)，所以一般安全写：

$$
O((V+E)\log(V+E)).
$$

对于简单图，通常可写 O((V+E)log V)；对于存在大量平行边的多重图应明确 E 的约束。使用 decrease-key 的 indexed heap 可得到 O((V+E)log V) 一类界限，空间开销和实现复杂度也不同。

### 9.3 DSU 的 α(V)

通过路径压缩与按秩/大小合并，一系列 union/find 操作的**均摊**时间近似 O(α(V))；α 是反 Ackermann 函数，增长极慢。

“接近常数”不等于“严格的每次最坏 O(1)”。

## 10. 平均、期望与摊销复杂度

### 10.1 Worst / Average / Expected / Amortized

- **Worst-case**：最不利输入的成本。
- **Average-case**：在指定输入概率分布下的平均成本。
- **Expected**：对算法内部随机性或指定概率模型求期望。
- **Amortized**：对操作序列计算总成本后，分摊到单次操作；不依赖概率。

### 10.2 vector::push_back 为什么均摊 O(1)？

假设容量以固定倍数（如 2 倍）增长。扩容需要复制/移动已有元素，单次可能 O(n)，但插入 n 个元素的总搬迁次数：

$$
1+2+4+\cdots < 2n.
$$

再加上 n 次普通插入，总时间 O(n)，所以每次 **amortized O(1)**。

**均摊 O(1) ≠ 单次最坏 O(1)**。

提前调用 reserve() 可以在容量未被突破期间规避扩容，但有预留内存、容量估计等权衡。

## 11. 实际输入规模与性能估算

### 11.1 从复杂度转成工作量

| 表达式 | n | 大约操作/状态数量 |
|---|---:|---:|
| n | 10⁶ | 10⁶ |
| n log₂ n | 10⁶ | 2×10⁷ |
| n² | 10⁴ | 10⁸ |
| n³ | 10³ | 10⁹ |
| 2ⁿ | 20 | 1.05×10⁶ |
| 2ⁿ | 30 | 1.07×10⁹ |
| 3ⁿ | 15 | 1.43×10⁷ |
| 3ⁿ | 20 | 3.49×10⁹ |
| n! | 12 | 4.79×10⁸ |

数字表示数学操作量级，不是实际运行时间。

一个简单估算式：

$$
\text{Time}\approx\frac{\text{Work Units}}{\text{Effective Units per Second}}.
$$

假设每秒能处理 10⁷ 个搜索节点，则 3²⁰ ≈ 34.9 亿个叶节点本身对应约 349 秒的工作量量级；完整树还有内部节点，剪枝则可能减少大量分支。**n = 20 不是不可运行的普适硬阈值**。

### 11.2 内存估算

若 int 为 4 bytes：

| 元素数量 | 仅 int 元素内存（十进制） |
|---:|---:|
| 10⁵ | 0.4 MB |
| 10⁶ | 4 MB |
| 10⁷ | 40 MB |
| 10⁸ | 400 MB |
| 10⁹ | 4 GB |

二维 int 数组 10000 × 10000 需要约 400 MB 元素存储，未计容器管理等开销。

O(n) 数组和 O(n) 哈希表虽然同阶，实际内存常数、访问模式可能差距很大。

## 12. C++ / HFT 工程视角

### 12.1 Big-O 没有覆盖真实硬件成本

常见影响因素：

- CPU 指令吞吐与依赖链；
- branch prediction；
- cache line、cache hit/miss；
- TLB / page walk；
- 连续内存 vs pointer chasing；
- NUMA、内存带宽；
- Heap allocation / reallocation；
- 多线程同步与调度。

例：扫描小型连续 vector 是 O(n)，Hash lookup 平均 O(1)，但小 n 场景中 vector 可能更快，因为预取、局部性、分配/哈希开销等。

### 12.2 Latency 与 Throughput

$$
\text{Asymptotic Complexity}
\ne
\text{Actual Latency}
\ne
\text{Tail Latency}.
$$

低延迟系统还需要关注 p50、p99、p99.9、最坏延迟。均摊成本低的操作可能有偶发尖峰，例如 vector 扩容、Hash rehash。

### 12.3 工程上怎样选算法？

结合以下维度：

1. 输入规模 n 和实际数据分布；
2. Worst-case vs average-case 要求；
3. 内存容量与内存访问局部性；
4. 是否需要预分配、避免运行时分配；
5. 数据结构维护/更新频率；
6. 尾延迟预算；
7. Benchmark、perf、硬件计数器和真实工作负载验证。

理论分析帮助排除不可扩展方案，真实 Benchmark 用于在可行方案间选择。

## 13. 面试分析流程与速查表

### 13.1 七步分析法

1. **定义规模**：n、m、V/E、容量 C 或编码位数？
2. **定义成本与场景**：操作是 O(1) 吗？Worst / Expected / Amortized？
3. **找核心工作**：循环、调用、复制、状态转移、容器操作？
4. **计算总工作量**：求和、递归树、递归式、状态数量 × 转移成本。
5. **计算峰值空间**：容器、缓存、临时内存、调用栈；明确输出是否计入。
6. **给出渐近界**：报告 O，能够证明上下界时用 Θ，并说明假设。
7. **估算可行性**：代入 n、内存限制、操作数量、时间预算，再讨论优化。

### 13.2 常见模式一页速查

| 模式 | 时间 | 辅助空间 |
|---|---|---|
| 单层循环 | Θ(n) | Θ(1) |
| 两层完整循环 | Θ(n²) | Θ(1) |
| 倍增/减半循环 | Θ(log n) | Θ(1) |
| 两指针都单调移动 | O(n) | 通常 O(1) |
| 2T(n/2)+Θ(1) | Θ(n) | Θ(log n) 栈 |
| 2T(n/2)+Θ(n) | Θ(n log n) | Θ(log n) 栈，不含额外缓冲 |
| 3T(n/2)+Θ(1) | Θ(n^(log₂3)) | Θ(log n) 栈 |
| 2T(n−1)+Θ(1) | Θ(2ⁿ) | Θ(n) 栈 |
| 3T(n−1)+Θ(1) | Θ(3ⁿ) | Θ(n) 栈 |
| 二叉 DFS + 按值复制增长路径 | Θ(n2ⁿ) | Θ(n²) |
| 一维 DP、常数转移 | Θ(n) | Θ(n)，可视依赖降空间 |
| 二维 DP、常数转移 | Θ(nm) | Θ(nm)，可视依赖滚动 |
| BFS/DFS（邻接表） | O(V+E) | O(V)，不含输入图 |

### 13.3 常见错误清单

| 错误 | 正确理解 |
|---|---|
| 两层循环就是 n² | 需统计实际总迭代次数 |
| 两个递归调用就是 2ⁿ | 必须看子问题规模如何缩小 |
| 递归总节点数就是栈空间 | 空间看同时活跃调用链和分配 |
| 输出不占空间 | 保存所有结果可能是指数空间 |
| DP 永远比暴力快 | 状态空间可能远大于有效搜索空间 |
| Hash 一律 O(1) | 通常是平均，不保证每次最坏 |
| 均摊 O(1) 表示每次 O(1) | 扩容/rehash 可能带来尖峰 |
| O(n) 总是比 O(n²) 快 | 小输入时常数和硬件访问成本可能主导 |
| O 就是 Worst-case | O 是渐近上界，Worst-case 是输入情形 |
| Big-O 可以预测运行秒数 | 实际速度必须结合操作成本和测量 |

### 13.4 DRW 双背包问题示范回答

对 n 个物品，每个选择：跳过、放入背包 A、放入背包 B，未剪枝暴力 DFS：

- **Time: O(3ⁿ)**（完整展开时 Θ(3ⁿ)）。
- **Auxiliary space: O(n)**（只计递归栈和常数状态，不存所有方案）。

容量为 C1、C2 的密集 DP：

- **Time: O(n C1 C2)**。
- **Space: O(n C1 C2)**，滚动后 **O(C1 C2)**。
- 注意 **伪多项式**：当容量数字很大时，DP 仍可能无法完成。
- n=20 时最多有约 34.9 亿个三选一叶节点，若无有效剪枝，在常见时间限制下不可行；实际阈值要根据节点成本和硬件评估。

### 13.5 最核心的三个公式

**循环：**

$$
T=\sum_{\text{各次迭代}}\text{每次工作量}
$$

**递归：**

$$
T=\sum_{\text{各层}}\text{节点数}\times\text{节点工作量}
$$

**DP：**

$$
T=\sum_{\text{已访问状态}}\text{每状态转移工作量}
$$

**空间：看执行期间的最大同时存活内存，而不是累计操作数。**

**工程：Big-O 给出渐近扩展趋势，不保证实际延迟或尾延迟表现。**
