# 区间数据结构：系统总结

> 目标：建立一套完整的“区间问题”识别与选型框架。  
> 核心不是死记 Segment Tree 或 BIT，而是先判断：**数据本身是什么、查询是什么、更新是什么、在线还是离线、静态还是动态。**

---

## 1. 什么是“区间数据结构”

“区间数据结构”不是单一数据结构，而是一类围绕 **range / interval** 的问题与工具。

最常见的区间问题可以分成两大类：

### 1.1 数组上的区间查询与区间修改

底层数据是一个数组：

~~~text
a[0], a[1], ..., a[n-1]
~~~

问题通常是：

~~~text
query(l, r)
update(l, r)
update(i)
~~~

例如：

- 查询 [l, r] 的和
- 查询 [l, r] 的最小值 / 最大值 / gcd
- 查询 [l, r] 中某个值出现次数
- 给 [l, r] 全部 +x
- 给 [l, r] 全部赋值为 x
- 单点修改后继续做区间查询

这一类典型工具：

- Prefix Sum
- Difference Array
- Fenwick Tree / Binary Indexed Tree
- Segment Tree
- Lazy Segment Tree
- Sparse Table
- sqrt decomposition
- Coordinate Compression

---

### 1.2 数据本身就是 interval

数据直接是：

~~~text
[start, end]
~~~

例如：

~~~text
[1, 5]
[8, 12]
[10, 15]
~~~

问题通常是：

- 是否 overlap
- merge intervals
- point 落在哪些 interval
- 一个新 interval 与哪些旧 interval 相交
- 最大重叠数量
- 动态添加 / 删除 interval
- 当前被覆盖的总长度
- Calendar booking
- 找空闲时间

这一类典型工具：

- Sort + Greedy
- Sweep Line / Event Sorting
- Ordered Map / Set
- Interval Tree
- Segment Tree + Coordinate Compression
- Difference Array + Compression
- TreeMap / std::map 管理 disjoint intervals

---

# 2. 先建立总决策框架

看到区间题，不要先问“是不是 Segment Tree”，而是依次问：

~~~text
1. 数据是 array 还是 intervals？
2. 静态还是动态？
3. Query 是什么？
4. Update 是什么？
5. Online 还是 Offline？
6. 坐标范围大不大？
7. 是否需要顺序统计 / kth / count？
8. 是否存在大量 range update？
~~~

一个非常实用的选择逻辑：

~~~text
静态数组
├─ range sum          -> Prefix Sum
├─ range min/max/gcd  -> Sparse Table
└─ query 很复杂       -> Segment Tree

动态数组
├─ point update + prefix/range sum -> Fenwick Tree
├─ point update + 通用 range query -> Segment Tree
└─ range update + range query      -> Lazy Segment Tree

interval 集合
├─ 只做一次 merge / count          -> Sort / Greedy
├─ 最大重叠 / 并发数                -> Sweep Line
├─ 动态维护 disjoint intervals      -> map/set
├─ overlap query 很多               -> Interval Tree
└─ 坐标超大 + range 操作            -> Coordinate Compression + Segment Tree/BIT
~~~

---

# 3. Prefix Sum

## 3.1 适用场景

Prefix Sum 最适合：

> **数组基本不修改，但需要大量区间和查询。**

原数组：

~~~text
a = [3, 1, 7, 5, 2]
~~~

定义：

~~~text
prefix[i] = a[0] + ... + a[i-1]
~~~

那么：

~~~text
prefix = [0, 3, 4, 11, 16, 18]
~~~

区间 [l, r]：

~~~text
sum(l, r) = prefix[r + 1] - prefix[l]
~~~

---

## 3.2 C++ 模板

~~~cpp
vector<long long> prefix(n + 1, 0);

for (int i = 0; i < n; ++i)
    prefix[i + 1] = prefix[i] + a[i];

auto rangeSum = [&](int l, int r) {
    return prefix[r + 1] - prefix[l];
};
~~~

---

## 3.3 复杂度

~~~text
Build: O(n)
Query: O(1)
Update: O(n)
Space: O(n)
~~~

因此：

> 多 query、少 update -> 非常适合。

---

## 3.4 常见应用

- Range Sum Query
- Subarray Sum
- 子数组平均值
- 区间计数
- 统计某字符在子串中的出现次数
- 固定属性的累计值

---

# 4. 二维 Prefix Sum

矩阵：

~~~text
matrix[r][c]
~~~

如果大量查询矩形区域和：

~~~text
(r1, c1) -> (r2, c2)
~~~

可以定义：

~~~text
prefix[i][j]
= 左上角 (0,0) 到 (i-1,j-1) 的矩形和
~~~

公式：

~~~text
sum(r1,c1,r2,c2)
= P[r2+1][c2+1]
- P[r1][c2+1]
- P[r2+1][c1]
+ P[r1][c1]
~~~

最后的 + 是 inclusion-exclusion。

---

## 4.1 C++ 模板

~~~cpp
vector<vector<long long>> pre(
    m + 1,
    vector<long long>(n + 1, 0));

for (int r = 0; r < m; ++r)
{
    for (int c = 0; c < n; ++c)
    {
        pre[r + 1][c + 1]
            = matrix[r][c]
            + pre[r][c + 1]
            + pre[r + 1][c]
            - pre[r][c];
    }
}
~~~

# 5. Difference Array

Difference Array 和 Prefix Sum 几乎是反向关系。

Prefix Sum：

> 快速 query，update 很慢。

Difference Array：

> 快速 range update，最后统一恢复。

假设要对：

~~~text
[l, r] += x
~~~

只需要：

~~~text
diff[l] += x
diff[r + 1] -= x
~~~

最后对 diff 做 prefix sum。

---

## 5.1 模板

~~~cpp
vector<long long> diff(n + 1);

for (auto [l, r, x] : updates)
{
    diff[l] += x;

    if (r + 1 < n)
        diff[r + 1] -= x;
}

vector<long long> a(n);
long long cur = 0;

for (int i = 0; i < n; ++i)
{
    cur += diff[i];
    a[i] = cur;
}
~~~

---

## 5.2 复杂度

~~~text
Range update: O(1)
Final reconstruction: O(n)
Online query: 不适合
~~~

---

## 5.3 典型应用

- Corporate Flight Bookings
- Car Pooling
- 批量区间增量
- 人数上下车
- 某时间段增加资源
- coverage count
- 扫描线的离散版本

---

# 6. Sweep Line：Difference Array 的连续坐标版本

Sweep Line 可以理解成：

> 把 interval 的变化转换成 event，然后按坐标排序。

区间：

~~~text
[start, end)
~~~

转换：

~~~text
start -> +1
end   -> -1
~~~

例如：

~~~text
[1,5)
[2,6)
[4,7)
~~~

得到：

~~~text
1: +1
2: +1
4: +1
5: -1
6: -1
7: -1
~~~

排序扫描，维护：

~~~text
active += delta
~~~

就可以得到：

- 最大 overlap
- 当前并发数
- 哪些区间被覆盖
- 最大资源需求

---

## 6.1 为什么 Sweep Line 很重要

它是区间问题最常见的建模方式之一。

很多题表面上不是“区间数据结构”，本质上都是：

~~~text
区间 -> 两个 event -> 排序 -> 扫描
~~~

---

## 6.2 经典应用

- Meeting Rooms II
- Minimum Number of Platforms
- 最大同时在线用户数
- 最大并发连接数
- 航班 / 火车站台
- My Calendar 系列
- Skyline
- 线段覆盖
- Rectangle Sweep

# 7. Fenwick Tree / Binary Indexed Tree

Fenwick Tree，简称 BIT。

它最擅长：

> **动态 prefix aggregate**

尤其是：

~~~text
point update
prefix sum
range sum
~~~

---

## 7.1 核心操作

~~~text
add(i, delta)
prefixSum(i)
rangeSum(l, r)
~~~

满足：

~~~text
rangeSum(l, r)
= prefixSum(r) - prefixSum(l - 1)
~~~

---

## 7.2 lowbit

BIT 的核心：

~~~text
lowbit(x) = x & -x
~~~

表示：

> 当前索引覆盖区间长度。

例如：

~~~text
index 12 = 1100b
lowbit(12) = 4
~~~

Fenwick tree[12] 管理一个长度 4 的区间。

---

## 7.3 C++ 模板

~~~cpp
class Fenwick
{
public:
    explicit Fenwick(int n)
        : bit_(n + 1, 0)
    {}

    void add(int i, long long delta)
    {
        for (++i; i < bit_.size(); i += i & -i)
            bit_[i] += delta;
    }

    long long prefixSum(int i) const
    {
        long long sum = 0;

        for (++i; i > 0; i -= i & -i)
            sum += bit_[i];

        return sum;
    }

    long long rangeSum(int l, int r) const
    {
        if (l == 0)
            return prefixSum(r);

        return prefixSum(r) - prefixSum(l - 1);
    }

private:
    vector<long long> bit_;
};
~~~

---

## 7.4 复杂度

~~~text
Point update: O(log n)
Prefix query: O(log n)
Range sum: O(log n)
Space: O(n)
~~~

---

# 8. BIT 的典型高级应用

Fenwick Tree 不只是 range sum。

只要问题能转换成：

> prefix count / prefix frequency

就很适合。

例如：

- Inversion Count
- Count of Smaller Numbers After Self
- Reverse Pairs 的某些变体
- 动态 frequency table
- prefix rank
- kth by cumulative frequency
- order statistics

典型模式：

~~~text
value 很大
-> coordinate compression
-> BIT[index] 保存 frequency
~~~

然后：

~~~text
count(<=x)
= prefixSum(compressed(x))
~~~

---

# 9. Fenwick Tree 的限制

Fenwick Tree 不是通用 Segment Tree。

它最自然支持的是：

> 可以通过 prefix 组合 / 逆运算得到 range 的信息。

sum 很适合：

~~~text
sum(l,r)
= prefix(r) - prefix(l-1)
~~~

但：

~~~text
max(l,r)
~~~

不能简单：

~~~text
prefixMax(r) - prefixMax(l-1)
~~~

因此 BIT 对：

- sum
- frequency
- xor

特别自然。

而对：

- arbitrary min/max
- maximum subarray
- complex state

通常 Segment Tree 更合适。

---

# 10. Segment Tree

Segment Tree 是最通用的区间数据结构之一。

它把：

~~~text
[0, n-1]
~~~

递归拆成：

~~~text
              [0,7]

        [0,3]       [4,7]

     [0,1] [2,3] [4,5] [6,7]
~~~

每个 tree node 保存一个区间的 summary。

---

## 10.1 核心思想

每个节点保存：

~~~text
Node = aggregate(left child, right child)
~~~

例如 sum：

~~~text
parent.sum
= left.sum + right.sum
~~~

max：

~~~text
parent.max
= max(left.max, right.max)
~~~

gcd：

~~~text
parent.gcd
= gcd(left.gcd, right.gcd)
~~~

---

# 11. Segment Tree 的本质：Monoid / 可合并状态

理解 Segment Tree 最重要的不是背模板，而是理解：

> 一个区间的信息是否可以由两个子区间的信息 merge 得到？

只要：

~~~text
state(parent)
= merge(state(left), state(right))
~~~

就可能放进 Segment Tree。

常见 node state：

- sum
- min
- max
- gcd
- xor
- count
- frequency vector
- maximum subarray
- longest prefix
- longest suffix
- bracket state
- matrix
- DP state

---

# 12. Segment Tree 标准模板

下面以 range sum + point update 为例。

~~~cpp
class SegmentTree
{
public:
    explicit SegmentTree(const vector<int>& a)
    {
        n_ = a.size();
        tree_.resize(4 * n_);
        build(1, 0, n_ - 1, a);
    }

    void update(int index, int value)
    {
        update(1, 0, n_ - 1, index, value);
    }

    long long query(int ql, int qr)
    {
        return query(1, 0, n_ - 1, ql, qr);
    }

private:
    int n_;
    vector<long long> tree_;

    void build(
        int node,
        int l,
        int r,
        const vector<int>& a)
    {
        if (l == r)
        {
            tree_[node] = a[l];
            return;
        }

        int mid = l + (r - l) / 2;

        build(node * 2, l, mid, a);
        build(node * 2 + 1, mid + 1, r, a);

        tree_[node]
            = tree_[node * 2]
            + tree_[node * 2 + 1];
    }

    void update(
        int node,
        int l,
        int r,
        int index,
        int value)
    {
        if (l == r)
        {
            tree_[node] = value;
            return;
        }

        int mid = l + (r - l) / 2;

        if (index <= mid)
            update(node * 2, l, mid, index, value);
        else
            update(node * 2 + 1, mid + 1, r, index, value);

        tree_[node]
            = tree_[node * 2]
            + tree_[node * 2 + 1];
    }

    long long query(
        int node,
        int l,
        int r,
        int ql,
        int qr)
    {
        if (qr < l || r < ql)
            return 0;

        if (ql <= l && r <= qr)
            return tree_[node];

        int mid = l + (r - l) / 2;

        return query(node * 2, l, mid, ql, qr)
             + query(node * 2 + 1, mid + 1, r, ql, qr);
    }
};
~~~

---

# 13. Segment Tree Query 为什么是 O(log n)

直觉上：

> Query 区间会被分解成 O(log n) 个 canonical segments。

例如：

~~~text
query [2, 6]
~~~

不会访问整个数组，而只访问少量完整节点。

严格地说，一个 range query 每层最多访问常数个边界节点，因此：

~~~text
O(log n)
~~~

---

# 14. Lazy Segment Tree

普通 Segment Tree：

~~~text
point update
range query
~~~

很好。

但如果要：

~~~text
[l, r] += x
~~~

逐个 leaf update 会退化。

Lazy Propagation 的核心：

> 如果一个 tree node 的整个区间都被 update 覆盖，就先更新 node summary，并把“待传播操作”保存在 lazy tag，不立即深入所有叶子。

---

# 15. Lazy Propagation 的三个关键概念

## 15.1 Apply

把某个 operation 直接应用到当前节点。

例如 range add：

~~~text
sum += delta * segment_length
lazy += delta
~~~

---

## 15.2 Push

如果之后需要进入孩子：

~~~text
lazy(parent)
-> apply(left)
-> apply(right)
-> clear parent lazy
~~~

---

## 15.3 Pull / Merge

孩子变化之后：

~~~text
parent
= merge(left, right)
~~~

---

# 16. Lazy Segment Tree 的不变量

理解 lazy tree 最关键的是：

> tree[node] 必须始终代表该区间“已经考虑所有 lazy effect 之后”的正确 aggregate。

即使 children 还没有真正收到 update：

~~~text
parent summary 已经正确
children 可能暂时旧
lazy tag 记录欠下的操作
~~~

等真正访问 children 时再 push。

---

# 17. Lazy Segment Tree：Range Add + Range Sum 模板

~~~cpp
class LazySegmentTree
{
public:
    explicit LazySegmentTree(int n)
        : n_(n),
          tree_(4 * n, 0),
          lazy_(4 * n, 0)
    {}

    void rangeAdd(int l, int r, long long delta)
    {
        rangeAdd(1, 0, n_ - 1, l, r, delta);
    }

    long long rangeSum(int l, int r)
    {
        return rangeSum(1, 0, n_ - 1, l, r);
    }

private:
    int n_;
    vector<long long> tree_;
    vector<long long> lazy_;

    void apply(
        int node,
        int l,
        int r,
        long long delta)
    {
        tree_[node] += delta * (r - l + 1);
        lazy_[node] += delta;
    }

    void push(
        int node,
        int l,
        int r)
    {
        if (lazy_[node] == 0 || l == r)
            return;

        int mid = l + (r - l) / 2;

        apply(node * 2, l, mid, lazy_[node]);
        apply(node * 2 + 1, mid + 1, r, lazy_[node]);

        lazy_[node] = 0;
    }

    void rangeAdd(
        int node,
        int l,
        int r,
        int ql,
        int qr,
        long long delta)
    {
        if (qr < l || r < ql)
            return;

        if (ql <= l && r <= qr)
        {
            apply(node, l, r, delta);
            return;
        }

        push(node, l, r);

        int mid = l + (r - l) / 2;

        rangeAdd(
            node * 2,
            l,
            mid,
            ql,
            qr,
            delta);

        rangeAdd(
            node * 2 + 1,
            mid + 1,
            r,
            ql,
            qr,
            delta);

        tree_[node]
            = tree_[node * 2]
            + tree_[node * 2 + 1];
    }

    long long rangeSum(
        int node,
        int l,
        int r,
        int ql,
        int qr)
    {
        if (qr < l || r < ql)
            return 0;

        if (ql <= l && r <= qr)
            return tree_[node];

        push(node, l, r);

        int mid = l + (r - l) / 2;

        return rangeSum(
                   node * 2,
                   l,
                   mid,
                   ql,
                   qr)
             + rangeSum(
                   node * 2 + 1,
                   mid + 1,
                   r,
                   ql,
                   qr);
    }
};
~~~

---

# 18. Range Assign 为什么比 Range Add 更难

Range Add：

~~~text
old lazy + new delta
~~~

可以直接叠加。

Range Assign：

~~~text
[l,r] = x
~~~

会覆盖旧操作。

如果同时存在：

~~~text
range assign
range add
~~~

lazy tag 的组合关系就必须明确：

~~~text
assign x
then add y
=> assign x+y
~~~

但：

~~~text
add y
then assign x
=> assign x
~~~

因此：

> Lazy propagation 的真正难点不是树，而是“operation composition”。

# 19. Sparse Table

Sparse Table 适合：

> **静态数组 + 大量 idempotent range query**

最经典的是：

- min
- max
- gcd

预处理：

~~~text
st[k][i]
= 从 i 开始长度 2^k 的区间答案
~~~

---

## 19.1 Query

例如 RMQ：

~~~text
len = r-l+1
k = floor(log2(len))
~~~

使用两个长度 2^k 的区间：

~~~text
[l, l+2^k-1]
[r-2^k+1, r]
~~~

虽然重叠，但 min/max/gcd 不怕重复。

因此：

~~~text
query = min(st[k][l], st[k][r-2^k+1])
~~~

---

## 19.2 复杂度

~~~text
Build: O(n log n)
Query: O(1)
Update: 不支持
Space: O(n log n)
~~~

---

# 20. Sparse Table 为什么不能通用到 Sum

因为它常利用：

> idempotent operation

例如：

~~~text
min(x,x) = x
max(x,x) = x
gcd(x,x) = x
~~~

但：

~~~text
sum(x,x) = 2x
~~~

所以两个 overlap block 不能用于 sum。

---

# 21. sqrt decomposition

把数组分成大约 sqrt(n) 个 block。

每个 block 保存 aggregate。

例如：

~~~text
block sum
block max
~~~

Query：

- 两端散点逐个处理
- 中间整块直接取 aggregate

复杂度典型：

~~~text
Query: O(sqrt(n))
Update: O(1) 或 O(sqrt(n))
~~~

优点：

- 实现简单
- 某些题比 Segment Tree 更容易写
- 适合有特殊 block-level trick 的题

缺点：

- 理论复杂度不如 O(log n)
- 通常不是首选模板

---

# 22. Coordinate Compression

很多区间问题的坐标巨大：

~~~text
1
1000000000
987654321
~~~

但实际只出现少量坐标。

这时可以：

~~~text
收集所有重要坐标
sort
unique
映射到 0...m-1
~~~

例如：

~~~text
values = [100, 1000000, 500000000]
~~~

压缩成：

~~~text
100        -> 0
1000000    -> 1
500000000  -> 2
~~~

---

## 22.1 Coordinate Compression 常和谁组合

最常见：

~~~text
Compression + BIT
Compression + Segment Tree
Compression + Difference Array
Compression + Sweep Line
~~~

---

## 22.2 一个重要坑：长度信息

如果问题只关心：

~~~text
ordering / rank / count
~~~

简单压缩即可。

但如果问题关心：

~~~text
实际覆盖长度
~~~

不能直接把：

~~~text
100 -> 0
1000000 -> 1
~~~

当成距离 1。

必须保存真实 gap：

~~~text
1000000 - 100
~~~

这在：

- union length
- rectangle area
- skyline
- coverage length

特别重要。

---

# 23. Interval Scheduling

经典 interval scheduling：

~~~text
[start, end]
~~~

任务位置已经固定。

目标：

> 最大化不重叠 interval 数量。

Greedy：

> 按结束时间最早排序。

~~~text
sort by end ascending
~~~

然后不断选择：

~~~text
start >= lastEnd
~~~

这和 EDD / EDF 不同：

- interval scheduling 的 end 是真实固定结束时间
- EDD / EDF 的 deadline 是最晚允许结束时间

---

# 24. Merge Intervals

最经典的 interval management。

步骤：

~~~text
1. sort by start
2. 维护当前 [L,R]
3. 如果 next.start <= R
      merge
   else
      输出当前
~~~

复杂度：

~~~text
O(n log n)
~~~

排序往往已经是主要成本。

---

# 25. Ordered Map / Set 管理动态不重叠区间

如果需要动态维护：

~~~text
[1,5]
[10,15]
[20,25]
~~~

常用：

~~~cpp
map<int, int> intervals;
~~~

表示：

~~~text
start -> end
~~~

插入新 interval：

~~~text
[4,12]
~~~

需要：

1. 找第一个可能 overlap 的 interval
2. 向前检查 predecessor
3. 向后 merge 所有 overlap interval
4. 插入合并结果

最后：

~~~text
[1,15]
[20,25]
~~~

---

# 26. std::map 为什么适合 interval management

因为它支持：

~~~text
lower_bound(start)
predecessor
successor
erase range
insert
~~~

全部：

~~~text
O(log n)
~~~

这在动态 calendar / range module 中非常自然。

---

# 27. Interval Tree

Interval Tree 专门支持：

> 找和 query interval overlap 的所有区间。

典型结构通常基于平衡 BST。

节点按照：

~~~text
interval.start
~~~

排序，同时维护：

~~~text
subtree maxEnd
~~~

例如节点：

~~~text
[start, end]
maxEnd = subtree 最大 end
~~~

查询一个 interval [ql, qr] 时：

如果左子树：

~~~text
left.maxEnd < ql
~~~

说明左子树全部不可能 overlap，可以直接剪枝。

---

# 28. Interval Tree 的典型场景

- Calendar conflict
- Genomic ranges
- Compiler source ranges
- Memory address ranges
- GIS
- 网络地址区间
- Scheduling overlap search

面试里真正手写 Interval Tree 比 Segment Tree 少。

很多题用：

~~~text
sort / map / sweep line
~~~

就足够。

---

# 29. Interval Tree 和 Segment Tree 的区别

这是很容易混淆的一点。

## Interval Tree

数据是：

~~~text
很多 arbitrary intervals
~~~

目标：

~~~text
找 overlap
~~~

---

## Segment Tree

数据通常是：

~~~text
一个坐标轴 / array
~~~

目标：

~~~text
range aggregate
range update
~~~

虽然 Segment Tree 也可以解决 interval coverage，但思想不同。

可以记：

~~~text
Interval Tree:
“存 interval”

Segment Tree:
“存 range summary”
~~~

---

# 30. Range Module 类型问题

例如动态支持：

~~~text
addRange(l,r)
removeRange(l,r)
queryRange(l,r)
~~~

可选方案：

### 方法 A：std::map 维护 disjoint intervals

适合：

- interval 数量相对少
- 区间天然可以 merge
- 坐标巨大

### 方法 B：Dynamic Segment Tree

适合：

- 坐标巨大
- range 操作频繁
- 需要复杂 coverage state

---

# 31. Dynamic Segment Tree

普通 Segment Tree 假设：

~~~text
n 已知
~~~

但如果坐标：

~~~text
[0, 10^9]
~~~

又不能建立 4 * 10^9 节点。

Dynamic Segment Tree：

> 节点按需创建。

只有访问过的区间才分配节点。

典型用于：

- Range Module
- My Calendar III
- 大坐标动态 coverage
- 在线区间计数

---

# 32. Implicit Segment Tree 的空间

假设有 q 次操作：

每次只访问：

~~~text
O(log C)
~~~

其中 C 是坐标范围。

因此节点总数大约：

~~~text
O(q log C)
~~~

而不是：

~~~text
O(C)
~~~

---

# 33. Persistent Segment Tree

如果需要保留历史版本：

~~~text
version 0
version 1
version 2
...
~~~

每次 update 不修改旧树，而只复制更新路径。

因为 point update 只影响：

~~~text
O(log n)
~~~

节点，所以每个 version 只新增：

~~~text
O(log n)
~~~

节点。

典型：

- kth number in subarray
- historical query
- time-travel state
- versioned range statistics

---

# 34. Segment Tree Beats

这是更高级的数据结构。

用于：

~~~text
range chmin
range chmax
range add
range sum
~~~

例如：

~~~text
for all i in [l,r]:
    a[i] = min(a[i], x)
~~~

普通 lazy propagation 很难直接处理。

Segment Tree Beats 会维护：

- maximum
- second maximum
- count of maximum
- sum

利用条件：

> 只有最大值会被 chmin 时，可以直接更新节点，不必继续递归。

这是竞赛高级内容，普通面试较少要求。

---

# 35. Order Statistics：第 k 小

区间数据结构常常和：

~~~text
rank / kth
~~~

结合。

典型方法：

### BIT + Frequency

如果 value domain 可压缩：

~~~text
BIT[value] = count
~~~

通过 cumulative count 找 kth。

### Segment Tree + Count

每个节点：

~~~text
count
~~~

从 root：

~~~text
if left.count >= k
    go left
else
    k -= left.count
    go right
~~~

复杂度：

~~~text
O(log n)
~~~

---

# 36. Wavelet Tree / Merge Sort Tree

如果需要：

~~~text
subarray [l,r] 中
有多少 <= x
第 k 小是什么
~~~

可以考虑：

- Merge Sort Tree
- Wavelet Tree
- Persistent Segment Tree

这些属于更高级的 range order-statistics 工具。

---

# 37. Merge Sort Tree

每个 Segment Tree 节点保存：

~~~text
该区间排序后的 vector
~~~

查询：

~~~text
count <= x in [l,r]
~~~

可以在每个被覆盖节点里：

~~~text
upper_bound
~~~

复杂度：

~~~text
Build: O(n log n)
Query: O(log^2 n)
Space: O(n log n)
~~~

# 39. Sweep Line + BIT 的经典模式

二维点：

~~~text
(x, y)
~~~

如果按 x 排序扫描：

~~~text
x -> sweep dimension
y -> BIT dimension
~~~

就把二维问题降成：

例如：

- rectangle counting

# 40. 静态 vs 动态：最重要的第一层分类

## 静态

数组不变：

~~~text

~~~

优先：

- Prefix Sum
- Sparse Table
- offline preprocessing

---

## 动态

不断：

~~~text

query
~~~

优先：

- BIT
- Segment Tree
- Lazy Segment Tree

# 41. Online vs Offline

## Online

query 到来时必须立刻回答。

不能提前知道后续操作。

典型：

- BIT
- Segment Tree
- balanced BST

---

## Offline

所有 query 预先知道。

可以：

- 排序 query
- 改变处理顺序
- coordinate compression
- sweep line
- Mo's Algorithm
- offline DSU

很多看起来需要复杂树结构的问题，offline 后可能明显简化。

# 42. Point / Range 四象限

这是区间题最重要的选型表之一。

| Update | Query | 常见选择 |
|---|---|---|
| 无 update | Range Sum | Prefix Sum |
| 无 update | Range Min/Max/GCD | Sparse Table |
| Point Update | Prefix/Range Sum | BIT |
| Point Update | General Range Query | Segment Tree |
| Range Update | 最终值 | Difference Array |
| Range Add | Point Query | Difference/BIT |
| Range Add | Range Sum | Lazy Segment Tree / Two BIT |
| Range Assign | Range Query | Lazy Segment Tree |
| Range Complex Op | Range Complex Query | Segment Tree |

# 43. BIT 也能做 Range Add + Range Sum

通过两个 BIT，可以支持：

~~~text
range add
range sum
~~~

这是经典技巧。

若维护 difference：

~~~text
d[i] = a[i] - a[i-1]
~~~

则 prefix sum 可以推导成：

~~~text
prefix(x)
= (x+1) * sum(B1, x) - sum(B2, x)
~~~

工程 / 面试中如果不熟，不必强行使用。

通常：

> 通用需求直接 Lazy Segment Tree 更清晰。

# 44. BIT vs Segment Tree

## BIT 优势

- 代码短
- 常数小
- cache locality 通常更好
- 内存 O(n)
- prefix sum/frequency 很自然

---

## Segment Tree 优势

- merge 更通用
- min/max/gcd
- complex node state
- lazy propagation
- range assign
- kth
- maximum subarray
- coverage

---

## 面试选择

如果题目明确：

~~~text
point update + range sum
~~~

优先 BIT。

如果：

~~~text
不知道后面要扩展什么
或者 query 很复杂
~~~

Segment Tree 更通用。

# 45. Segment Tree 的常见 Node 设计

## Sum

~~~cpp
struct Node {
    long long sum;
};
~~~

Merge：

~~~text
sum = left.sum + right.sum
~~~

---

## Min / Max

~~~cpp
struct Node {
    int mn;
    int mx;
};
~~~

Merge：

~~~text
mn = min(left.mn, right.mn)
mx = max(left.mx, right.mx)
~~~

---

## Maximum Subarray Sum

需要维护：

~~~text
sum
bestPrefix
bestSuffix
bestSubarray
~~~

Merge：

~~~text
sum = L.sum + R.sum

prefix
= max(
    L.prefix,
    L.sum + R.prefix)

suffix
= max(
    R.suffix,
    R.sum + L.suffix)

best
= max(
    L.best,
    R.best,
    L.suffix + R.prefix)
~~~

这个例子非常好地体现了：

> Segment Tree 本质是“可合并 DP state”。

# 46. Coverage Segment Tree

区间覆盖问题经常维护：

~~~text
coverCount
coveredLength
~~~

如果：

~~~text
coverCount > 0
~~~

整个节点区间都被覆盖：

~~~text
coveredLength
= coordinate[r+1] - coordinate[l]
~~~

否则：

~~~text
coveredLength
= left.coveredLength + right.coveredLength
~~~

经典应用：

- Rectangle Area II
- union of intervals
- sweep line + segment tree

# 47. Interval overlap 的基础判断

两个闭区间：

~~~text
[a,b]
[c,d]
~~~

不 overlap：

~~~text
b < c
or
d < a
~~~

所以 overlap：

~~~text
max(a,c) <= min(b,d)
~~~

如果是半开区间：

~~~text
[a,b)
[c,d)
~~~

overlap：

~~~text
max(a,c) < min(b,d)
~~~

面试里一定要先确认：

> interval endpoint 是 closed 还是 half-open。

---

# 48. 为什么半开区间 [l,r) 很常见

半开区间优点：

~~~text
length = r-l
~~~

相邻区间：

~~~text
[1,3)
[3,5)
~~~

天然不 overlap。

数组 slice 也自然：

~~~text
[l,r)
~~~

因此工程系统中非常常见。

---

# 49. Event tie-breaking

Sweep Line 里如果多个 event 同坐标，顺序很关键。

例如 closed interval：

~~~text
[1,3]
[3,5]
~~~

是否认为 time=3 overlap？

要根据题意。

常见规则：

### Half-open [start,end)

~~~text
end event before start event
~~~

因为：

~~~text
[1,3)
[3,5)
~~~

不 overlap。

### Closed interval

可能需要：

~~~text
start before end
~~~

因此：

> event tie-breaking 必须由 endpoint semantics 决定。

# 69. Range Query 的统一抽象

很多区间查询都可以抽象为：

~~~text
query(l,r)
= combine(
    information of subranges
)
~~~

关键问题：

> combine 是否 associative？

如果：

~~~text
combine(combine(a,b),c)
=
combine(a,combine(b,c))
~~~

那么树形分治非常自然。

Segment Tree 就依赖这种可合并性。

# 75. 面试时如何解释为什么选某结构

推荐按这个顺序说：

~~~text
1. 数据会不会变化？
2. Query 类型是什么？
3. Update 类型是什么？
4. 需要 online 吗？
5. 目标复杂度是多少？
~~~

例如：

> We need point updates and range-sum queries online. Prefix sums would make updates O(n), while a Fenwick tree supports both operations in O(log n), so BIT is the simplest fit.

或者：

> We need range updates and range maximum queries, so a Fenwick tree is not expressive enough. A lazy segment tree gives O(log n) range update and query.

# 77. 最终总结

“区间数据结构”不要理解成：

~~~text
Segment Tree
~~~

而应该理解成完整的问题空间：

~~~text
Array Range Problems
|
+-- Static
|   +-- Prefix Sum
|   +-- Sparse Table
|
+-- Dynamic
    +-- Fenwick Tree
    +-- Segment Tree
    +-- Lazy Segment Tree


Interval Problems
|
+-- Sorting / Greedy
+-- Sweep Line
+-- Ordered Map / Set
+-- Interval Tree
+-- Compression + Segment Tree
~~~

最重要的能力是：

> **先识别问题维度，再选择数据结构。**

面试里最实用的判断顺序：

~~~text
静态还是动态？
point 还是 range？
query 是 sum / min / max / count / overlap 哪一种？
online 还是 offline？
坐标范围是否需要压缩？
~~~

只要这几个问题回答清楚，大部分区间问题的数据结构选择就会自然出现。
