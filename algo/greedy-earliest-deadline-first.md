# Earliest-deadline-first、EDF、EDD 与经典区间调度

> 核心区别：EDD / EDF 的任务通常给出“需要多久、最晚何时完成”，执行位置由调度决定；经典 interval scheduling 给出固定的起止时间，算法只能选择区间，不能移动区间。
>
> LC630 则需要解决两件事：**按截止时间安排顺序，超时时淘汰耗时最长的课程。**

## 1. 概念对照

| 概念 | 任务模型 | 核心规则 | 典型目标 / 结论 |
|---|---|---|---|
| earliest-deadline-first 思想 | 泛指有截止时间的任务 | 越早到期，越优先处理 | 是思考方向，是否最优取决于模型 |
| EDF（Earliest Deadline First） | 任务可在不同时间到达，有执行时长和绝对截止时间 | 从当前已就绪且未完成的任务中，执行截止时间最早者 | 经典单处理器、可抢占模型下，若存在可行调度，EDF 也可行 |
| EDD（Earliest Due Date） | 经典模型中所有任务在时间 0 可用，单机、非抢占 | 按 due date 升序执行 | 最小化最大延误量 maximum lateness |
| LC630（Course Schedule III） | 每门课程有 duration 和 lastDay，可选取子集 | 按 lastDay 排序；超时则删除最长课程 | 最大化按时完成的课程数 |
| 经典 interval scheduling（Activity Selection） | 固定区间，通常记为 [start, end) | 每次选择与已选区间兼容、结束最早的区间 | 最大化互不重叠的区间数量 |

Earliest Deadline First 就是 EDF 的英文全称。但算法讨论中的“earliest-deadline-first 思想”有时只是泛指按截止时间优先，不一定在说实时系统中的严格 EDF 调度算法。

EDD 常用于静态排序，EDF 常用于动态优先级调度；这是一种常见使用语境，不是说 EDF 只能处理动态任务。当所有任务同时可用时，EDF 可以得到与 EDD 相同的截止时间顺序。

## 2. EDD：先确定执行顺序

设每个任务有处理时长 p_i、截止时间 d_i，完成时间为 C_i。假设：

- 只有一台机器，同一时刻只能处理一个任务。
- 所有任务从时间 0 起都可执行。
- 任务不可抢占，没有前置依赖或额外切换成本。

EDD 按 d_i 非递减排序。例如：

| 任务 | 时长 p | 截止时间 d |
|---|---:|---:|
| A | 3 | 7 |
| B | 2 | 5 |
| C | 4 | 12 |

顺序是 B → A → C，完成时间分别为 2、5、9，均不超过各自截止时间。

### 2.1 可行性的交换论证

假设某个可行调度中，相邻任务的顺序为 B → A，但 d_A <= d_B。它们开始前已经执行了 T 时间。

由于原调度可行：

```text
T + p_B + p_A <= d_A <= d_B
```

交换为 A → B 后：

```text
A 的完成时间 = T + p_A <= T + p_B + p_A <= d_A
B 的完成时间 = T + p_A + p_B <= d_A <= d_B
```

两者都不迟到，后续任务的开始时间也不变。不断交换截止时间逆序的相邻任务，就得到 EDD 顺序。

因此：**如果选定的一组任务存在可行顺序，那么按截止时间升序执行也可行。**

注意，这只回答“选定任务之后怎么排”，没有回答“应该选哪些任务”。截止时间最早的任务不一定必须保留。

### 2.2 最小化 maximum lateness

定义：

```text
L_i = C_i - d_i              // lateness，可以为负
L_max = max_i L_i
T_i = max(0, C_i - d_i)      // tardiness，不能为负
```

在上述经典模型中，EDD 最小化 L_max。交换论证不必假设原调度可行：对于相邻逆序 B → A，交换后 A 和 B 的 lateness 都不超过原来 A 的 lateness，因此不会增大最大 lateness。

如果 EDD 下 L_max <= 0，所有任务都能按时完成；如果 EDD 下 L_max > 0，则不存在能让这整组任务全部按时完成的调度。

这个结论不意味着 EDD 能最小化总迟到时间，或直接最大化按时完成的任务数量。存在不同释放时间时，也不能直接照搬这个静态排序结论。

## 3. EDF：始终执行就绪任务中截止时间最早者

EDF 的经典规则是：**在当前已经到达、尚未完成的任务中，选择绝对截止时间最早的任务运行。**

例如：

```text
t = 0：A 到达，执行时长 6，绝对截止时间 10
       开始执行 A
t = 2：B 到达，执行时长 2，绝对截止时间 5
       抢占 A，先执行 B
t = 4：B 完成，恢复 A
t = 8：A 完成
```

两个任务都按时完成。如果不允许抢占而让 A 连续执行到 t = 6，B 就会错过截止时间。

这里比较的是 absolute deadline（绝对截止时间）。如果给的是相对截止时间 D_i，应先计算 d_i = r_i + D_i，其中 r_i 是到达时间。

经典 EDF 可行性最优结论依赖于单处理器、独立任务、允许抢占、忽略抢占开销等条件；不能无条件推广到多处理器、不可抢占或存在资源阻塞的情况。EDF 本身也不解决过载时“选择哪个子集以最大化完成数量”的问题。

## 4. 经典 interval scheduling：区间位置已经固定

每个活动给出固定区间 [s_i, f_i)，目标是选择最多个互不重叠的区间。采用半开区间约定时，前一个活动结束的时刻可以作为下一个活动开始的时刻。

算法：

1. 按结束时间 f_i 升序排序。
2. 维护最后一个已选区间的结束时间 lastEnd。
3. 如果 s_i >= lastEnd，就选中当前区间并更新 lastEnd。

### 为什么选择结束最早的区间？

设贪心选择 G，某个最优解的第一个区间是 O。因为 f_G <= f_O，把 O 替换为 G 后，原来排在 O 后面的所有区间仍可放在 G 后面，数量不变。之后对剩余兼容区间重复同样的论证。

**结束最早，为后面留下最多可用时间。**

这和 EDD 的交换论证不同：

- EDD 交换任务的执行顺序，任务的开始和完成时间随之变化。
- 区间调度替换所选区间，区间自身的起止时间不变。

例如 [1, 4)、[3, 5)、[4, 6)，贪心选择 [1, 4) 和 [4, 6)。不能把 [3, 5) 挪到其他时间执行。

这里指的是每个区间价值相同、最大化数量的经典问题。带权区间调度通常使用动态规划；最少会议室数等问题也不是同一个目标。

## 5. LC630：EDD 排序 + 大根堆淘汰

每门课程给出 [duration, lastDay]。课程没有固定开始时间，只要求在 lastDay 前完成；同一时刻只能学习一门课程，目标是完成尽可能多的课程。

### 5.1 两层贪心分别负责什么？

```text
按 lastDay 升序：确定已选课程的执行顺序。
按 duration 淘汰最长课程：在发生冲突时决定保留哪些课程。
```

由 EDD 的交换论证，任何可行课程子集都可以按 lastDay 升序学习。因此可以先排序，把顺序问题固定下来，再处理子集选择问题。

### 5.2 算法

维护一个存储已选课程时长的大根堆，以及总时长 total：

1. 按 lastDay 升序遍历课程。
2. 暂时选入当前课程，将 duration 入堆并加到 total。
3. 如果 total > lastDay，弹出堆中最长的课程，并从 total 中减去其时长。
4. 最终堆的大小就是答案。

### 5.3 为什么删除最长课程？

超时时，删除一门课程就能把数量减一；在这些删除方案中，删除最长课程释放的时间最多。它可能是当前课程，也可能是之前已经选入的课程。

删除后仍然可行：

- 若删除当前课程，回到加入它之前的可行集合。
- 若删除旧课程，剩余旧课程的完成时间只会提前；当前课程排在末尾，其完成时间也会降到当前截止时间以内。

为什么只弹出一次就够？设加入当前课程前总时长为 T，当前时长为 p、截止时间为 d，弹出的最长时长为 q。之前集合可行且按截止时间扫描，所以 T <= d；同时 q >= p，因此：

```text
T + p - q <= T <= d
```

完整的最大数量最优性还依赖这一经典删除策略的交换论证：在 EDD 序列第一次发生超时时，超时前缀至少要舍弃一个任务，而可以选择舍弃其中最长任务而不降低最优可完成数量；对剩余序列重复这一操作。该算法通常称为 Moore–Hodgson 算法。仅证明“当前总时长更小”或“当前集合仍可行”，还不足以单独完成全局最优性证明。

### 5.4 示例：先选的课程也可以被替换

| 课程 | duration | lastDay |
|---|---:|---:|
| A | 5 | 5 |
| B | 4 | 6 |
| C | 2 | 6 |

按截止时间扫描（同截止时间时这里先处理 B）：

```text
选 A：total = 5，保留 A。
加 B：total = 9 > 6，删除最长的 A，total = 4，保留 B。
加 C：total = 6 <= 6，保留 B、C。
```

答案为 2。如果遇到放不下的课程就直接跳过、永远不替换旧课程，这个例子只能保留 A，答案为 1。

这说明：**先处理早截止时间，不等于最终必须选择早截止时间的课程。**

### 5.5 C++ 实现

```cpp
#include <algorithm>
#include <queue>
#include <vector>
using namespace std;

class Solution {
public:
    int scheduleCourse(vector<vector<int>>& courses) {
        sort(courses.begin(), courses.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[1] < b[1];
             });

        priority_queue<int> selected;
        long long total = 0;

        for (const auto& course : courses) {
            total += course[0];
            selected.push(course[0]);

            if (total > course[1]) {
                total -= selected.top();
                selected.pop();
            }
        }
        return static_cast<int>(selected.size());
    }
};
```

排序和堆操作共需 O(n log n) 时间，堆需要 O(n) 额外空间。实现会原地重排输入课程。

## 6. 识别题型时问什么？

| 看到的条件或目标 | 优先考虑 |
|---|---|
| 固定 start/end，选最多个不重叠活动 | 经典区间调度：按 end 贪心选择 |
| duration/deadline，所有任务同时可用，检查能否全部按时完成 | EDD 排序后检查每个完成时间 |
| 经典单机模型下最小化最大 lateness | EDD |
| 任务动态到达，允许抢占，满足截止时间 | 检查是否满足经典 EDF 模型 |
| duration/deadline，可舍弃任务，最大化按时完成数量 | LC630：EDD + 大根堆 |

记忆要点：**EDD 排顺序，EDF 管当前优先级，经典区间调度选固定活动；LC630 先排顺序，再用最长时长淘汰策略选子集。**
