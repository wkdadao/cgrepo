# Dependency Scheduler + Critical Path（依赖调度与关键路径）

> 自拟 C++17/20 两小时 OA 综合题，**不是已核实的 DRW 真题**。
> 重点：Topological Sort、DAG Longest Path、Cycle Detection、动态图重算。
> 建议用时：120 分钟。P0。

## 1. 背景与任务

一个交易平台由 N 个初始化任务组成，例如 Market Data、Reference Data、Pricing、Risk 和 Order Routing。任务 i 需要 d[i] 个整数时间单位才能完成。

依赖关系 u -> v 表示：任务 v **只能在任务 u 完成后**开始。多个依赖必须全部满足才能启动 v。不同任务可以无限并行执行，没有 CPU、线程或资源数量限制。所有没有前置依赖的任务最早在时间 0 开始；任务不可中断。

系统允许用户动态添加或删除依赖。在任何时刻，查询需判断依赖图是否有效，并在有效时给出完成全部任务所需的**最短总时间**以及一条决定该时间的关键路径。

特别注意：这是 DAG 上的最长加权路径问题，**不是**用任务时长相加求串行执行时间。

## 2. 输入格式

标准输入：

~~~text
N M Q
d1 d2 ... dN
u1 v1
...
uM vM
command1
...
commandQ
~~~

- 任务编号 1..N；任务时长为正整数。
- 初始有 M 条有向依赖，允许初始图存在环。
- 每个命令独占一行，按输入顺序执行。

命令：

| 命令 | 含义 |
| --- | --- |
| ADD u v | 添加有向依赖 u -> v |
| DEL u v | 删除有向依赖 u -> v |
| QUERY | 校验当前图，若无环则计算最短完成时间及关键路径 |

对已有边 ADD、对不存在边 DEL，均视为合法的无操作。允许自环；自环即构成环。不存在重复存储的平行边。

## 3. 输出格式

只有 QUERY 输出。

若当前图存在任何有向环：

~~~text
CYCLE
~~~

否则：

~~~text
OK minimumTime k v1 v2 ... vk
~~~

其中 v1..vk 是一条关键路径：

1. 路径沿图的有向边前进；单个任务也可以构成路径。
2. 路径上任务时长之和等于 minimumTime。
3. 若存在多条关键路径，**可以输出任意一条**，不要求字典序。
4. minimumTime 是所有任务完成的最早时刻，必须包含孤立任务。

不要输出拓扑序，也不要输出中间状态或调试日志。

## 4. 样例一：关键路径、动态形成环、恢复

输入：

~~~text
5 5 5
3 2 5 4 2
1 3
1 4
2 4
3 5
4 5
QUERY
ADD 5 1
QUERY
DEL 5 1
QUERY
~~~

输出：

~~~text
OK 10 3 1 3 5
CYCLE
OK 10 3 1 3 5
~~~

解释：1 -> 3 -> 5 的时长为 3+5+2=10。1 -> 4 -> 5 为 9。加入 5 -> 1 后，1 -> 3 -> 5 -> 1 构成环；删除后恢复。

## 5. 样例二：并行、孤立任务、自环

输入：

~~~text
3 0 5
7 2 5
QUERY
ADD 2 2
QUERY
DEL 2 2
QUERY
~~~

输出：

~~~text
OK 7 1 1
CYCLE
OK 7 1 1
~~~

## 6. 约束

- 1 <= N <= 100000；0 <= M <= 200000。
- 1 <= d[i] <= 1000000。
- 1 <= Q <= 200000；QUERY 命令不超过 20 次。
- 有效边数随时不超过 200000。
- 所有 QUERY 时的 (N + 当前有效边数) 之和不超过 4000000。
- 所有任务时长总和保证在有符号 64 位整数范围内。
- 输入保证命令与编号格式合法；不要求错误命令处理。

## 7. 正确性要求与边界

- 必须检测**任意**环，包括不与任何起点或终点连接的孤立环。
- 一旦有环，不能输出一条局部可执行顺序代替 CYCLE。
- 多个前驱时，任务的最早开始时刻为所有前驱完成时刻的最大值，而非总和。
- 关键路径允许以非编号 1 的任务开始、以非编号 N 的任务结束。
- 时长只计算顶点，不可额外把边数计入时长。
- QUERY 不能改变图；ADD/DEL 可能把图从合法切换成非法，再恢复。
- 小心 32 位整数溢出。

## 8. 目标与建议接口

目标：每次 QUERY 时间 O(N+E)，不要求在更新时增量维护拓扑序。

~~~cpp
struct QueryResult {
    bool hasCycle;
    int64_t minimumTime;
    std::vector<int> criticalPath;
};

class DependencyScheduler {
public:
    explicit DependencyScheduler(std::vector<int64_t> durations);
    void addDependency(int u, int v);
    void removeDependency(int u, int v);
    QueryResult query() const;
};
~~~

接口只是组织建议；最终按输入输出协议实现。内部可以每次从当前边集合构造邻接表，使用 Kahn 拓扑排序及 DAG DP。

## 9. 加分扩展（不属于必做）

1. 输出按任务编号最小优先的确定性拓扑序。
2. 返回环内一条具体的闭合路径，而非仅输出 CYCLE。
3. 若同时运行任务数最多为 K，重新讨论能否直接使用最长路径结果（一般不能）。
4. 支持任务时长修改，并说明缓存哪些状态才能高效重算。

## 10. 自测清单

- 单节点；多孤立点；单自环；长度为 2 的环。
- 多条同时最长的关键路径；多个前驱在同一节点汇合。
- 动态添加不存在的边；重复添加；删除不存在的边。
- 环在不相关子图内；删除一条环边后重新可查询。
- 大任务时长、深链、宽层级 DAG、QUERY 多次重复。
