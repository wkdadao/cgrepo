# Falling Blocks / Tetris — 旋转、重力、锁定与消行模拟

> **C1 / Simulation / Falling Blocks / Tetris**  
> 建议用时：**90–120 分钟** ｜ 难度：**中高** ｜ 语言：**C++17/20**  
> 训练重点：读题建模、二维坐标变换、碰撞、事件顺序、状态提交、边界测试  
> **本文件为可独立练习的完整 OA 题目，不提供参考代码或解法。**
>
> 这是**自定义的简化 Tetris**，并非经典俄罗斯方块的官方规则：没有 SRS / wall kick、Hold、Next Queue、七袋随机、锁定延迟或分数系统。

## 1. Problem Statement

给定一个 `H × W` 的游戏棋盘和一串按顺序落下的方块（Pieces）。棋盘中 `#` 表示**已锁定的静态方块格子**，`.` 表示空格。

每个新方块在指定的起始列生成，随后执行一串预先给出的玩家操作：

- `L`：向左移动一列。
- `R`：向右移动一列。
- `C`：顺时针旋转 90°。
- `N`：不做玩家操作（等待一个时间步）。
- `H`：Hard Drop（持续下落到底），立即锁定，并消除所有填满的行。

对 `L/R/C/N`，**玩家操作处理完毕后，系统尝试让活动方块向下移动一行**。如果重力下降受阻，方块本次停在原地，**不会自动锁定**；直到 `H` 才会锁定。

每个方块的指令串保证以一个 `H` 结尾，且前面只能出现 `L/R/C/N`。

任务是按顺序模拟所有方块：

- 若某个方块在生成时就与棋盘或边界冲突，立即输出 `GAMEOVER i`，其中 `i` 为第一个无法生成的方块编号（从 1 开始）。
- 如果所有方块都能成功生成和锁定，输出总消行数以及最终棋盘。

**这是一道确定性模拟题，不要求搜索最优放置位置或最佳操作序列。**

## 2. 坐标、棋盘和活动方块

- 棋盘行号自上而下为 `0..H-1`，列号自左而右为 `0..W-1`（**0-based**）。
- `board[r][c] = '#'` 表示已锁定的格子。它们**不会因为重力自动下落**，只会在整行消除时随棋盘其余行整体下移。
- 任意时刻最多只有**一个活动方块**。活动方块的四个占据格子与棋盘中已有的 `#` **分开处理**，直到 Lock 才写进棋盘。
- 任何成功的移动或旋转都不允许使活动方块的占据格子越界或与已有 `#` 重叠。
- 棋盘上初始不存在已经填满的行；**只在每次锁定后进行消行**。

## 3. 方块类型

共有 5 种方块：`I`、`O`、`T`、`L`、`S`。每种方块使用一个固定大小的**局部方阵（local matrix）**描述：

### I：4 × 4

~~~text
....
####
....
....
~~~

### O：2 × 2

~~~text
##
##
~~~

### T：3 × 3

~~~text
.#.
###
...
~~~

### L：3 × 3

~~~text
#..
###
...
~~~

### S：3 × 3

~~~text
.##
##.
...
~~~

这些局部方阵里，`#` 表示该方块实际占据的格子，`.` 是局部方阵中的**透明空格**，不占据棋盘，也不参与碰撞。

### 3.1 位置（Position）

一个方块的状态为：

- 当前局部矩阵 `shape`（初始如上，可旋转）。
- 局部方阵左上角对应的棋盘坐标 `(row, col)`。

如果局部方阵中 `shape[i][j] == '#'`，其占据的棋盘格子就是：

~~~text
(row + i, col + j)
~~~

**碰撞只检查实际的 `#` 格子。** 局部矩阵中的 `.` 不要求落在棋盘内，也不与其他方块冲突。

### 3.2 Spawn

输入为每个方块指定一个起始列 `c`，它生成在：

~~~text
row = 0
col = c
orientation = initial
~~~

- `c` 是**局部方阵左上角的列**，而非方块最左边实际 `#` 的列。
- 若当前方块的**任何实际 `#` 格子**在出生位置越界或碰到已锁定的 `#`，本次 Spawn 失败：`GAMEOVER i`。
- Spawn 成功后，**不会额外触发一次重力 tick**；第一条 `L/R/C/N` 才会触发一步重力，`H` 则执行 Hard Drop。
- 输入保证 `0 ≤ c < W`，但仍可能因形状尺寸或已有锁定格子而 Spawn 失败。

## 4. 碰撞与合法性

令 `fits(shape, row, col)` 表示**该局部形状的每个 `#` 格子**映射到棋盘后都：

1. 在 `[0,H) × [0,W)` 范围内。
2. 对应的静态棋盘格子为 `.`。

只有满足 `fits`，对应的新位置/方向才能被接受。

**重要：本题中玩家操作被阻挡不是非法命令，不会导致 Game Over。**

- 左右移动被挡住：保持原来的横向位置。
- 旋转被挡住：保持原来的方向。
- 无论横移/旋转成功还是被挡住，**仍继续执行本次操作后的重力 tick**。
- 重力下降被挡住：位置不变，等待后续命令；不自动 Lock。

除了 Spawn 失败，所有输入保证的 `L/R/C/N/H` 都可以被执行。

## 5. 玩家操作与重力的明确顺序

### 5.1 `L`、`R`

1. 尝试将活动方块的 `col` 减一或加一。
2. 若 `fits` 通过则接受横移，否则原地不动。
3. **然后尝试向下移动一格**：若 `fits(shape,row+1,col)` 通过，`row++`；否则本 tick 不动。

**即使 L/R 被墙、边界或其他已锁定块阻挡，仍执行第 3 步。**

### 5.2 `C`（clockwise rotation）

在当前 `N × N` 局部方阵内**原地**顺时针旋转 90°，不改变方阵左上角 `(row,col)`。

旋转定义：

~~~text
old[i][j] -> rotated[j][N - 1 - i]
~~~

旋转后方阵尺寸仍为 `N × N`：

- 如果旋转后的占据格子均满足 `fits`，接受旋转。
- 否则拒绝旋转，保留原形状、原 `row` 和原 `col`。
- 旋转之后（无论成功/失败），再尝试**一次**重力下降。

**没有 Wall Kick**：不能为了使旋转成功而把方块额外向左/右/上/下平移。局部方阵的左上角在旋转时固定。

例如 `T` 初始形状：

~~~text
.#.
###
...
~~~

顺时针旋转后为：

~~~text
.#.
.##
.#.
~~~

注意：`I` 使用 4×4 方阵旋转，`O` 使用 2×2 方阵旋转，不能统一当成 3×3，也不能在旋转后自动裁掉透明边缘并改变锚点。

### 5.3 `N`（wait one tick）

不做横移/旋转，只尝试**一次**重力下降。

### 5.4 `H`（Hard Drop + Lock + Clear）

`H` 是每个方块**最后一条命令**，其语义：

1. 在当前方向与当前列保持不变的情况下，重复向下移动一格，直到下一格移动不再满足 `fits`。
2. 将活动方块的四个 `#` 格子写入静态棋盘，完成 **Lock**。
3. 立即检查静态棋盘中的所有满行，**一次性消除**。
4. 更新累计消行数；然后才允许生成下一个方块。

`H` 可以令方块下降 **0 格**，例如方块已在底部或被其他锁定格子支撑。这样的 `H` **仍合法**，并应成功 Lock。

**不存在 H 后的额外重力 tick**；Hard Drop 已经落到不能下降的位置。

## 6. 消行（Line Clear）

一个满行定义为：该行每列都是已锁定的 `#`。

锁定之后，同时找出所有满行：

- 删除这些行。
- 把剩余行按原有**相对顺序**向下移动。
- 在棋盘顶部补同样数量的全 `.` 行。
- 每消除一行，累计计数增加 1。

**多行必须同时消除**。不要扫描到一行就立即删掉、移动，然后漏检查另一行。

例如，4 列宽棋盘锁定后：

~~~text
....
....
##..
####
####
~~~

同时消除底部两行后：

~~~text
....
....
....
....
##..
~~~

这里计入 **2 行**消除。

消行仅发生在 `H` 锁定之后，不会因一条 `L/R/C/N` 的结束而发生。

## 7. 输入格式

~~~text
H W
board[0]
board[1]
...
board[H-1]
P
type[1] column[1] commands[1]
type[2] column[2] commands[2]
...
type[P] column[P] commands[P]
~~~

字段说明：

- `H W`：棋盘行数和列数。
- `board[r]`：长度恰为 `W` 的字符串，仅包含 `.`、`#`；表示**初始已锁定棋盘**。
- `P`：待投放的方块数。
- `type[i]`：`I`、`O`、`T`、`L` 或 `S`。
- `column[i]`：局部方阵左上角的起始列 `c`（从 **0** 开始）。
- `commands[i]`：长度 ≥1 的操作字符串，以唯一的最后一个 `H` 结尾，其余字符来自 `L/R/C/N`。

例：

~~~text
T 2 LRCNNH
~~~

表示：T 形块从局部左上角列 2 出生，依次执行左移、右移、旋转、等待、等待、Hard Drop。

## 8. 输出格式

### 所有方块成功 Spawn、Lock

先输出一行：

~~~text
LINES K
~~~

其中 `K` 是整个模拟过程的**累计消除行数**。

再输出 `H` 行最终静态棋盘，每行恰好 `W` 个字符。

### 某个方块 Spawn 失败

只输出一行：

~~~text
GAMEOVER i
~~~

`i` 为第一个生成失败的方块编号（**1-based**）。不用输出中间棋盘或已消除行数。

注意：**阻挡横移、阻挡旋转或重力下降失败不会触发 Game Over。**

## 9. 数据范围与建议限制

| 参数 | 范围 |
|---|---|
| `6 ≤ H ≤ 30` | 棋盘高度 |
| `4 ≤ W ≤ 20` | 棋盘宽度 |
| `1 ≤ P ≤ 500` | 方块数量 |
| `1 ≤ |commands[i]| ≤ 1,000` | 每个方块的指令字符串长度 |
| `0 ≤ column[i] < W` | 局部矩阵出生列 |
| 初始棋盘 | 只有 `.#`，没有完整满行 |
| 时间限制（练习建议） | 2 秒 |
| 内存限制（练习建议） | 256 MB |

没有活动方块时，已锁定的格子即使“悬空”也不会自动掉落。这是本题规则，与上一道 Push Box + Gravity（所有物体都会下落）不同。

## 10. 样例

### Sample 1 — 普通 Hard Drop

**Input**

~~~text
6 6
......
......
......
......
......
......
1
O 1 H
~~~

**Output**

~~~text
LINES 0
......
......
......
......
.##...
.##...
~~~

**Explanation**

O 块使用 2×2 方阵，从 `(0,1)` 出生，执行 `H` 后停在棋盘最后两行。

### Sample 2 — 同时消除两行

**Input**

~~~text
6 4
....
....
....
....
##..
##..
1
O 2 H
~~~

**Output**

~~~text
LINES 2
....
....
....
....
....
....
~~~

**Explanation**

O 块填入最后两行的第 2、3 列（0-based），两行都变满，必须同时消除。累计消行数为 2。

### Sample 3 — 原地旋转 + Hard Drop

**Input**

~~~text
7 7
.......
.......
.......
.......
.......
.......
.......
1
T 2 CH
~~~

**Output**

~~~text
LINES 0
.......
.......
.......
.......
...#...
...##..
...#...
~~~

**Explanation**

T 块先在 `(0,2)` 顺时针旋转，使用 `3×3` 方阵且局部左上角不动；`C` 随后触发一次重力下降；最后 `H` 落到底部并锁定。

### Sample 4 — 被阻挡的横移是合法 no-op

**Input**

~~~text
6 6
......
......
......
......
......
......
1
O 0 LH
~~~

**Output**

~~~text
LINES 0
......
......
......
......
##....
##....
~~~

**Explanation**

`L` 尝试向左一格，但 O 块占据列 0、1，向左会越界，因此横移被忽略。**该次操作仍触发一个重力 tick**。之后 `H` 正常下落并锁定。

### Sample 5 — Spawn 冲突导致 Game Over

**Input**

~~~text
6 6
..#...
......
......
......
......
......
1
O 2 H
~~~

**Output**

~~~text
GAMEOVER 1
~~~

**Explanation**

O 块在 `row=0, col=2` 生成时，已经与静态棋盘 `(0,2)` 的 `#` 冲突。因此第一个方块生成失败，后面的 `H` 不会执行。

### Sample 6 — 多个方块顺序锁定

**Input**

~~~text
6 6
......
......
......
......
......
......
2
O 0 H
O 2 H
~~~

**Output**

~~~text
LINES 0
......
......
......
......
####..
####..
~~~

**Explanation**

每个方块锁定后才生成下一个，第二个 O 块与第一个 O 块并排摆放，未出现满行。

## 11. 必测边界情况

在完成样例后，至少自行构造并核对：

1. `I` 的四种旋转方向；确认用的是 **4×4 局部方阵**。
2. `O` 顺时针旋转后形状不变。
3. `T/L/S` 顺时针旋转时左上角锚点不变。
4. 横移导致某个实际 `#` 越界，移动被忽略。
5. 旋转后有方块格子越界，旋转被忽略。
6. 旋转后会与已锁定块碰撞，旋转被忽略。
7. 被忽略的横移/旋转仍然执行一次重力 tick。
8. `N` 只执行一次重力下降，不是 Hard Drop。
9. 方块已落在底部时，仍可执行 `L/R/C/N`，直到 `H` 才锁定。
10. `H` 在当前高度已不能下落，直接锁定（下降 0 格）。
11. `H` 下降多格后，形状保持不变。
12. 锁定后仅消除一行。
13. 锁定后同时消除两行或更多行。
14. 消行后上方旧格子整体下移，顶部补全空行。
15. 多个方块连续生成、锁定；后续 Spawn 基于消行后的棋盘。
16. 第 `i` 个 Spawn 失败，输出 `GAMEOVER i`，不输出部分结果。
17. 局部方阵中的 `.` 不参与碰撞检测，即使它对应的坐标越界或已有锁定块。
18. 初始锁定格子在后续下落前保持原位，只有 Line Clear 才移动。
19. 存在同一时刻多个满行，消行操作必须一次完成。
20. `P=500`、长指令串、重复旋转，检查程序能否稳定结束。

## 12. C1 OA 训练流程（不属于判题规则）

### Phase A — 读题与建模（15–20 分钟）

先写出以下定义，再开始实现：

- **Board / Active Piece**：静态锁定棋盘与活动方块是否分开保存？
- **Piece Anchor**：`row,col` 表示什么？旋转是否改变锚点？
- **Collision / Validity**：只检查占据格还是整个方阵？
- **Event Ordering**：`L/R/C/N` 与重力、`H` 与锁定、锁定与消行，分别是什么顺序？
- **No-op vs Failure**：哪些阻挡被忽略？什么情况才 Game Over？
- **Commit Boundary**：一次操作、一个方块，还是整串方块？

### Phase B — 最小可运行实现（50–70 分钟）

优先完成整条主流程：

~~~text
For each piece:
    Spawn
      | if collision -> GAMEOVER
    For each operation:
      L/R/C/N:
        Attempt player operation (blocked => no-op)
        Attempt one gravity step
      H:
        Hard Drop
        Lock cells into board
        Clear all full rows
    Next piece

Output total cleared lines + board
~~~

无需引入抽象事件系统也可以实现；如果练习 **TEDS（Transactional Event-Driven Simulation）**，可将下落、锁定和消行拆成事件，但**不能改变上面规定的顺序和 no-op 语义**。本题没有任意未来事件时间戳，不需要 `priority_queue`。

### Phase C — 测试与复盘（20–30 分钟）

- 分别手算 6 组样例。
- 对 5 个方块的旋转单独测试。
- 重点检查：碰撞边界、当前操作与重力的先后顺序、行消除的整体性。
- 先使所有逻辑正确，再考虑预计算旋转形状、维护高度索引等性能优化。
- 记录本题最大的实现风险：**坐标变换 / 状态变更顺序 / 多行同时消除**。
