# Rotting Oranges — 多源同步传播模拟

> **C1 / Simulation / Propagation / Tick-Based Events**  
> 建议用时：**25–40 分钟** ｜ 难度：**基础至中等** ｜ C++17/20  
> 训练重点：多个传播源、时间层、同步更新、重复访问、不可到达状态。  
> **本文件是基于经典 Rotting Oranges 机制重新编写的 OA 输入输出练习，不包含参考解法。**

## 1. Problem Statement

仓库有一个 `H × W` 的网格，每个格子可能为空、存放新鲜橘子或存放已经腐烂的橘子。

从时间 `t=0` 开始，腐烂会向相邻的新鲜橘子传播。传播每经过一层相邻关系，需要 **1 分钟**。多个腐烂源可以同时向外传播。

请计算**让所有初始新鲜橘子都变为腐烂所需的最少分钟数**。

- 如果所有新鲜橘子最终都可以腐烂，输出所需的分钟数。
- 如果存在永远无法被感染的新鲜橘子，输出 `-1`。
- 如果初始时根本没有新鲜橘子，答案为 `0`。

本题没有人为选择的动作序列，也不要求改变感染传播规则。

## 2. 格子状态

每个格子为以下整数之一：

| 值 | 含义 |
|---|---|
| `0` | 空格；不能传播腐烂 |
| `1` | 新鲜橘子 |
| `2` | 腐烂橘子 |

腐烂只通过**上、下、左、右**四个方向传播；斜对角不算相邻。

腐烂橘子不会恢复新鲜；空格永远保持空格。

## 3. 时间与同步传播规则

### 3.1 初始时间

`t=0` 时，所有输入中标为 `2` 的橘子都已经腐烂，是传播的**同时起点**。

### 3.2 每分钟的状态变化

对任意整数时间 `t >= 0`：

1. 找出时间 `t` 时已经腐烂的橘子。
2. 它们会使四邻中仍然新鲜的橘子在时间 `t+1` 变为腐烂。
3. **时间 `t+1` 才新腐烂的橘子，不得在同一分钟内继续传播**；它们最早会在 `t+2` 影响邻居。
4. 不会因为同时被两个腐烂源影响而重复计算新腐烂事件。

即：**每一轮（minute）使用该轮开始时的感染状态计算下一轮的变化**。

例如：

~~~text
t=0: 2 1 1 1
t=1: 2 2 1 1
t=2: 2 2 2 1
t=3: 2 2 2 2
~~~

这里的最少时间是 **3 分钟**，不是 1 分钟。

### 3.3 停止条件

当所有初始新鲜橘子都变成腐烂状态时，记录此时的最小时间。

若某一时刻之后再无任何可传播变化，仍存在新鲜橘子，则输出 `-1`。

若初始没有腐烂橘子，但存在新鲜橘子，也无法发生任何传播，输出 `-1`。

## 4. 输入格式

~~~text
H W
grid[0][0] grid[0][1] ... grid[0][W-1]
...
grid[H-1][0] ...        grid[H-1][W-1]
~~~

说明：

- `H` 是行数，`W` 是列数。
- 接下来 `H` 行，每行恰好 `W` 个整数。
- 每个整数只能是 `0`、`1` 或 `2`。

输入只有一组数据；行列坐标使用 **0-based**，但本题输出不需要坐标。

## 5. 输出格式

输出**唯一一行**：

~~~text
MINUTES K
~~~

`K` 为最少分钟数；如果无法让全部新鲜橘子腐烂，`K = -1`。

## 6. 数据范围

| 参数 | 范围 |
|---|---|
| `1 <= H,W <= 200` | 地图尺寸 |
| `grid[r][c]` | `0`、`1`、`2` |
| 建议时间限制 | 2 秒 |
| 建议内存限制 | 256 MB |

## 7. 样例

### Sample 1 — 单源多层传播

**Input**

~~~text
3 3
2 1 1
1 1 0
0 1 1
~~~

**Output**

~~~text
MINUTES 4
~~~

**Explanation**

时间 0 的腐烂源为左上角。通过四邻传播，最远的可达新鲜橘子在第 4 分钟腐烂。所有新鲜橘子均可达。

### Sample 2 — 有新鲜橘子不可达

**Input**

~~~text
3 3
2 1 1
0 1 1
1 0 1
~~~

**Output**

~~~text
MINUTES -1
~~~

**Explanation**

左下角的新鲜橘子被空格隔开，不可能接触到任何腐烂橘子。

### Sample 3 — 没有新鲜橘子

**Input**

~~~text
2 3
0 2 0
2 0 2
~~~

**Output**

~~~text
MINUTES 0
~~~

开始时已经满足“所有新鲜橘子都已腐烂”这一条件（没有新鲜橘子），无须等待传播。

### Sample 4 — 有新鲜橘子，但没有腐烂源

**Input**

~~~text
2 3
1 1 0
0 1 1
~~~

**Output**

~~~text
MINUTES -1
~~~

### Sample 5 — 多个同时传播源

**Input**

~~~text
3 5
2 1 1 1 2
1 1 1 1 1
0 0 1 0 0
~~~

**Output**

~~~text
MINUTES 4
~~~

**Explanation**

两端的腐烂源从同一时间 `t=0` 开始传播。最晚变腐烂的格子在第 4 分钟完成传播，两个源对同一橘子的影响不能重复计数。

## 8. 必测边界情况

1. `1×1` 地图，仅有 `0`。
2. `1×1` 地图，仅有 `1`。
3. `1×1` 地图，仅有 `2`。
4. 一整行全部为新鲜橘子，仅一端有腐烂源。
5. 一整列传播。
6. 两个不同腐烂源在中间同时到达同一个橘子。
7. 空格将地图分割为多个无法互通的区域。
8. 所有格子一开始都已经腐烂。
9. 没有腐烂源但存在新鲜橘子。
10. 新鲜橘子虽然相距很近，但仅对角相邻，不允许传播。
11. 传播经过多层，不能让新感染格子在同一分钟继续传播。
12. 大规模 `200×200` 输入，检查时间与空间复杂度。

## 9. OA 建模问题

编码前明确：

- **State**：静态空格与动态腐烂状态分别如何表示？
- **Events**：所有 `t=0` 已腐烂格子是否应作为同时传播源？
- **Ordering**：同一分钟新感染的橘子能否立即传播？
- **Deduplication**：两个腐烂源同时触发同一目标时，目标算几次？
- **Termination**：没有新变化但仍有新鲜橘子时怎么办？
- **Output**：为什么结果是最晚感染时间，而不是已处理的事件数量？

本题是同步传播问题。可以采用按时间层推进的模型，也可基于旧状态计算下一状态。**并不需要 Priority Queue 或 Transactional Copy**；选择最简单且符合规则的实现即可。

## 10. 提交要求

提交 C++17/20 程序，从标准输入读取一组数据，仅输出 `MINUTES K`。不要求打印每分钟的网格状态，也不要求图形动画。

**核心训练目标：用统一的时间层处理多个传播源，防止新感染状态在同一时间步被重复传播。**
