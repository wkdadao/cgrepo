# Balloon Chain Explosion — 延迟触发与连锁爆炸模拟

> **C1 / Simulation / Chain Reaction / Discrete Events**  
> 建议用时：**60–90 分钟** ｜ 难度：**中等偏上** ｜ C++17/20  
> 训练重点：事件时间、连锁触发、同一时刻事件、去重、终止性、输出验证。  
> **原创 OA 训练题：只提供完整题目与测试，不提供参考实现。**

## 1. Problem Statement

二维平面上有 `N` 个气球，编号为 `1..N`。每个气球的位置、爆炸影响半径以及**从被触发到真正爆炸的延迟**均已知。

在时间 `t=0`，人为**直接引爆**编号为 `S` 的气球。此后，每个实际发生的爆炸都可能触发附近尚未被触发的气球，形成连锁反应。

请求计算：

- 最终实际爆炸的气球数量；
- 所有爆炸完成的最晚时间；
- 每个气球实际爆炸的时间；没有爆炸的输出 `-1`。

**这是一道确定性事件模拟题**：没有随机性，不需要寻找最佳引爆位置，也不需要求最短路径。

## 2. 气球定义

气球 `i` 有四个参数：

| 字段 | 含义 |
|---|---|
| `x[i], y[i]` | 固定的二维整数坐标 |
| `radius[i]` | 气球 `i` **实际爆炸时**的影响半径 |
| `delay[i]` | 气球 `i` 被其他爆炸**首次触发**后，等待多久才真正爆炸 |

每个气球有以下三个逻辑状态：

- **UNTRIGGERED**：从未被触发，尚未有未来爆炸安排。
- **SCHEDULED**：已被触发，未来会在某个确定时刻爆炸。
- **EXPLODED**：已经实际爆炸，此后不再爆炸。

所有气球的位置保持不变；气球互相之间**不会阻挡爆炸影响范围**。即使某个气球已经被触发但还没真正爆炸，它仍然可以受到其他爆炸的影响，不过**不会因此再次安排爆炸或提前爆炸**。

## 3. 爆炸传播规则

### 3.1 初始引爆

编号 `S` 的气球在 **`t=0` 直接爆炸**，其自身 `delay[S]` **不生效**。随后按它的爆炸半径尝试触发其他气球。

### 3.2 爆炸影响范围

当气球 `i` 在时间 `t` 真正爆炸时，对每一个**其他**气球 `j`，若：

~~~text
(x[i] - x[j])² + (y[i] - y[j])² <= radius[i]²
~~~

则 `j` 位于 `i` 的爆炸范围内。

- 使用**欧氏距离**，不是曼哈顿距离。
- 圆周边界上的气球也受影响（使用 `<=`）。
- 半径属于**爆炸源 `i`**，不是目标 `j`。
- 爆炸影响**瞬时到达**，不另计传播时间。
- 每次实际爆炸都使用本气球自身的 `radius[i]` 触发周边目标。

### 3.3 首次触发及延迟

如果 `j` 在时间 `t` 被爆炸命中，且 `j` 当前为 **UNTRIGGERED**，则立即成为 **SCHEDULED**，其爆炸计划时间为：

~~~text
scheduledTime[j] = t + delay[j]
~~~

注意延迟属于**接收触发的气球 `j`**。

如果气球 `j` 已是 **SCHEDULED** 或 **EXPLODED**，则新的命中**不做任何事**：

- 不重复安排事件；
- 不累加爆炸强度；
- 不修改现有爆炸时间；
- 不把爆炸时间提前。

**每个气球最多实际爆炸一次。**

### 3.4 零延迟

允许 `delay[j] = 0`。

这意味着气球 `j` 被首次触发后，可能**在同一个时间戳 `t`** 立即爆炸，并继续触发其他气球。

必须把此类新事件完整处理，不能只扫描当前时间戳最开始就存在的事件。

### 3.5 同一时间的执行顺序

所有**实际爆炸事件**按键 `(explosionTime, balloonId)` 的字典序处理：

1. 爆炸时间小的先处理。
2. 时间相同，气球 ID 小的先处理。
3. 处理一次爆炸时，按 ID 从小到大检查可被触发的目标。
4. 如果一次爆炸新生成时间也等于当前时间的事件，它立即进入待处理事件集合，并继续参与同一 `(time,id)` 排序。

例如，当前待处理事件是 `(5, 7)` 和 `(5, 9)`，在处理气球 7 时新生成 `(5, 3)`，则接下来应处理 `(5, 3)`，然后再处理 `(5, 9)`。

此规定确保**零延迟与同一时刻多次触发的结果具有确定性**。

### 3.6 结束条件

当再没有尚待执行的爆炸事件时，模拟结束。

因为每个气球最多被首次触发一次、最多安排一次真正爆炸，所以连锁反应**一定终止**。

## 4. 输入格式

~~~text
N S
x[1] y[1] radius[1] delay[1]
x[2] y[2] radius[2] delay[2]
...
x[N] y[N] radius[N] delay[N]
~~~

- `N`：气球数量。
- `S`：最初直接引爆的气球编号（**1-based**）。
- 后面 `N` 行的顺序即气球 ID，从 1 到 N。

输入只有**一组测试数据**。

## 5. 输出格式

第一行：

~~~text
COUNT C
~~~

第二行：

~~~text
LAST_TIME T
~~~

随后输出 `N` 行，每行：

~~~text
i explosionTime[i]
~~~

其中：

- `C`：最终实际爆炸的气球个数；初始气球一定爆炸，所以 `C >= 1`。
- `T`：所有实际爆炸时间的最大值。
- `explosionTime[i]`：气球 `i` 的真正爆炸时间；若从未爆炸则为 `-1`。
- `i` 从 1 到 N 顺序输出，即使气球未爆炸也必须输出该行。

不要输出额外日志。

## 6. 数据范围

| 参数 | 约束 |
|---|---|
| `1 <= N <= 2,000` | 气球数量 |
| `1 <= S <= N` | 最初引爆编号 |
| `-10^6 <= x[i], y[i] <= 10^6` | 整数坐标 |
| `0 <= radius[i] <= 10^6` | 爆炸半径 |
| `0 <= delay[i] <= 10^6` | 触发至爆炸的延迟 |
| 坐标 | 保证每个气球位置各不相同 |
| 建议时限 | 2 秒 |
| 建议内存 | 256 MB |

即使输入参数本身适合 32-bit 整数，**平方距离、事件时间和中间计算应使用足够宽的整数类型**。

## 7. 样例

### Sample 1 — 连锁引爆与零延迟

**Input**

~~~text
5 1
0 0 3 0
2 0 3 2
5 0 2 1
5 2 0 0
20 0 1 0
~~~

**Output**

~~~text
COUNT 4
LAST_TIME 3
1 0
2 2
3 3
4 3
5 -1
~~~

**Explanation**

- `t=0`：气球 1 爆炸，触发气球 2。
- `t=2`：气球 2 爆炸，触发气球 3。
- `t=3`：气球 3 爆炸，触发气球 4；`delay[4]=0`，故气球 4 也在 `t=3` 爆炸。
- 气球 5 从未落入任何实际爆炸的影响范围。

### Sample 2 — 同时间爆炸、重复命中不改变计划

**Input**

~~~text
4 1
0 0 3 5
1 0 5 0
0 2 5 0
5 2 0 4
~~~

**Output**

~~~text
COUNT 4
LAST_TIME 4
1 0
2 0
3 0
4 4
~~~

**Explanation**

- `t=0`：气球 1 触发 2、3，它们均零延迟，按照 ID 先 2 后 3 爆炸。
- 气球 2 在 `t=0` 首先触发气球 4，其爆炸被安排在 `t=4`。
- 气球 3 随后在 `t=0` 再次命中 4，**不会**新增事件或修改 `t=4` 的计划。
- `t=4`：气球 4 爆炸。

### Sample 3 — 半径为零，初始 delay 被忽略

**Input**

~~~text
3 2
0 0 1 4
10 0 0 5
20 0 3 0
~~~

**Output**

~~~text
COUNT 1
LAST_TIME 0
1 -1
2 0
3 -1
~~~

气球 2 在 `t=0` 直接爆炸，不等待 `delay[2]=5` 秒；半径 0 不会触发其他气球。

### Sample 4 — 恰好位于爆炸半径边界

**Input**

~~~text
2 1
0 0 5 0
3 4 0 7
~~~

**Output**

~~~text
COUNT 2
LAST_TIME 7
1 0
2 7
~~~

因为 `3² + 4² = 5²`，气球 2 受到气球 1 的爆炸影响。

## 8. 必须自行测试的情况

1. `N=1`，只有初始气球。
2. 初始气球半径为 0。
3. 爆炸目标恰好在圆周上。
4. 目标在圆周外一点，不能被触发。
5. 多个目标被同一次爆炸触发。
6. 连锁反应形成多个分支，存在不同延迟。
7. 延迟为 0，导致多层连锁在同一个时间戳发生。
8. 同一目标被不同爆炸多次命中，实际只安排一次。
9. 多个爆炸同时发生，必须遵守 `(time,id)` 排序。
10. 爆炸图可能存在环，但气球绝不能重复爆炸。
11. 只有部分气球可达，其余必须输出 `-1`。
12. 允许出现长时间后才发生的下一次爆炸。
13. 所有气球最终全部爆炸。
14. 坐标含负数、平方距离较大时不溢出。
15. `N=2000`，仍然能够结束并输出所有 ID。

## 9. OA 建模检查（不是解法）

写代码前回答：

- **State**：哪些数据不变？哪些是每个气球的动态状态？
- **Event**：触发事件与实际爆炸事件是否应该区分？
- **Ordering**：零延迟是否引入新的同时间事件？
- **Deduplication**：气球在什么时刻被标记为“已经触发”？
- **Failure mode**：没有额外事件时怎样终止？如何避免一个环无限触发？
- **Validation**：是否保证气球最多爆炸一次、爆炸时间不小于首次触发时间？

本题的延迟不同，未来事件可能交错，所以按时间排序处理事件是自然的。**Event-Driven 不要求事务拷贝：本题没有“命令失败则必须整体回滚”的规则。** 可以选择直接修改模拟状态；如果使用 TEDS，应保持本题的时间与去重语义。
