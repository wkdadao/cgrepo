# Capacity-Constrained Routing（容量约束的最小费用路由）

> 自拟 C++17/20 两小时 OA 综合题，**不是已核实的 DRW 真题**。
> 重点：Flow Network、Residual Graph、Min-Cost Flow、可行性判断。
> 建议用时：120 分钟。P2（进阶，整体实现难度偏高）。

## 1. 背景与任务

一个交易请求路由网络有 N 个节点、M 条有向通道。每条边 u -> v 给出：

- capacity：最多允许转发多少整数单位的请求流。
- unitCost：每转发 1 个单位产生的非负整数成本。

每个节点除源点 s 和目标点 t 外，满足流量守恒：流入总量等于流出总量。流量可以拆分到多条路径上，但每条边上的流量必须是**非负整数**，且不超过其 capacity。

给定需求 D，需要从 s 向 t 发送**恰好 D 个单位**的流量，使总费用

~~~text
sum(flowOnEdge * unitCost)
~~~

尽可能小。

如果网络不能承载 D 个单位，输出 IMPOSSIBLE。成本仅与实际流过的量有关，未使用的容量不产生费用。

本题不考虑负原始费用、时间维度、订单优先级或流量拆分的固定启动费。

## 2. 输入格式

~~~text
N M s t Q
u1 v1 capacity1 unitCost1
...
uM vM capacityM unitCostM
PLAN D1
...
PLAN DQ
~~~

- 节点编号 1..N；s != t。
- 有向边可以平行、自环。
- 每个 PLAN 查询都从**原始容量尚未被使用**的独立网络快照开始计算；前一次查询不会占用下一次查询的容量。
- D 可为 0。

## 3. 输出格式

对于每条 PLAN：

- 如果能发送恰好 D 单位，输出：

~~~text
COST minimumTotalCost
~~~

- 如果不能发送足够流量，输出：

~~~text
IMPOSSIBLE
~~~

当 D=0 时恒输出 COST 0。

基础题只输出最低费用，不要求输出逐边流量分配或实际路径。

## 4. 样例：容量瓶颈与较贵备用路径

输入：

~~~text
4 5 1 4 3
1 2 3 1
1 3 3 2
2 4 2 1
3 4 3 1
2 3 1 0
PLAN 4
PLAN 7
PLAN 0
~~~

输出：

~~~text
COST 9
IMPOSSIBLE
COST 0
~~~

解释：发送 4 单位时，一种最优流量分配为：

- 2 单位走 1 -> 2 -> 4，每单位成本 2：总成本 4。
- 1 单位走 1 -> 2 -> 3 -> 4，每单位成本 2：总成本 2。
- 1 单位走 1 -> 3 -> 4，每单位成本 3：总成本 3。

合计成本 9。发送 7 单位不可能，因为源点出边容量合计只有 6（而目标点入边总容量只有 5）。

## 5. 约束

- 2 <= N <= 60；0 <= M <= 300。
- 1 <= Q <= 10。
- 0 <= capacity <= 1000。
- 0 <= unitCost <= 100。
- 0 <= D <= 1000。
- 总费用保证在 int64_t 范围内。
- 保证输入合法；允许初始有向环及平行边。

## 6. 正确性要求

- 满足全部节点（源、汇除外）的流量守恒。
- 每条边流量必须在 [0, capacity] 内，且是整数。
- 必须发送**恰好** D，不是“最多 D”；不能为了节约成本故意少送。
- 容量限制施加在**单条边**上，不是单条路径独享的容量。
- 流可以拆分，不能把问题简化为只选择一条最便宜路径。
- 并不是始终先选当前最短路径并永久锁定：后续可能需要撤销前面已选择的部分流，重新分配。
- 平行边按独立容量计算；自环在 unitCost 非负时不帮助完成 s -> t 需求。
- 输入原始边的费用非负，但残量网络里的反向边费用可能为负，不能直接在任意残量网络上无条件使用普通 Dijkstra。

## 7. 算法与目标

参考方向：Minimum-Cost Flow（最小费用流），典型实现是 Successive Shortest Augmenting Path。

1. 对每条原始边建正向残量边（容量 cap、成本 cost），同时建立反向边（容量 0、成本 -cost）。
2. 在当前残量网络中寻找 s -> t 的最低费用可增广路径。
3. 沿路径增加可行流量（最多为所有残量边容量的最小值），同步更新正反向残量容量。
4. 累加“本次实际增加的流量 × 路径单位费用”。
5. 无增广路径但尚未满足 D，则输出 IMPOSSIBLE。

有负成本反向边时：

- 可选择 Bellman-Ford / SPFA 风格最短路并论证终止与正确性；或
- 使用节点势能（potentials）得到非负 reduced costs，再运行 Dijkstra。

目标是正确完成基本最小费用流。由于图规模较小，允许选择实现简单的最短增广路方法；没有指定唯一的最优复杂度。应能说明其耗时与增广次数、V、E 有关。

## 8. 加分扩展（不属于必做）

1. 返回每条原始边实际分配的流量，便于验证流量守恒和总费用。
2. 单独查询网络的 Maximum Flow，而不要求最优费用。
3. 增加每条边的最小流量下界 lowerBound，分析可行流转化。
4. 每条路径经过边数不得超过 K，讨论为什么最小费用流状态会变复杂。
5. 增加负的原始 unitCost 或全局负费用环，解释原问题语义与算法保证需要怎样调整。

## 9. 自测清单

- D=0；边为空；目标不可达；需求大于最大流。
- 单条边；两条平行边；多条可替代路径。
- 某条最便宜路径只有部分容量；必须使用更贵路径。
- 需要利用残量网络反向边重新分配已送流量。
- 零费用边、零容量边、环、自环。
- 多次 PLAN 必须相互独立，不能共享已消耗的残量容量。
