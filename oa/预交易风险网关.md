# 预交易风险网关

**Pre-Trade Risk Gateway**

> 自拟 C++17 OA 练习，并非已核实的 DRW、Jump Trading 或其他公司的原题。核心题建议限时 120 分钟；改单部分为单独计时的可选扩展。风险模型与回报行为以本文为准。

## 题目

实现一个单线程风险网关。程序在新订单发往交易所前检查风险，接受请求时立即占用额度，并根据模拟交易所回报更新订单、净持仓与额度。

核心题支持：账户及品种配置、新单、成交、新单拒绝、撤单及查询。

本题使用本地逻辑订单 ID 和请求 ID 关联事件，不负责撮合、FIX 编解码或真实网络通信。

## 输入约定

- 从标准输入逐行读取，直到 EOF。每行一条命令，字段以空白分隔，没有空行。
- 命令名、字段数量、整数格式和 ID 格式保证正确；业务引用、操作时机和价格数量可能非法。
- ID 长度为 1～32，只含字母、数字或下划线；`-` 为输出缺省值。
- 买卖方向为 `B` 或 `S`。
- 价格为整数金额单位；所有品种使用相同单位，合约乘数固定为 1，无币种换算。
- 本题只计算挂单金额占用及数量持仓，不计算现金余额、成交金额、盈亏或保证金。

## 一、初始配置

输入先提供配置，随后提供业务命令。配置部分保证合法、无重复；业务阶段不再新增或修改配置。配置命令成功时不输出。

### 账户配置

```text
ACCOUNT account maxOrderQty maxOrderNotional maxOpenNotional
```

| 字段 | 限制对象 |
| --- | --- |
| `maxOrderQty` | 单笔新单或改单请求的总数量 |
| `maxOrderNotional` | 单笔请求的 `price × totalQty` |
| `maxOpenNotional` | 该账户所有尚未终结订单的金额占用之和 |

### 品种配置

```text
SYMBOL account symbol maxAbsPosition
```

该账户必须已经配置。每个 `(account, symbol)` 独立限制最坏情况下的持仓数量，初始净持仓为零。

## 二、风险模型

### 1. 单笔限制

新单请求的数量及金额必须满足：

```text
qty <= maxOrderQty
price × qty <= maxOrderNotional
```

价格和数量都必须大于零。限额允许恰好取等号。

### 2. 每张订单的占用

`orderQty` 是当前已生效订单的总数量，`cumQty` 是累计成交量。

| 情况 | leavesQty | riskQty | riskNotional |
| --- | --- | --- | --- |
| PendingNew、New、PartiallyFilled、PendingCancel | `orderQty - cumQty` | `leavesQty` | `price × riskQty` |
| Filled、Canceled、Rejected | 0 | 0 | 0 |

新单在本地接受后、尚未收到交易所确认时，已经计入占用。

撤单请求发出后，收到撤单成功回报前，未成交部分继续占用额度。成交保留为净持仓，其对应的挂单占用不再保留。

改单扩展的占用规则由后文单独定义。

### 3. 账户挂单金额

`openNotional` 为该账户所有订单的 `riskNotional` 之和，必须满足：

```text
openNotional <= maxOpenNotional
```

不同品种、买单和卖单的金额占用直接相加，不做抵消。其他账户的订单不计入本账户。

### 4. 品种最坏持仓

对同一 `(account, symbol)`：

| 数值 | 定义 |
| --- | --- |
| `position` | 累计买入成交数量减去累计卖出成交数量 |
| `buyRiskQty` | 该账户、该品种所有买单的 riskQty 之和 |
| `sellRiskQty` | 该账户、该品种所有卖单的 riskQty 之和 |
| `upperPosition` | `position + buyRiskQty` |
| `lowerPosition` | `position - sellRiskQty` |

接受请求后的候选状态必须同时满足：

```text
upperPosition <= maxAbsPosition
lowerPosition >= -maxAbsPosition
```

买卖挂单不相互抵消：上下界分别覆盖只有买单成交、或只有卖单成交的情况。

## 三、ID 与订单状态

- `orderId` 在整个输入期间唯一。成功创建后，终结订单仍保留记录，不能复用 ID。
- `reqId` 是每次发往交易所的新单、撤单或可选改单请求的 ID。成功发出后永不复用。
- 被本地拒绝、没有产生 SEND 的请求不占用 reqId，也不创建新订单。
- 一张订单最多有一个等待回报的请求。
- `execId` 的唯一性范围为同一张逻辑订单。

| state | 含义 |
| --- | --- |
| `PendingNew` | 新单已由本地接受，等待交易所回报 |
| `New` | 新单已被交易所接受，尚无成交 |
| `PartiallyFilled` | 已有成交，仍有未成交部分，没有等待中的请求 |
| `PendingCancel` | 等待撤单回报，期间仍可成交 |
| `Filled` | 当前总数量全部成交，没有等待中的请求 |
| `Canceled` | 撤单成功 |
| `Rejected` | 新单被交易所拒绝 |

## 四、本地业务命令

### 新单

```text
NEW orderId reqId account symbol side price qty
```

基本条件：账户及该品种限制存在，orderId 尚未创建，reqId 尚未使用，price 和 qty 均大于零。

请求必须通过所有风险检查。接受后创建 PendingNew 订单，立即占用额度，输出：

```text
SEND D reqId orderId account symbol side price qty
```

本地拒绝时按第七节输出 REJECT，所有状态不变。

### 撤单

```text
CANCEL orderId reqId
```

订单必须处于 New 或 PartiallyFilled，reqId 尚未使用。

接受后进入 PendingCancel，额度继续保留，输出：

```text
SEND F reqId orderId
```

撤单不进行单笔金额、账户金额或持仓上界的风险检查，但仍须满足操作状态与 ID 条件。

## 五、模拟交易所回报

合法回报更新状态，但不直接输出。回报不重新执行本地风险准入检查。

### 新单回报

```text
NEW_ACK reqId
NEW_REJECT reqId
```

只可回应当前等待中的新单请求。

- 接受后进入 New，清除等待中的新单请求，原占用保留。
- 拒绝后进入 Rejected，释放该订单全部占用，清除等待中的请求。
- 新单确认前不允许成交。

### 成交

```text
FILL orderId execId lastQty
```

新成交要求订单已被交易所接受，并且 `0 < lastQty <= 当前 leavesQty`。

- cumQty 增加 lastQty。
- 买入使 position 增加，卖出使 position 减少。
- 更新剩余数量及风险占用。
- 等待撤单或改单期间，仍可对当前生效订单成交。
- 期间全部成交，不自动清除尚未收到回报的请求；等待撤单时仍显示 PendingCancel。
- 没有等待请求且全部成交时，进入 Filled。

相同 `(orderId, execId)` 的成功成交回报再次出现时，直接忽略，不输出、不重复更新，即使订单已经终结。重复回报内容保证与首次相同。非法成交不登记 execId。

### 撤单回报

```text
CANCEL_ACK reqId
CANCEL_REJECT reqId
```

只可回应当前等待中的撤单请求。

- 成功后进入 Canceled，清除等待中的撤单请求，释放剩余占用，保留累计成交及净持仓。
- 如果已经全部成交，CANCEL_ACK 属于错误，需由 CANCEL_REJECT 结束请求。
- 拒绝时清除该请求，根据最新累计成交量恢复为 New、PartiallyFilled 或 Filled。期间成交不回滚。

本题没有交易所主动撤单、外部持仓变化、成交撤销或成交更正。

## 六、查询

### 账户

```text
ACCOUNT_QUERY account
```

输出：

```text
ACCOUNT account openNotional availableNotional
```

`availableNotional = maxOpenNotional - openNotional`。

### 品种

```text
SYMBOL_QUERY account symbol
```

输出：

```text
SYMBOL account symbol position buyRiskQty sellRiskQty upperPosition lowerPosition
```

### 订单

```text
ORDER_QUERY orderId
```

输出：

```text
ORDER orderId state price orderQty cumQty leavesQty riskQty riskNotional pendingReqId
```

无等待请求时 pendingReqId 输出 `-`。PendingNew 时为新单 reqId，PendingCancel 时为撤单 reqId。

## 七、拒绝与错误

### 本地请求拒绝

NEW、CANCEL、可选 REPLACE 不满足要求时，输出：

```text
REJECT reqId reason
```

同一请求有多个拒绝原因时，按照以下优先级选择第一个：

| 优先级 | reason | 条件 |
| --- | --- | --- |
| 1 | `INVALID` | 基本业务条件不满足：未知账户或品种、无效价格数量、重复订单 ID 或已使用请求 ID、未知订单、非法操作状态等 |
| 2 | `QTY_LIMIT` | 请求总数量超过单笔数量上限 |
| 3 | `ORDER_NOTIONAL` | 请求价格乘以总数量超过单笔金额上限 |
| 4 | `ACCOUNT_NOTIONAL` | 接受请求后的候选账户挂单金额超限 |
| 5 | `POSITION_LIMIT` | 接受请求后的候选品种持仓上界或下界超限 |

CANCEL 只可能因 INVALID 被本地拒绝。

本地拒绝不得修改订单、持仓、占用或已使用 ID 集合；原先未使用的 reqId 不会因本次拒绝而变成已使用。

### 非法回报或查询

未知或已完成请求的回报、回报类型不匹配、非法新成交、查询未知账户／品种／订单等，输出：

```text
ERROR lineNumber
```

原始输入行号从 1 开始，配置及查询也占行号。

失败行不改变任何状态，并继续处理下一行。成功成交回报的重复按前述规则忽略；其他交易所回报不提供重复处理语义。

## 八、输出与规模

- 标准输出只允许出现 SEND、REJECT、ACCOUNT、SYMBOL、ORDER 和 ERROR 行。
- 字段之间恰好一个空格，不得有行末空格、调试日志或额外解释。
- EOF 时不自动输出汇总或订单快照。
- 输入最多 `2 × 10^5` 行，账户最多 `10^3` 个，账户与品种配置组合最多 `10^4` 个。
- 业务输入的价格和数量绝对值均不超过 `10^6`。
- maxOrderQty 为 `1～10^6`，两种金额限额均为 `1～10^15`，maxAbsPosition 为 `1～10^12`。
- 只允许使用 C++ 标准库。

## 九、可选扩展：改单风险

本部分单独计时，不计入核心 120 分钟。扩展模式在核心题上增加以下命令及规则。

### 改单请求

```text
REPLACE orderId reqId newPrice newQty
```

订单必须处于 New 或 PartiallyFilled，reqId 尚未使用；newPrice、newQty 均大于零，且 `newQty >= 当前 cumQty`。其他情况按 INVALID 拒绝。

newQty 是修改后的总数量。单笔数量、单笔金额限制分别按 newQty、`newPrice × newQty` 检查。

在等待改单回报期间，当前生效的 price、orderQty 不变，新增状态为 PendingReplace。

### 等待期间的占用

对这一张逻辑订单定义：

```text
oldRemaining = orderQty - cumQty
newRemaining = max(newQty - cumQty, 0)

riskQty = max(oldRemaining, newRemaining)
riskNotional = max(price × oldRemaining, newPrice × newRemaining)
```

PendingReplace 的 leavesQty 等于 oldRemaining。

数量占用和金额占用分别按上述规则计算，它们可能对应不同版本的订单。

在接受请求后的候选风险状态中，该逻辑订单按上述占用计一次，其他订单占用不变。账户金额、品种最坏持仓必须通过核心题的限制。

接受时立即采用该等待期间占用，输出：

```text
SEND G reqId orderId newPrice newQty
```

本地拒绝时不改变任何状态。拒绝原因优先级与核心题相同。

等待期间若发生成交，按当前生效的 orderQty 限制成交数量；累计成交和净持仓正常增加，并按最新 cumQty 重新计算等待期间占用。全部成交后仍保留 PendingReplace，直到收到改单回报。

ORDER_QUERY 的 pendingReqId 此时为改单 reqId。

### 改单回报

```text
REPLACE_ACK reqId
REPLACE_REJECT reqId
```

只可回应当前等待中的改单请求。

成功时：

- price 变为请求的 newPrice。
- orderQty 变为请求 newQty 与确认时 cumQty 中的较大者。
- 清除请求，根据最新数量进入 New、PartiallyFilled 或 Filled。
- 恢复按当前生效订单的普通占用规则计算风险。

拒绝时：

- 原 price、orderQty 保留，期间成交不回滚。
- 清除请求，根据最新数量进入 New、PartiallyFilled 或 Filled。
- 按普通占用规则计算风险，释放仅为改单额外保留的部分。

两种回报都不再次执行单笔或账户风险准入检查。账户、品种、买卖方向以及 orderId 在改单中保持不变。
