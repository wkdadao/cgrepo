# 多来源行情聚合

**Multi-Source Market Data Aggregation**

> 自拟 C++17 OA 练习，建议限时 120 分钟，并非已核实的 DRW、Jump Trading 或其他公司的原题。所有行情语义均以本文为准。

## 题目

实现一个单线程行情聚合程序，接收多个来源对多个品种的最新报价，并查询每个品种的综合最优买卖报价。

每个来源对一个品种最多提供一档买价和一档卖价，可以只提供其中一侧。同一品种在所有来源中使用相同的整数价格单位和数量单位。报价不会触发成交。

程序需要处理报价替换、撤回、消息重复与乱序、报价过期，以及来源的启用和停用。从标准输入逐行读取命令，直到 EOF；严格按输入行顺序处理。

## 1. 数据与初始状态

### 1.1 标识与数值

| 字段 | 含义与范围 |
| --- | --- |
| `source` | 行情来源，长度 1～16，仅含 ASCII 字母、数字或下划线，区分大小写 |
| `symbol` | 品种标识，格式与 `source` 相同 |
| `ttl` | 来源报价的有效时长，整数，范围 `1～10^9` |
| `now` | 全局逻辑时间，整数，范围 `0～10^12` |
| `seq` | 消息序号，整数，范围 `1～10^12` |
| `price` | 价格，整数，范围 `1～10^9` |
| `qty` | 数量，整数，范围 `1～10^9` |

所有时间使用同一抽象单位。程序初始时间为 `0`，没有已注册来源，也没有报价。

### 1.2 报价与序号的作用范围

一条来源报价由 `(source, symbol)` 唯一确定。不同来源、不同品种的报价相互独立。

消息序号也在**每个 `(source, symbol)` 内独立比较**。`UPDATE` 和 `DELETE` 共用该对来源与品种的序号。序号可跳跃，不要求连续，不回绕，也不跨日重置。

即使报价已经撤回或过期，仍需保留其最新已接受事件的序号和内容，以便判断后续消息。停用或重新启用来源不重置序号。

## 2. 输入命令

字段以空格或制表符分隔，允许行首和行尾有空白。每条命令占一行，命令名区分大小写。以下格式中的字段名只用于说明。

### 2.1 注册来源

```text
SOURCE source ttl
```

注册一个来源，设置固定的 `ttl`，初始状态为 `UP`。

来源注册后，其 `ttl` 不可修改。重复注册同名来源属于错误，即使 `ttl` 相同也不例外。

除 `SOURCE` 外，所有带有 `source` 字段的命令都必须引用已注册来源。

### 2.2 推进时间

```text
TIME now
```

将全局逻辑时间设置为给定值。新值必须大于或等于当前时间；时间倒退属于错误。

只有合法的 `TIME` 命令会改变时间。不使用机器时钟，不因处理其他命令而自动推进时间。同一时间的多条命令仍按输入顺序生效。

### 2.3 更新报价

```text
UPDATE source symbol seq bidPrice bidQty askPrice askQty
```

这是一条对该来源、该品种的**完整报价替换**：

- 有买方报价时，`bidPrice` 和 `bidQty` 都必须为范围内的正整数。
- 无买方报价时，两个字段都必须为 `-`。
- 卖方字段使用相同规则。
- 至少有一侧存在；两侧均为 `- -` 属于错误。
- 若两侧均存在，必须满足 `bidPrice < askPrice`。

缺失的一侧表示移除该来源此前在这一侧的报价，不能沿用旧值。

消息的序号处理见第 3 节。仅在消息作为新事件被接受时，才替换报价，并将本条报价的接收时间设为**当前全局逻辑时间**。两侧共用该接收时间与来源的 `ttl`。

### 2.4 撤回报价

```text
DELETE source symbol seq
```

消息作为新事件被接受时，撤回该来源对该品种的买卖两侧报价。

该来源此前未对该品种报过价，或报价已经撤回、过期时，新的 `DELETE` 仍可被接受，并记录其序号与事件类型。

### 2.5 设置来源可用状态

```text
SETSOURCE source state
```

`state` 只能为 `UP` 或 `DOWN`。

- `UP`：该来源的未过期报价可以参与聚合。
- `DOWN`：该来源的所有报价均不参与聚合。

重复设置为当前状态是合法操作。

来源处于 `DOWN` 时，仍按正常规则接受 `UPDATE` 和 `DELETE`，报价也继续计时。切换状态不会删除报价、延长有效期或改变序号。

重新设为 `UP` 后，只允许当前尚未过期且未被撤回的最新报价重新参与聚合。

### 2.6 查询综合最优报价

```text
BBO symbol
```

输出一行：

```text
BBO symbol bidPrice bidQty bidSources askPrice askQty askSources state
```

`BBO` 可以查询此前从未出现过的品种。聚合与输出规则见第 5 节。

除 `BBO` 和错误输出外，其他命令均不输出。报价过期或来源状态变化本身不产生输出。

## 3. 消息序号、重复与冲突

先对整条命令完成校验，包括来源是否存在、字段数量、数值范围和报价合法性。合法后，才与该 `(source, symbol)` 的最新已接受事件比较。

### 3.1 首条消息或更大序号

如果此前没有接受过该对来源与品种的事件，或新消息的序号更大，则接受本事件，按 `UPDATE` 或 `DELETE` 的规则生效。

直接以本事件为准，不等待跳过的序号。

### 3.2 更小序号

忽略合法的旧消息，不改变任何状态，不刷新报价接收时间，也不输出。

### 3.3 相同序号

将新消息与最新已接受事件比较：

- 事件类型及全部报价字段相同：属于重复消息，忽略，不改变状态或刷新时间。
- 事件类型不同，或任一报价字段不同：属于冲突，输出错误，保留此前状态。

两个同序号的 `DELETE` 是重复消息。`UPDATE` 与 `DELETE` 不是同一类型，即使当前都没有有效报价，也属于冲突。

比较字段时使用解析后的数值与缺失标记，数字的前导零不影响相等性。只需对比最新已接受事件；更小序号一律按旧消息规则处理。

报价过期后，同序号重复 `UPDATE` 仍被忽略，不能使其恢复有效。必须使用更大序号的合法 `UPDATE` 才能产生新的报价。

## 4. 报价有效期

一条已接受的 `UPDATE` 若接收时间为 `receivedAt`，其过期时刻为：

```text
expiresAt = receivedAt + ttl
```

报价仅在以下条件**同时成立**时参与聚合：

1. 它是该 `(source, symbol)` 最新已接受事件留下的报价，且未被撤回。
2. 来源当前状态为 `UP`。
3. 当前时间满足 `now < expiresAt`。

当 `now == expiresAt` 时，报价已经过期。过期不会撤销最新事件的序号记录，也不会恢复更早的报价。

更大序号的 `UPDATE` 即使价格和数量与前一条完全相同，也会产生新的接收时间与有效期。旧消息、重复消息、来源状态切换和查询均不会延长有效期。

## 5. 聚合与输出规则

对查询品种，仅考虑当前可参与聚合的来源报价。买卖两侧独立计算。

### 5.1 买方

- `bidPrice`：所有有效买价中的最大值。
- `bidQty`：所有报价恰好等于该最优买价的来源，其买量之和。
- `bidSources`：贡献该最优买价的全部来源名称，按 ASCII 字典序升序排列，以英文逗号连接，不含空格。

没有有效买方报价时，三个字段依次输出 `- 0 -`。

### 5.2 卖方

- `askPrice`：所有有效卖价中的最小值。
- `askQty`：所有报价恰好等于该最优卖价的来源，其卖量之和。
- `askSources`：贡献该最优卖价的全部来源名称，排序与分隔规则同买方。

没有有效卖方报价时，三个字段依次输出 `- 0 -`。

每个来源在每侧最多贡献一次。非最优价格的数量不计入该侧输出。买量和卖量分别相加，不相互抵消。同一来源可以同时出现在买方和卖方来源列表中。

### 5.3 综合状态

| 条件 | `state` |
| --- | --- |
| 两侧都不存在 | `EMPTY` |
| 只有买方 | `BID_ONLY` |
| 只有卖方 | `ASK_ONLY` |
| 两侧都存在，且 `bidPrice < askPrice` | `NORMAL` |
| 两侧都存在，且 `bidPrice == askPrice` | `LOCKED` |
| 两侧都存在，且 `bidPrice > askPrice` | `CROSSED` |

单个来源的双边报价必须满足严格的买价小于卖价，但不同来源合并后可能出现 `LOCKED` 或 `CROSSED`。这两种综合状态均为合法结果，不删除来源报价，不撮合，也不修改价格或数量。

输出中的所有整数使用十进制，不保留前导零。

## 6. 错误处理

遇到错误命令，输出：

```text
ERROR lineNumber
```

`lineNumber` 是该命令在整个输入中的行号，从 1 开始；错误行和空行也计入行号。空行本身是错误命令。

以下情况均属于错误：

- 未知命令、字段数量不匹配或标识格式非法。
- 数字格式或范围非法。数字字段只接受十进制数字串，不接受正负号、小数点或指数表示。
- 引用未注册来源、重复注册来源或 `state` 非法。
- 时间倒退。
- 买卖侧的价格与数量缺失标记不成对、两侧均缺失，或来源双边报价不满足 `bidPrice < askPrice`。
- 与最新已接受事件发生同序号冲突。

一条命令若存在多个错误，只输出一行错误。不要求区分错误类型。

**错误命令必须完全不改变状态**，包括当前时间、来源状态、报价、接收时间和已接受序号。输出错误后继续处理下一行。

即使消息序号较旧，也必须先完成全部格式与业务校验；不能因准备忽略旧序号而跳过校验。

## 7. 输入规模

- 输入总行数不超过 `2 × 10^5`，每行长度不超过 256 字节，不含换行符。
- 不同来源、品种和 `(source, symbol)` 对的数量分别不超过 `2 × 10^5`。
- 所有 `BBO` 输出中的来源名称出现次数之和不超过 `10^6`。
- 汇总数量及时间计算可能超过 32 位有符号整数范围；所有结果均不超过 64 位有符号整数范围。

## 8. 样例

各组样例独立运行。

### 样例一：同价合并、完整替换与综合交叉

输入：

```text
SOURCE V2 50
SOURCE V1 50
SOURCE V3 50
UPDATE V2 ABC 1 100 7 103 8
UPDATE V1 ABC 1 100 5 102 6
UPDATE V3 ABC 1 99 20 102 4
BBO ABC
UPDATE V3 ABC 2 101 9 - -
BBO ABC
UPDATE V2 ABC 2 - - 101 3
BBO ABC
UPDATE V1 ABC 2 102 2 104 1
BBO ABC
DELETE V1 ABC 3
DELETE V3 ABC 3
BBO ABC
DELETE V2 ABC 3
BBO ABC
```

输出：

```text

BBO ABC 101 9 V3 102 6 V1 NORMAL
BBO ABC 101 9 V3 101 3 V2 LOCKED
BBO ABC 102 2 V1 101 3 V2 CROSSED
BBO ABC - 0 - 101 3 V2 ASK_ONLY
BBO ABC - 0 - - 0 - EMPTY
```
