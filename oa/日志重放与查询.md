# 日志重放与查询

**Event Log Replay & Historical Queries**

> 自拟 C++17 OA 练习，建议限时 120 分钟，并非已核实的 DRW、Jump Trading 或其他公司的原题。日志格式与重放语义均以本文为准。

## 题目

实现一个单线程日志重放与查询程序。

系统记录对整数键值状态的修改事件。日志可能乱序到达，也可能重复。程序先载入并封存日志，然后按规定顺序重放，支持查询当前状态、指定历史时刻的状态，以及时间区间内的事件。

从标准输入逐行读取命令，直到 EOF。每条输入命令按到达顺序处理；日志事件的重放顺序另有规定。

## 1. 数据模型

### 1.1 字段与范围

| 字段 | 含义与范围 |
| --- | --- |
| `eventId` | 全局唯一事件 ID，整数，范围 `1～10^12` |
| `timestamp` | 事件时间戳，整数，范围 `1～10^12` |
| `key` | 长度 1～16，仅含 ASCII 字母、数字或下划线，区分大小写 |
| `value` / `delta` | 有符号整数，范围 `-10^9～10^9` |
| 查询时间与重放时间 | 整数，范围 `0～10^12` |

事件时间戳从 1 开始，因此时间 0 时所有键都不存在。

`eventId` 在整个日志中唯一，不是每个键独立编号，也不是输入行号。它不表示事件的到达顺序。

### 1.2 事件类型

| 类型 | 字段 | 应用效果 |
| --- | --- | --- |
| `SET` | `key value` | 将键设为存在，并把值完整替换为 `value` |
| `ADD` | `key delta` | 键存在时加上 `delta`；键不存在时，以 0 为初值相加并创建该键 |
| `DEL` | `key` | 删除该键；键已不存在时仍视为正常应用 |

键的值为 0 与键不存在是两种不同状态。`ADD key 0` 也会使原本不存在的键变为存在。

每个键还具有 `lastEventId`：截至所查询时刻，最后一个应用到该键的事件 ID。

- 从未应用过任何事件时，`lastEventId` 不存在。
- `DEL` 使值变为不存在，但仍将 `lastEventId` 更新为本事件 ID。
- `SET` 为相同值、`ADD 0`、删除不存在的键，也都更新 `lastEventId`。

### 1.3 确定的重放顺序

所有已接受的不同事件，按以下二元组升序排列：

```text
(timestamp, eventId)
```

先比较时间戳；只有时间戳相同时，才按事件 ID 的数值升序排列。

同一时刻对同一键的多个事件必须依次应用，不能合并、互换顺序或只保留其中一个。对时刻 `t` 的状态查询，必须包含所有 `timestamp <= t` 的事件效果。

## 2. 处理阶段

程序初始处于**载入阶段**，日志为空。

- 载入阶段只允许 `LOG` 和 `SEAL`。
- 成功执行一次 `SEAL` 后，进入**重放与查询阶段**。
- 重放与查询阶段允许 `REPLAY`、`RESET`、`GET`、`AT` 和 `HISTORY`。
- 封存后不得新增、修改或删除日志事件，也不能再次执行 `SEAL`。
- 阶段不允许的命令属于错误，即使它在其他阶段具有合法含义。
- EOF 只结束输入，不隐式封存日志，也不产生额外输出。

## 3. 载入与封存

字段以空格或制表符分隔，允许行首、行尾有空白。每条命令占一行，命令名和事件类型区分大小写。

### 3.1 载入一条事件

```text
LOG eventId timestamp SET key value
LOG eventId timestamp ADD key delta
LOG eventId timestamp DEL key
```

先完整校验本行格式、标识和数值范围，再处理事件 ID：

1. 该 `eventId` 尚未出现：接受并保留本事件。
2. 已存在相同 ID，且时间戳、类型、键及数值字段全部相同：视为重复，忽略。
3. 已存在相同 ID，但任一事件字段不同：视为冲突，输出错误，保留先前接受的事件。

比较数字时使用解析后的数值。前导零不影响相等性，数值字段的 `-0` 与 `0` 相同。

重复事件只保留一次，不重复计入日志数量、重放数量或历史事件查询。即使两条记录的键、时间戳、类型和值都相同，只要事件 ID 不同，它们仍是两个独立事件。

载入成功或忽略重复时不输出。载入日志本身不会修改任何键的当前值。

### 3.2 封存日志

```text
SEAL
```

结束载入，输出：

```text
READY n
```

`n` 为成功接受的不同事件数量。空日志也允许封存。

进入重放与查询阶段后，初始重放时间 `replayTime = 0`，当前状态为空。此时日志事件尚未应用到当前状态。

## 4. 重放与当前状态查询

### 4.1 重放到指定时间

```text
REPLAY t
```

要求 `t >= replayTime`，否则属于错误。

按重放顺序，将当前进度之后、时间戳不大于 `t` 的事件依次应用到当前状态，然后设置 `replayTime = t`。

输出：

```text
REPLAY t appliedCount
```

`appliedCount` 为本条命令新应用的事件数量：

- 包含所有键的事件，不仅是此前查询过的键。
- `DEL` 删除不存在的键等事件，也计为应用一次。
- 相同时间重复 `REPLAY` 时，不重新应用已经覆盖的事件，数量为 0。
- `t` 可以晚于日志中的最后一个事件，也可以落在没有事件的时间区间；仍将重放时间设为 `t`。

### 4.2 重置当前重放进度

```text
RESET
```

将 `replayTime` 设回 0，并清空当前状态，包括所有键的当前值与 `lastEventId`。

封存日志保持完整。之后可以再次从头重放，历史查询也继续可用。

输出一行：

```text
RESET
```

### 4.3 查询当前状态

```text
GET key
```

输出：

```text
GET key replayTime value lastEventId
```

- 键当前存在时，`value` 为其整数值。
- 键当前不存在时，`value` 输出 `-`。
- 当前重放进度内从未应用过该键的事件时，`lastEventId` 输出 `-`。
- 最近事件为 `DEL` 时，值为 `-`，但仍输出该删除事件的 ID。

查询从未出现在日志中的键是合法操作。

## 5. 历史查询

历史查询始终基于**封存的全部日志**，不受当前 `replayTime` 限制。即使尚未执行 `REPLAY`，或查询时间晚于当前进度，也必须正常返回结果。

历史查询不能改变当前重放时间、当前值或后续 `REPLAY` 的计数。

### 5.1 查询指定历史时刻

```text
AT key t
```

返回从空状态开始，按规定顺序应用全部 `timestamp <= t` 事件后，该键的值与最近事件 ID。

输出：

```text
AT key t value lastEventId
```

不存在值、没有最近事件时的 `-` 规则与 `GET` 相同。

时间恰好等于事件时间戳时，包含该时刻的全部事件。若查询时间晚于该键最后一个事件，返回最后状态；删除后不得恢复更早的值。

### 5.2 查询区间内的事件

```text
HISTORY key from to
```

要求 `from <= to`，否则属于错误。

选取该键所有满足以下条件的不同事件：

```text
from <= timestamp <= to
```

按 `(timestamp, eventId)` 升序输出。先输出一行：

```text
HISTORY key from to n
```

随后输出恰好 `n` 行事件，每行使用规范格式：

```text
LOG eventId timestamp SET key value
LOG eventId timestamp ADD key delta
LOG eventId timestamp DEL key
```

区间包含两个端点。同一时刻的所有符合条件事件都返回，包括后来被覆盖的 `SET`、`ADD 0` 和删除不存在的键的事件。

没有符合条件的事件时，只输出数量为 0 的首行，不增加空行。

所有输出数字使用十进制，不保留前导零，不输出 `-0`。

## 6. 错误处理

错误命令输出：

```text
ERROR lineNumber
```

`lineNumber` 为整个输入中的行号，从 1 开始。错误行与空行均计入行号；空行本身属于错误。

错误包括：

- 未知命令、未知事件类型、字段数量不匹配或键格式非法。
- 数字格式或范围非法。
- 相同事件 ID 对应不同内容。
- 在错误的处理阶段执行命令。
- 重放时间倒退，或历史区间起点大于终点。

事件 ID、时间戳和查询时间仅接受十进制数字串。`SET` 与 `ADD` 的数值允许一个可选的前导负号。所有数字字段均不接受前导加号、小数点或指数形式。

一行存在多个错误时，只输出一行错误，不要求区分错误类型。

错误命令必须**完全不改变任何状态**，包括：

- 已接受的事件及事件 ID 的占用情况。
- 当前处理阶段。
- 当前重放时间、键值和最近事件 ID。

因此，一条错误的 `LOG` 不会占用新的事件 ID，之后可以使用该 ID 提交合法事件。输出错误后继续读取下一行。

## 7. 输入规模

- 总输入行数不超过 `2 × 10^5`，每行不超过 256 字节，不含换行符。
- 不同事件和不同键的数量分别不超过 `2 × 10^5`。
- 所有合法 `REPLAY` 输出的 `appliedCount` 之和不超过 `10^6`；`RESET` 后再次重放同一事件，重新计入该总数。
- 所有 `HISTORY` 实际输出的事件行数之和不超过 `10^6`。
- 累加后的键值可能超过 32 位有符号整数范围；所有中间结果与最终结果均在 64 位有符号整数范围内。

## 8. 样例

各组样例独立运行。

### 样例一：乱序载入与同一时刻的事件顺序

输入：

```text
LOG 30 20 ADD PX 5
LOG 10 10 SET PX 100
LOG 20 20 ADD PX 10
LOG 25 20 SET PX 7
LOG 40 30 DEL PX
LOG 50 30 ADD PX 0
SEAL
GET PX
REPLAY 19
GET PX
REPLAY 20
GET PX
AT PX 19
AT PX 20
REPLAY 30
GET PX
HISTORY PX 20 30
```

输出：

```text
READY 6
GET PX 0 - -
REPLAY 19 1
GET PX 19 100 10
REPLAY 20 3
GET PX 20 12 30
AT PX 19 100 10
AT PX 20 12 30
REPLAY 30 2
GET PX 30 0 50
HISTORY PX 20 30 5
LOG 20 20 ADD PX 10
LOG 25 20 SET PX 7
LOG 30 20 ADD PX 5
LOG 40 30 DEL PX
LOG 50 30 ADD PX 0
```
