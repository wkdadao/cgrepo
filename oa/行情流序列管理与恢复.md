# 行情流序列管理与恢复

**Market Data Sequencing & Recovery**

> 自拟 C++17 OA 练习，建议限时 120 分钟，并非已核实的 Jump Trading、DRW 或其他公司的原题。协议及恢复行为均以本文为准。

## 题目

实现一个单线程行情流处理程序，按通道处理带序号的增量消息，并使用完整快照恢复行情状态。

一个通道可以包含多个品种。每个品种只维护最新买价和卖价，不维护订单、价格档位或成交。程序需要处理重复、乱序、序号缺口、快照覆盖，以及恢复期间的查询。

从标准输入逐行读取命令，直到 EOF。按输入行顺序处理；不同通道互不影响。

## 1. 数据与初始状态

### 通道和品种

- `channel` 和 `symbol` 均为长度 1～16 的字母、数字或下划线字符串，区分大小写。
- 同名品种在不同通道中的状态相互独立。
- 价格是整数 tick，范围为 `1～10^9`，必须满足 `bid < ask`。

### 序号

- 序号在**每个通道内统一递增**，不是每个品种各自递增。
- 增量消息的序号 `seq` 为 `1～10^12`。
- 快照序号 `snapshotSeq` 为 `0～10^12`。
- 序号不回绕，不跨日重置；本练习没有会话切换。

### 通道状态

每个已初始化通道包含以下对外概念：

| 名称 | 含义 |
| --- | --- |
| `lastApplied` | 当前行情状态已覆盖到的序号 |
| `nextExpected` | 下一个期望的增量序号，等于 `lastApplied + 1` |
| `pendingCount` | 已收到但尚未应用的不同序号增量消息数量 |
| `LIVE` | 当前没有已知序号缺口 |
| `GAP` | 已收到更晚的增量，但中间仍有缺失序号 |

`LIVE` 只表示尚未观察到缺口，不表示今后的消息已经到齐，也不衡量报价的新鲜程度。

## 2. 输入命令

字段以空白分隔，每条命令占一行。以下尖括号或序号后缀仅用于说明字段，不是实际输入的一部分。

### 2.1 初始化通道

```text
INIT channel
```

创建一个空通道，初始 `lastApplied = 0`、`nextExpected = 1`、`pendingCount = 0`，状态为 `LIVE`。

初始化成功时不输出。重复初始化同一通道属于错误。其他命令引用未初始化通道也属于错误。

### 2.2 更新报价

```text
UPDATE channel seq symbol bid ask
```

这是一条带序号的增量消息。消息被应用时，将该品种的报价完整设置为给定 `bid/ask`；品种不存在时创建它。

实际应用该消息时输出：

```text
APPLY UPDATE channel seq symbol bid ask
```

收到消息不代表可以立即应用，处理时机由第 3 节规定。

### 2.3 删除报价

```text
DELETE channel seq symbol
```

这也是一条带序号的增量消息，与 `UPDATE` 共用通道序号。

实际应用时，删除该品种的报价。如果品种不存在，仍将该消息视为成功应用，照常推进序号。输出：

```text
APPLY DELETE channel seq symbol
```

### 2.4 完整快照

```text
SNAPSHOT channel snapshotSeq n symbol1 bid1 ask1 ... symbolN bidN askN
```

`n` 是快照中的品种数量，范围为 `0～2 × 10^5`；必须恰好提供 `n` 组品种报价，同一快照内的品种不得重复。

快照包含该通道在 `snapshotSeq` 时刻的**全部品种报价**，并代表已经包含序号不大于 `snapshotSeq` 的增量效果。

快照是整条输入行，不需要分片拼接。完整恢复规则见第 4 节。

### 2.5 查询报价

```text
QUOTE channel symbol
```

输出：

```text
QUOTE channel symbol mode lastApplied bid ask
```

`mode` 为该通道当前的 `LIVE` 或 `GAP`。该品种不存在时，两个价格均输出 `-`。

通道处于 `GAP` 时，仍返回本地已经确认的报价，并保留 `GAP` 标记。不得把尚未应用的增量反映到查询结果中。

### 2.6 查询通道状态

```text
STATUS channel
```

输出：

```text
STATUS channel mode lastApplied nextExpected pendingCount gapBegin gapEnd
```

- `LIVE` 时，`pendingCount` 为零，`gapBegin/gapEnd` 均输出 `-`。
- `GAP` 时，只报告**最早一段已知缺口**：从 `nextExpected` 开始，到最小已缓存序号的前一个序号结束。
- 即使还存在更晚的缺口，也不在本次状态行中列出。

## 3. 增量消息的处理规则

所有输入先完成完整校验，合法后才按以下语义处理。

### 3.1 旧消息

若 `seq < nextExpected`，该序号已经应用，或已经被快照覆盖。

忽略该消息，不改变状态，也不输出。不需要保存旧消息内容来比较一致性；合法的旧消息均按序号忽略。

### 3.2 当前期望消息

若 `seq == nextExpected`，应用该消息并推进通道序号。

随后，如果此前已收到的消息能够从新的 `nextExpected` 开始连续接上，也必须在本条输入处理结束前依次应用。每条被应用的消息分别输出一行 `APPLY`，按序号递增排列。

遇到缺失序号时停止应用。不同通道之间不进行全局重排。

### 3.3 更晚的消息

若 `seq > nextExpected`，暂存该消息，等待缺失消息或快照。

此时不改变任何品种报价，不推进 `lastApplied`，也不输出 `APPLY`。输入处理完成后，通道为 `GAP`。

### 3.4 同序号重复与冲突

同一通道中，若某个序号已经暂存：

- 新消息与已缓存消息的**类型、品种和报价数值**全部相同，则视为重复，忽略且不输出。
- 任一项不同，则属于冲突，输出错误；保留先前缓存的消息，其他状态也不改变。
- `UPDATE` 和 `DELETE` 类型不同，即使品种相同也属于冲突。
- 数字文本的前导零不影响数值相等性。

应用完当前可连续处理的全部消息后，若仍有暂存消息，通道为 `GAP`；没有暂存消息则为 `LIVE`。

## 4. 快照恢复规则

快照必须先完整校验，包括品种数量、重复品种、所有价格和字段格式。

### 4.1 旧快照

若 `snapshotSeq < lastApplied`，忽略该快照，不输出，不改变状态。

即使是旧快照，格式或报价非法时仍输出错误。

### 4.2 接受快照

若 `snapshotSeq >= lastApplied`：

1. 当前报价整体替换为快照内容。此前存在、但未出现在快照中的品种被移除。
2. 当前行情状态覆盖到 `snapshotSeq`。
3. 已缓存且序号不大于 `snapshotSeq` 的增量已经被快照覆盖，不再应用，不输出对应的 `APPLY`。
4. 更晚的缓存消息仍然保留。若能从 `snapshotSeq + 1` 开始连续衔接，必须在本条输入处理结束前应用。
5. 衔接后仍有缺口则为 `GAP`，否则为 `LIVE`。

接受快照时，先输出一行：

```text
SNAPSHOT channel snapshotSeq n
```

随后才输出本次恢复衔接产生的各行 `APPLY`。`n` 指输入快照中的品种数，而不是衔接之后的品种数。

允许接受 `snapshotSeq == lastApplied` 的快照，仍执行整体替换并输出快照行。本练习不要求比较该快照与本地报价是否一致。

快照可以越过当前缺失区间。它不会自动生成缺失增量的 `APPLY` 输出。

## 5. 错误处理

以下情况均输出一行：

```text
ERROR lineNumber
```

`lineNumber` 为原始输入行号，从 1 开始；空行也占一个行号。

错误情况包括：

- 空行、未知命令、字段缺失或多余。
- 非法 ID、非法整数、数值超范围。
- 非法报价，例如零价格或 `bid >= ask`。
- 重复初始化或引用未知通道。
- 同通道已缓存序号的消息内容冲突。
- 快照数量不匹配或快照品种重复。

所有数字均采用无符号十进制数字文本，允许前导零，不接受正负号、小数、科学计数法或非数字后缀。

**失败行不得产生任何状态变化或部分输出。** 例如快照最后一个品种非法时，前面的品种也不能已经生效。

一行同时有多个错误时，只输出一行 `ERROR`，无需区分原因。处理失败后继续读取下一行。

所有字段必须先满足基本合法性，才适用“旧消息忽略”或“重复消息忽略”的规则。

## 6. 输出与边界约定

- 标准输出只允许出现上述 `APPLY`、`SNAPSHOT`、`QUOTE`、`STATUS` 和 `ERROR` 行。
- 每行字段之间恰好一个空格，不得有行末空格；整数按普通十进制输出，不保留前导零。
- 缓存、忽略消息、忽略旧快照、成功初始化都不单独输出。
- EOF 时不自动生成快照、恢复请求或错误。仍有缺口的通道保留最后状态，程序正常结束。
- 不要求真实 socket、二进制解码、多线程、超时、A/B 双源切换、磁盘恢复或会话重置。

## 7. 数据规模

- 输入最多 `2 × 10^5` 行。
- 不同通道最多 `10^3` 个。
- 所有快照输入的品种条目数量之和不超过 `2 × 10^5`。
- 每个通道的待处理消息数量只受总输入规模限制；本题不另外定义缓存溢出行为。
- `nextExpected` 允许达到 `10^12 + 1`。
- 只允许使用 C++ 标准库。

## 8. 样例一：乱序、重复与删除

### 输入

```text
INIT C1
UPDATE C1 1 EURUSD 100 102
UPDATE C1 3 EURUSD 103 105
STATUS C1
QUOTE C1 EURUSD
UPDATE C1 3 EURUSD 103 105
UPDATE C1 2 GBPUSD 200 203
STATUS C1
UPDATE C1 1 EURUSD 99 101
QUOTE C1 EURUSD
DELETE C1 4 EURUSD
QUOTE C1 EURUSD
```

### 输出

```text
APPLY UPDATE C1 1 EURUSD 100 102
STATUS C1 GAP 1 2 1 2 2
QUOTE C1 EURUSD GAP 1 100 102
APPLY UPDATE C1 2 GBPUSD 200 203
APPLY UPDATE C1 3 EURUSD 103 105
STATUS C1 LIVE 3 4 0 - -
QUOTE C1 EURUSD LIVE 3 103 105
APPLY DELETE C1 4 EURUSD
QUOTE C1 EURUSD LIVE 4 - -
```

## 9. 样例二：快照恢复与整体替换

### 输入

```text
INIT C2
UPDATE C2 1 AAA 10 12
UPDATE C2 4 AAA 14 16
UPDATE C2 6 CCC 30 32
SNAPSHOT C2 3 2 AAA 13 15 BBB 20 22
QUOTE C2 BBB
STATUS C2
UPDATE C2 5 BBB 21 23
SNAPSHOT C2 2 1 AAA 1 2
QUOTE C2 AAA
SNAPSHOT C2 8 1 DDD 40 42
QUOTE C2 AAA
QUOTE C2 DDD
DELETE C2 9 MISSING
STATUS C2
```

### 输出

```text
APPLY UPDATE C2 1 AAA 10 12
SNAPSHOT C2 3 2
APPLY UPDATE C2 4 AAA 14 16
QUOTE C2 BBB GAP 4 20 22
STATUS C2 GAP 4 5 1 5 5
APPLY UPDATE C2 5 BBB 21 23
APPLY UPDATE C2 6 CCC 30 32
QUOTE C2 AAA LIVE 6 14 16
SNAPSHOT C2 8 1
QUOTE C2 AAA LIVE 8 - -
QUOTE C2 DDD LIVE 8 40 42
APPLY DELETE C2 9 MISSING
STATUS C2 LIVE 9 10 0 - -
```

## 10. 样例三：独立通道、消息冲突与失败不改变状态

### 输入

```text
INIT A
INIT B
UPDATE A 2 X 100 102
UPDATE B 1 Y 200 202
UPDATE A 2 X 101 103
SNAPSHOT A 1 2 X 99 101 X 100 102
STATUS A
UPDATE A 1 X 99 101
QUOTE A X
QUOTE B Y
UPDATE A 3 X 110 109
STATUS A
UPDATE Z 1 X 100 102
INIT A
DELETE A 3 X
QUOTE A X
```

### 输出

```text
APPLY UPDATE B 1 Y 200 202
ERROR 5
ERROR 6
STATUS A GAP 0 1 1 1 1
APPLY UPDATE A 1 X 99 101
APPLY UPDATE A 2 X 100 102
QUOTE A X LIVE 2 100 102
QUOTE B Y LIVE 1 200 202
ERROR 11
STATUS A LIVE 2 3 0 - -
ERROR 13
ERROR 14
APPLY DELETE A 3 X
QUOTE A X LIVE 3 - -
```
