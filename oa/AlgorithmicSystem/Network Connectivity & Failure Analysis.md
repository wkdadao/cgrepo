# C3.3 — Network Connectivity & Failure Analysis（动态网络连通性与故障分析）

> **C3 / Algorithmic System / Network Connectivity & Failure Analysis**  
> 建议用时：**90–120 分钟** ｜ 语言：**C++17/20** ｜ 难度：**高**  
> 训练重点：动态图、连通分量、桥（Bridge）、割点（Articulation Point）、故障影响、边界测试  
> **本文只含完整题面、样例及测试要求，不包含算法提示、参考解法或实现。**

## 1. Problem Statement

某交易平台在多个数据中心之间维护一张通信网络。数据中心视为**节点**，物理链路视为**无向边**。

网络中可能存在冗余链路，也可能存在单点故障：删除某条链路或某个节点后，原本连通的部分网络可能被拆分成多个互不连通的区域。

你需要实现一个单线程命令行程序，支持以下操作：

- 动态新增、更新和删除链路；
- 判断两个节点是否连通；
- 统计网络中的连通分量；
- 判断某条链路是否为 **Bridge（桥）**；
- 判断某个节点是否为 **Articulation Point（割点）**；
- 计算指定节点故障后网络中剩余的连通分量数；
- 汇总当前网络的连通分量、桥和割点的数量。

所有查询针对**当前网络状态**，并按照命令顺序执行。

## 2. Network Model

网络由 `N` 个节点组成，编号为 `0` 至 `N-1`。

每条链路的数据格式为：

~~~text
id u v
~~~

| 字段 | 含义 |
| --- | --- |
| `id` | 链路唯一 ID（整数） |
| `u` | 一个端点 |
| `v` | 另一个端点 |

**关键规则：**

1. 链路是**无向**的，因此 `u-v` 和 `v-u` 表示同一连接方向上的关系。
2. 允许**平行边（Parallel Edges）**：两个节点之间可以同时存在多条不同 ID 的物理链路，彼此独立。
3. 允许**自环（Self-loop）**：`u == v`，但自环不连接两个不同节点。
4. 链路由 ID 唯一标识；删除某条链路不会删除同端点的其他链路。
5. 删除某条链路后，允许在后续 `ADD` 命令中重新使用其 ID。
6. `UPDATE` 可以修改已存在链路的两个端点，ID 不变。
7. 所有节点始终存在，**包括没有连接任何链路的孤立节点**。
8. 一条查询不会永久改变网络，只有 `ADD`、`UPDATE` 和 `REMOVE` 会修改网络。

## 3. Definitions

### 3.1 Connected

两个节点 `u` 和 `v` 如果存在一条由当前活跃链路构成的路径相连，则称它们连通。

- 节点可以经过零条边到达自身，所以 `CONNECTED u u` 永远返回 `YES`。
- 平行边不改变“是否连通”的定义。
- 自环不会让原本不连通的不同节点连通。

### 3.2 Connected Component

**连通分量**是一个极大的、两两可达的节点集合。

- 一个孤立节点也是一个连通分量。
- 所有节点都必须计入连通分量统计。
- 没有任何边、但有 `N` 个节点时，连通分量数量为 `N`。

### 3.3 Bridge（桥）

一条**当前存在**的链路 `id` 是桥，当且仅当：

> 如果仅删除这条链路，网络的连通分量数量会**增加**。

对本题的无向图，删除一条桥会使连通分量数恰好增加 1。

注意：

- 如果两个节点之间至少有两条独立的平行边，仅删除其中一条不会破坏它们之间的直接连通。
- 自环不可能是桥。
- 桥的定义适用于本来就不连通的网络；并不要求当前网络只有一个连通分量。

### 3.4 Articulation Point（割点）

一个节点 `u` 是割点，当且仅当：

> 删除节点 `u` **以及与 `u` 相连的所有链路**后，剩余网络的连通分量数量严格**大于**删除前整个网络的连通分量数量。

这里的“删除节点”是**假设性故障**，而不是永久修改网络。

特别注意：

- 删除节点后，**该节点不再计入任何连通分量**。
- 删除一个孤立节点，会使连通分量数减少 1，因此该节点不是割点。
- 对于一个只有两个节点、由一条边连接的网络，删除任一端点后仍只有一个连通分量，因此两者都不是割点。
- `N = 1` 时，删除唯一节点后，剩余网络有 **0** 个连通分量，该节点不是割点。
- 割点定义同样适用于原本不连通的网络。

## 4. Commands

命令名大写。输入保证每条命令的格式正确、参数合法。

### 4.1 `ADD id u v`

添加一条无向边。`id` 保证在当前网络中尚未使用。

无输出。

### 4.2 `UPDATE id u v`

修改当前存在的链路 `id`，使其两个端点变为 `u` 和 `v`。

无输出。

### 4.3 `REMOVE id`

删除当前存在的链路 `id`。

无输出。

### 4.4 `CONNECTED u v`

判断节点 `u` 和 `v` 是否连通。

输出：

~~~text
YES
~~~

或

~~~text
NO
~~~

### 4.5 `COMPONENTS`

输出当前网络的连通分量数量（单个非负整数）。

### 4.6 `BRIDGE id`

判断当前存在的链路 `id` 是否为桥。

输出 `YES` 或 `NO`。

此命令只做**假设性删除**；查询结束后链路仍然存在。

### 4.7 `CUTVERTEX u`

判断当前存在的节点 `u` 是否为割点。

输出 `YES` 或 `NO`。

此命令不改变网络。

### 4.8 `FAIL_NODE u`

假设节点 `u` 故障，被完全移除（连同所有关联链路），输出**剩余网络**的连通分量数量。

例如，原来只有 `0-1-2` 这条路径，删除节点 1 后，节点 0 和 2 都成为孤立节点；输出 `2`。

**这是一次只读查询；不会实际移除节点或边。**

### 4.9 `SUMMARY`

输出三个整数，按以下顺序、用一个空格分隔：

~~~text
componentCount bridgeCount articulationPointCount
~~~

分别表示当前网络的：

1. 连通分量数量；
2. 桥的数量（按**链路 ID** 计数）；
3. 割点的数量（按**节点**计数）。

## 5. Input Format

~~~text
N M
id_1 u_1 v_1
...
id_M u_M v_M
Q
command_1
...
command_Q
~~~

- `N` 是节点数量。
- `M` 是初始链路数量。
- 接下来 `M` 行描述初始无向边。
- `Q` 是命令数量。
- 接下来恰有 `Q` 行命令。

输入中所有整数及命令名均以空白字符分隔。

## 6. Output Format

每条查询命令（`CONNECTED`、`COMPONENTS`、`BRIDGE`、`CUTVERTEX`、`FAIL_NODE`、`SUMMARY`）输出恰好一行。

`ADD`、`UPDATE`、`REMOVE` **不产生任何输出**。

输出不能包含调试文字、提示符或额外空行。

## 7. Constraints

| 项目 | 约束 |
| --- | --- |
| 节点数量 | `1 <= N <= 80` |
| 初始链路数量 | `0 <= M <= 300` |
| 整个输入出现的不同链路 ID 总数 | `<= 300` |
| 链路 ID | `1 <= id <= 10^9` |
| 节点编号 | `0 <= u, v < N` |
| 命令数量 | `1 <= Q <= 200` |

额外保证：

- 初始链路 ID 互不相同。
- `ADD` 的 ID 在该命令发生时不存在。
- `UPDATE`、`REMOVE`、`BRIDGE` 的 ID 在命令发生时存在。
- `UPDATE` 或 `ADD` 的端点可以相同，即允许自环。
- 全部命令参数合法，不需要处理 `ERROR`。

**性能要求**：在上述范围内正确完成所有命令即可；不要求维护在线增量图算法。可在需要时重新分析当前网络。实现仍需避免明显的指数时间搜索。

## 8. Samples

### Sample 1 — 环、桥、割点与新增冗余链路

**Input**

~~~text
5 4
1 0 1
2 1 2
3 2 0
4 2 3
10
SUMMARY
CONNECTED 0 3
CONNECTED 0 4
BRIDGE 4
CUTVERTEX 2
FAIL_NODE 2
ADD 5 3 0
SUMMARY
REMOVE 5
SUMMARY
~~~

**Output**

~~~text
2 1 1
YES
NO
YES
YES
3
2 0 0
2 1 1
~~~

**Explanation**

- 初始网络中 `0-1-2-0` 构成环，`2-3` 是唯一的桥，节点 2 是唯一的割点；节点 4 是孤立节点。
- 假设节点 2 故障，剩余有 `{0,1}`、`{3}` 和 `{4}` 三个连通分量。
- 新增 `3-0` 后，0、1、2、3 所在的区域拥有冗余路径，不再有桥或割点。
- 删除新增边后恢复原状。

### Sample 2 — 平行边、自环与边端点更新

**Input**

~~~text
3 4
10 0 1
11 0 1
12 1 1
13 1 2
12
SUMMARY
BRIDGE 10
BRIDGE 11
BRIDGE 12
BRIDGE 13
FAIL_NODE 1
REMOVE 11
SUMMARY
UPDATE 10 0 2
SUMMARY
CUTVERTEX 2
CUTVERTEX 1
~~~

**Output**

~~~text
1 1 1
NO
NO
NO
YES
2
1 2 1
1 2 1
YES
NO
~~~

**Explanation**

- 两条 `0-1` 平行边互为冗余，因此都不是桥。
- `1-1` 是自环，不是桥。
- 初始唯一的桥是 `1-2`。
- 删除其中一条 `0-1` 平行边后，`0-1` 也成为桥。
- 更新链路 10 为 `0-2` 后，节点 2 成为割点，节点 1 不再是割点。

### Sample 3 — 两个区域、链路重连与环形成

**Input**

~~~text
4 2
1 0 1
2 2 3
9
SUMMARY
UPDATE 2 1 2
SUMMARY
FAIL_NODE 1
ADD 3 0 2
SUMMARY
REMOVE 1
SUMMARY
CONNECTED 3 0
~~~

**Output**

~~~text
2 2 0
2 2 1
3
2 0 0
2 2 1
NO
~~~

### Sample 4 — 单节点与自环

**Input**

~~~text
1 1
5 0 0
8
SUMMARY
CONNECTED 0 0
BRIDGE 5
CUTVERTEX 0
FAIL_NODE 0
REMOVE 5
SUMMARY
FAIL_NODE 0
~~~

**Output**

~~~text
1 0 0
YES
NO
NO
0
1 0 0
0
~~~

### Sample 5 — 孤立节点与原本不连通的网络

**Input**

~~~text
6 3
1 0 1
2 1 2
3 4 5
9
SUMMARY
FAIL_NODE 3
FAIL_NODE 1
CUTVERTEX 4
BRIDGE 3
UPDATE 3 2 3
SUMMARY
ADD 4 0 3
SUMMARY
~~~

**Output**

~~~text
3 3 1
2
4
NO
YES
3 3 2
3 0 0
~~~

**Explanation**

- 初始有三个连通分量：`{0,1,2}`、`{3}`、`{4,5}`。
- 删除孤立节点 3 后，只剩两个连通分量。它不是割点。
- 删除节点 1 后，原来的 `{0,1,2}` 分裂成 `{0}` 与 `{2}`，总分量数由 3 增加到 4。
- 删除节点 4 后，节点 5 虽然孤立，但原分量 `{4,5}` 只变成 `{5}`，总分量数不变，所以 4 不是割点。
- 把边 3 改接到 `2-3` 后，0、1、2、3 构成一条链；节点 1 和 2 是割点。
- 再加 `0-3`，形成一个环，所有桥和割点消失。

## 9. Extra Tests You Must Design

请在提交前设计并实际运行测试，至少覆盖：

1. `N=1, M=0`，没有任何边。
2. `M=0`、`N>1`，所有节点孤立。
3. 两个节点之间仅有一条边，再新增平行边。
4. 平行边与自环同时存在，并删除其中一条。
5. 三角形、链、星形（Star）三种基本拓扑。
6. 多个互不连通的区域，其中某一区域存在桥。
7. 删除孤立节点时，连通分量数量**减少**。
8. 删除叶节点时，连通分量数量**不变**。
9. 删除中间节点时，连通分量数量**增加**。
10. 新增链路后，原先的桥或割点不再关键。
11. `UPDATE` 使一条原来非桥的边变为桥，或反之。
12. `REMOVE` 后重新 `ADD` 相同 ID，但使用不同端点。
13. 自环不会错误地增加连通分量数或产生桥。
14. `CONNECTED u u` 不论是否有边，都应返回 `YES`。
15. `SUMMARY` 在连续多次增删改命令后保持正确。

特别提醒：**遍历无向多重图时，存在平行边是本题的一项重要隐藏测试风险。**
