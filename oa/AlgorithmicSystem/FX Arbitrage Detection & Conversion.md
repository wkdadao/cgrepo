# C3.2 — FX Arbitrage Detection & Conversion（外汇套利检测与最优兑换）

> **C3 / Algorithmic System / FX Arbitrage Detection & Conversion**  
> 建议用时：**90–120 分钟** ｜ 语言：**C++17/20** ｜ 难度：**高**  
> 训练重点：从金融业务语义建立图模型、最优兑换、可达性、套利影响范围、动态数据更新、数值边界  
> **本文件只含题目描述、样例和测试要求，不提供算法提示、参考实现或解法。**

## 1. Problem Statement

一家电子外汇交易平台维护若干货币之间的**单向兑换报价**。每个报价规定：使用一定数量的源货币，可以按固定比例兑换成目标货币。

系统接收连续命令，能够新增、修改和删除报价，并回答两类问题：

1. 当前**整个市场**中，是否存在能够通过一系列兑换增加初始资金的**套利循环**？
2. 给定起始货币、目标货币和初始数量，最多能获得多少目标货币？

市场中可能存在套利循环；在本题的数学模型下，这可能使某些兑换查询的最优结果**没有有限上界**。但请注意：**市场中存在套利，并不代表任意货币对的兑换都无界。**

请编写一个独立的命令行程序，依次处理命令，并输出各查询结果。

## 2. Exchange Model

系统有 `N` 种货币，编号为 `0` 至 `N-1`。

每个报价是一个**有向**兑换关系：

~~~text
id  from  to  rate
~~~

其含义为：

> 持有 `x` 单位的 `from` 货币，可以兑换为 `x * rate` 单位的 `to` 货币。

例如：

~~~text
1 0 1 0.900000
~~~

表示持有 100 单位的货币 `0`，通过报价 ID 1，可以得到 90 单位的货币 `1`。

规则：

- 每个当前有效报价的 `id` 唯一。
- **兑换有方向**。`from -> to` 并不隐含反方向报价。
- 同一个货币对允许多个不同 ID 的报价，且兑换率可以不同。
- 允许 `from == to` 的报价（自环）。
- 删除报价后，可以重新使用该 ID。
- `UPDATE` 只修改兑换率，不能修改货币对。
- 每次兑换按照该报价的 `rate` **乘法转换**。
- **允许重复经过同一货币和重复使用同一报价**，兑换次数没有限制。
- 本题不考虑手续费、汇差之外的其他成本、最小交易量、资金上限、滑点、精度截断或市场冲击。
- 一条报价的 `rate` 始终严格大于 0。

一条由 `k` 次兑换组成的路线，其总转换倍率是沿途 `rate` 的**乘积**：

~~~text
finalAmount = initialAmount * rate_1 * rate_2 * ... * rate_k
~~~

使用零次兑换也是合法操作，但只有当起点与终点为同一货币时才可作为完整兑换路线。零次兑换的倍率为 1。

## 3. Arbitrage Definition

**套利循环**是从某一货币出发，经过一次或多次兑换后回到同一货币，且最终金额**严格大于**初始金额的兑换路线。

等价地，该闭合路线的所有兑换率之积严格大于 1：

~~~text
rate_1 * rate_2 * ... * rate_k > 1
~~~

例如，下列两条报价构成套利：

~~~text
0 -> 1 : 2.0
1 -> 0 : 0.6
~~~

从 1 单位的货币 0 出发，经过两次兑换可得到 1.2 单位的货币 0。

明确规则：

- 套利可以发生在任何货币组成的连通区域，不要求货币 `0` 能到达该区域。
- 一个自环报价如果 `rate > 1`，它本身就是套利循环。
- 循环的倍率恰好为 1 **不构成**套利。
- 因为允许无限次重复兑换，有利可图的套利循环可以被重复使用。

## 4. Commands

所有命令按照输入顺序执行。输入保证语法及参数合法。

### 4.1 `ADD id from to rate`

新增一个兑换报价。

- `id` 在命令执行前不是活跃报价 ID。
- 新报价立即对之后的查询生效。
- **不输出**。

### 4.2 `UPDATE id rate`

修改已存在报价的兑换率，方向不变。

- `id` 保证当前存在。
- **不输出**。

### 4.3 `REMOVE id`

删除报价。

- `id` 保证当前存在。
- 删除后，其余报价保持不变。
- **不输出**。

### 4.4 `ARBITRAGE`

判断当前整个市场是否存在**任意**套利循环。

输出：

- 存在套利循环：`YES`
- 不存在套利循环：`NO`

注意：即便套利位于与其他货币完全隔离的区域，也要回答 `YES`。

### 4.5 `BEST s t amount`

从 `amount` 单位的货币 `s` 出发，经过零次或多次兑换，求最终最多可以获得多少单位货币 `t`。

输出分为三种情况，按下列语义判断。

**情况 A — 不可达**

如果没有任何从 `s` 到 `t` 的兑换路线，输出：

~~~text
IMPOSSIBLE
~~~

**情况 B — 无有限上界**

如果存在一条从 `s` 出发、最终可到达 `t` 的路线，并且沿途能进入某个套利循环、重复使用该循环任意多次后仍可到达 `t`，那么最终数量可以无限增长。

输出：

~~~text
UNBOUNDED
~~~

**情况 C — 有限最优值**

其余情况下，输出可以得到的**最大目标货币数量**，保留小数点后 6 位。

例如：

~~~text
13500.000000
~~~

请注意以下细节：

- 某个套利循环**从 `s` 可达**，但循环区域**无法到达 `t`**，不应直接使查询结果为 `UNBOUNDED`。
- 某个套利循环可以到达 `t`，但从 `s` **无法到达循环**，同样不应导致 `UNBOUNDED`。
- `s == t` 时，零次兑换总是可行，所以结果**至少为 `amount`**；若从 `s` 能进入套利循环并返回 `s`，则结果为 `UNBOUNDED`。
- 有效报价被 `UPDATE` 或 `REMOVE` 后，需要根据**当前报价状态**重新作答。
- 不要求输出兑换路线，只需要输出结果。

## 5. Input Format

~~~text
N M
id_1 from_1 to_1 rate_1
...
id_M from_M to_M rate_M
Q
command_1
...
command_Q
~~~

- 第一行：货币数量 `N`，初始报价数量 `M`。
- 随后 `M` 行：每行一条初始报价。
- 下一行：命令数量 `Q`。
- 随后 `Q` 行：每行一条命令。

命令名均为大写，数据字段之间用空格分隔。`rate` 和 `amount` 使用十进制数字表示。

## 6. Output Format

每条 `ARBITRAGE` 或 `BEST` 命令输出一行。

| 命令 | 可能输出 |
| --- | --- |
| `ARBITRAGE` | `YES` / `NO` |
| `BEST` | `IMPOSSIBLE` / `UNBOUNDED` / 数值 |

有限的 `BEST` 数值必须使用**固定 6 位小数**格式。不要输出货币单位、额外说明或调试信息。

在有限数值的评测中，考虑浮点计算误差，可接受的数值误差为：

~~~text
absoluteError <= max(1e-6, 1e-6 * abs(expectedValue))
~~~

其中打印仍需固定 6 位小数；`YES`、`NO`、`IMPOSSIBLE`、`UNBOUNDED` 必须完全匹配。

## 7. Constraints

| 项目 | 约束 |
| --- | --- |
| 货币数量 | `1 <= N <= 45` |
| 初始报价数量 | `0 <= M <= 300` |
| 整份输入中不同报价 ID 的数量 | `<= 300` |
| 报价 ID | `1 <= id <= 10^9` |
| 货币编号 | `0 <= from, to, s, t < N` |
| 兑换率 | `0.000001 <= rate <= 1000` |
| 兑换率精度 | 小数点后最多 6 位 |
| 初始兑换数量 | `0.000001 <= amount <= 1000` |
| 初始数量精度 | 小数点后最多 6 位 |
| 命令数量 | `1 <= Q <= 200` |

初始所有报价 ID 各不相同；在任意时刻最多有 300 条活跃报价。

数值保证：

- 对任何**简单有向循环**（除首尾同一节点外，不重复经过节点），如果其倍率不等于 1，则它与 1 的相对差距至少为 `1e-8`。
- 不会设置依赖于极其微小数值差别才能区分 `YES` / `NO`、`UNBOUNDED` / 有限数值的测试。
- 所有合法查询的有限最优值都能在 IEEE 754 `double` 的数值范围内表示。

## 8. Samples

### Sample 1 — 最优兑换与新增套利

**Input**

~~~text
3 3
1 0 1 0.9
2 1 2 150
3 0 2 130
5
BEST 0 2 100
ARBITRAGE
ADD 4 2 0 0.008
ARBITRAGE
BEST 0 2 100
~~~

**Output**

~~~text
13500.000000
NO
YES
UNBOUNDED
~~~

**Explanation**

初始时，从 `0 -> 1 -> 2` 的倍率为 `0.9 * 150 = 135`，优于直接从 `0 -> 2` 的倍率 130。

新增 `2 -> 0` 报价后，`0 -> 1 -> 2 -> 0` 的循环倍率为 `0.9 * 150 * 0.008 = 1.08`。这个循环可以反复利用，随后仍能到达货币 2。

### Sample 2 — 市场有套利，但起点无法到达套利区域

**Input**

~~~text
5 5
1 0 1 2
2 1 2 3
3 0 2 5
4 3 4 2
5 4 3 0.6
5
ARBITRAGE
BEST 0 2 10
BEST 0 4 10
BEST 3 3 7
BEST 0 0 1
~~~

**Output**

~~~text
YES
60.000000
IMPOSSIBLE
UNBOUNDED
1.000000
~~~

**Explanation**

货币 3 和 4 之间存在倍率为 1.2 的套利循环，但从货币 0 无法进入该区域。查询 `BEST 0 2 10` 仍有有限最优值 60。

### Sample 3 — 起点能够套利，但套利区域无法到达指定终点

**Input**

~~~text
5 5
1 0 1 2
2 1 2 0.6
3 2 1 2
4 0 3 4
5 3 4 2
8
ARBITRAGE
BEST 0 4 10
BEST 0 2 10
BEST 1 4 10
ADD 6 2 3 0.5
BEST 0 4 10
REMOVE 6
BEST 0 4 10
~~~

**Output**

~~~text
YES
80.000000
UNBOUNDED
IMPOSSIBLE
UNBOUNDED
80.000000
~~~

**Explanation**

循环 `1 -> 2 -> 1` 的倍率为 `0.6 * 2 = 1.2`。

最初，虽然 `0` 可以进入该套利循环，但循环区域到不了 `4`。因此 `BEST 0 4 10` 的有限最优路线是 `0 -> 3 -> 4`，最终数量为 `10 * 4 * 2 = 80`。

新增 `2 -> 3` 后，循环区域能够到达 `4`，所以查询变为 `UNBOUNDED`。删除该边后恢复有限最优值。

### Sample 4 — 修改后产生套利，再删除关键链路

**Input**

~~~text
2 2
1 0 1 2
2 1 0 0.4
6
ARBITRAGE
BEST 0 1 3
UPDATE 2 0.6
ARBITRAGE
REMOVE 1
BEST 0 1 3
~~~

**Output**

~~~text
NO
6.000000
YES
IMPOSSIBLE
~~~

### Sample 5 — 倍率恰好为 1 不属于套利

**Input**

~~~text
3 3
1 0 1 0.5
2 1 0 2
3 1 2 1.2
4
ARBITRAGE
BEST 0 0 10
BEST 0 2 10
BEST 2 0 10
~~~

**Output**

~~~text
NO
10.000000
6.000000
IMPOSSIBLE
~~~

### Sample 6 — 自环、删除和重新使用 ID

**Input**

~~~text
2 1
7 0 0 1.1
8
ARBITRAGE
BEST 0 0 2
BEST 0 1 2
REMOVE 7
ARBITRAGE
ADD 7 0 1 2
BEST 0 1 2
BEST 0 0 2
~~~

**Output**

~~~text
YES
UNBOUNDED
IMPOSSIBLE
NO
4.000000
2.000000
~~~

## 9. Additional Test Cases to Design Yourself

除上面样例外，请自己构造并执行以下类型的测试：

1. `N = 1`，没有报价，查询 `ARBITRAGE` 和 `BEST 0 0 amount`。
2. 只有一个 `rate > 1` 的自环；`rate == 1` 的自环。
3. 有两个反向报价，但倍率恰好等于 1、低于 1、高于 1。
4. 存在套利，但套利循环与起点和目标都不连通。
5. 起点可到达套利循环，但循环无法到达目标。
6. 循环可到达目标，但起点无法到达循环。
7. 存在两条及以上兑换路线，单边报价最高的路线并不是乘积最高的路线。
8. 同一有向货币对存在平行报价。
9. `UPDATE` 将原本不存在的套利变为存在，或者将套利消除。
10. `REMOVE` 使原本可达的目标变成不可达。
11. 删除一个 ID 后重新 `ADD`，新报价方向与原报价不同。
12. 零次兑换与可获利的非零次兑换之间的区别。
13. 多个套利循环，其中只有部分会影响指定的 `BEST` 查询。
14. 输入顺序随机、混合多次 `ARBITRAGE`、`BEST` 和更新操作。
