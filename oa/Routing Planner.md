# Routing Planner（多约束最优路由规划）

> 自拟 C++17/20 两小时 OA 综合题，**不是已核实的 DRW 真题**。
> 重点：Dijkstra、扩展状态图（State Graph）、约束最短路。
> 建议用时：120 分钟。P0。

## 1. 背景与任务

交易系统需要在一张有向路由网络中，把请求从源节点发送到目标节点。每条有向边有一个**非负整数路由成本**。同一个源节点和目标节点可能存在多条不同的路径。

用户每次查询给出：

- 最多可以走 K 条边（即最多 K hops）。
- 是否拥有一张一次性折扣券。
- 如果拥有，**最多选择路径上的一条边**，把该边成本从 c 降为 floor(c/2)；也允许完全不使用。

你的任务是计算满足条件的**最小总成本**。某个节点在同一条路径中可以重复访问，边成本允许为 0。因为存在最多 K 条边的上限，路径一定是有限长度。

## 2. 输入格式

~~~text
N M Q
u1 v1 cost1
...
uM vM costM
ROUTE source target K coupon
...
~~~

- N 个节点，编号 1..N。
- M 条有向边；可包含同向平行边、自环。
- 每行查询的 coupon 为 0 或 1，分别表示没有折扣券或有一张折扣券。
- K 允许为 0。

输入保证所有编号及字段合法。

## 3. 输出格式

每个 ROUTE 输出一行：

~~~text
minimumCost
~~~

其中 minimumCost 是满足最多 K 条边及折扣规则的最小成本。如果目标不可达，输出：

~~~text
-1
~~~

当 source == target 时，可以选长度为 0 的路径，成本为 0，因此最优答案必定为 0。

只需要输出最小成本，不要求返回实际路径或折扣使用位置。

## 4. 样例一：跳数限制与一次性折扣

输入：

~~~text
4 5 4
1 2 8
2 4 8
1 3 4
3 4 20
1 4 30
ROUTE 1 4 2 0
ROUTE 1 4 2 1
ROUTE 1 4 1 1
ROUTE 4 1 3 1
~~~

输出：

~~~text
16
12
15
-1
~~~

解释：

1. 不使用折扣，1 -> 2 -> 4 总成本 8+8=16。
2. 有折扣时，同一路径对其中一条 8 的边打折，总成本 4+8=12。
3. 最多走一条边，只有直接走 1 -> 4，折扣后成本 floor(30/2)=15。
4. 图是有向的，4 无法返回 1。

## 5. 样例二：零成本边、零跳和可选优惠

输入：

~~~text
3 3 4
1 2 0
2 3 7
1 3 10
ROUTE 1 3 2 1
ROUTE 1 3 1 0
ROUTE 2 2 0 1
ROUTE 1 3 0 1
~~~

输出：

~~~text
3
10
0
-1
~~~

解释：1 -> 2 -> 3 可以只将成本 7 的那条边折半，floor(7/2)=3；无须强制使用折扣券。

## 6. 规模约束

- 1 <= N <= 5000；0 <= M <= 20000；1 <= Q <= 20。
- 0 <= cost <= 10^9；0 <= K <= 20。
- 所有答案在 int64_t 范围内。
- 查询之间相互独立，不修改图，也不消耗后续查询的折扣券。

## 7. 状态与语义

直接用一个 dist[node] 存最短距离通常不正确。

正确的历史信息至少包含：

- 当前节点 node。
- 已走过的边数 usedHops，范围 0..K。
- 折扣券是否已经使用 usedCoupon，0 或 1。

不同的 (node, usedHops, usedCoupon) **不可以随意合并**：同一个节点即使当前费用更低，也可能用掉更多跳数或提前使用了折扣券。

从状态 (u, h, used) 沿成本为 c 的边 u -> v，可产生：

1. 不打折：(v, h+1, used)，额外花费 c。
2. 如果仍有券且尚未使用：(v, h+1, 1)，额外花费 floor(c/2)。

只有 h < K 时才能继续经过边。答案是所有 (target, h, used) 中的最小距离。

## 8. 目标复杂度

采用扩展状态图上的 Dijkstra：

- 状态数 O(N*K*2)。
- 转移数 O(M*K*2)。
- 单次查询目标：O((N*K + M*K) log(N*K)) 的量级。
- 内存目标：O(N*K + M)。

不要求最优常数；正确处理过期 priority_queue entry 即可。

## 9. 加分扩展（不属于必做）

1. 输出完整最优路径和在哪条边使用了折扣。存在等价最优路径时可输出任意一个。
2. 增加禁用节点 / 禁用边的集合；讨论是否需要重新建图。
3. 支持至多 C 张券，讨论状态维度、复杂度和可扩展性。
4. 给每条边增加 latency 和 fee，分别设置约束上限：解释为什么不能简单把两个目标随意相加成单一权重。
5. 加入不断更新的边成本，讨论批量查询时选择重算还是缓存。

## 10. 自测清单

- source==target；K==0；没有边；不可达。
- K 比最短可达路径还小；多条平行边；自环和 0 成本环。
- 折扣用在最贵边未必对所有路径都最优。
- 当前成本最小的状态可能已耗尽跳数，不能替代成本略高但跳数较少的状态。
- floor 对奇数成本应向下取整；不使用券有时同样最优。
- 结果可能超过 int32_t，使用安全的 INF 和 int64_t。
