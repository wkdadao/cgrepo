# 二进制消息流解析

**Binary Message Stream Decoder**

> 自拟 C++17 OA 练习，建议限时 120 分钟，并非已核实的 DRW、Jump Trading 或其他公司的原题。下述二进制协议为练习协议，全部规则以本文为准。

## 1. 题目

实现一个增量二进制消息解析程序。

程序通过若干次分片输入接收字节流。一个分片可能只包含消息的一部分，也可能包含多条完整消息，或前一条消息的结尾与后一条消息的开头。

程序需要识别消息边界，校验报文，解析心跳、报价和成交消息，并输出对应的文本记录。任何消息都可能跨任意数量的分片。

本题中的序号仅作为消息字段输出；序号重复、跳号或乱序均合法。不维护订单簿或订单状态。

## 2. 通用二进制布局

一条消息由 **8 字节 Header、Body、2 字节 Trailer** 组成。

所有多字节整数均为**大端序**。有符号整数使用二进制补码表示。布局紧凑，没有隐含填充字节，字段地址不保证对齐。

### 2.1 Header

偏移量相对于整条消息的第一个字节，从零开始。

| 偏移 | 长度 | 字段 | 类型与含义 |
| --- | --- | --- | --- |
| 0 | 2 | `totalLength` | `uint16`，整条消息总字节数，包含 Header、Body 和 Trailer |
| 2 | 1 | `version` | `uint8`，必须为 `1` |
| 3 | 1 | `type` | `uint8`，消息类型 |
| 4 | 4 | `seq` | `uint32`，范围为 `0～2^32-1` |

合法 `totalLength` 范围为 **10～1024** 字节。

### 2.2 Trailer

最后两个字节为大端 `uint16` 校验和：

- 将整条消息中**除 Trailer 自身外**的全部字节，按无符号字节数值相加。
- 结果对 `65536` 取模。
- Trailer 必须等于该结果。

### 2.3 已知消息类型

| type 字节 | ASCII | 消息 |
| --- | --- | --- |
| `0x48` | `H` | 心跳 |
| `0x51` | `Q` | 报价 |
| `0x54` | `T` | 成交 |

其他任意 type 字节均按“未知类型”规则处理。

## 3. Body 布局与字段规则

以下偏移量均相对于 **Body 的第一个字节**，即整条消息偏移 8。

### 3.1 心跳 H

Body 为空，整条消息长度必须恰好为 `10` 字节。

合法时输出：

```text
HEARTBEAT seq
```

### 3.2 报价 Q

`n` 是 `symbolLength` 的数值。

| Body 偏移 | 长度 | 字段 | 类型 |
| --- | --- | --- | --- |
| 0 | 1 | `symbolLength` | `uint8` |
| 1 | n | `symbol` | n 个 ASCII 字节，无结束符 |
| 1+n | 4 | `bidPrice` | `int32` |
| 5+n | 4 | `bidQty` | `uint32` |
| 9+n | 4 | `askPrice` | `int32` |
| 13+n | 4 | `askQty` | `uint32` |

Body 长度必须恰好为 `17+n`，整条消息长度为 `27+n`。

字段要求：

- `1 <= symbolLength <= 8`。
- symbol 的每个字节只能为 `A～Z` 或 `0～9`，不含填充字节或字符串结束符。
- 买卖价格均以整数 tick 表示，允许负数和零，必须满足 `bidPrice < askPrice`。
- `bidQty > 0` 且 `askQty > 0`；允许达到 `2^32-1`。

合法时输出：

```text
QUOTE seq symbol bidPrice bidQty askPrice askQty
```

### 3.3 成交 T

`n` 是 `symbolLength` 的数值。

| Body 偏移 | 长度 | 字段 | 类型 |
| --- | --- | --- | --- |
| 0 | 8 | `tradeId` | `uint64` |
| 8 | 1 | `symbolLength` | `uint8` |
| 9 | n | `symbol` | n 个 ASCII 字节，无结束符 |
| 9+n | 1 | `side` | 一个 ASCII 字节 |
| 10+n | 4 | `price` | `int32` |
| 14+n | 4 | `qty` | `uint32` |

Body 长度必须恰好为 `18+n`，整条消息长度为 `28+n`。

字段要求：

- `tradeId > 0`，允许达到 `2^64-1`。
- symbol 的长度与字符规则同报价消息。
- side 只能是 `B` 或 `S`。
- price 是整数 tick，允许 `int32` 范围内的负数、零和正数。
- `qty > 0`，允许达到 `2^32-1`。

合法时输出：

```text
TRADE seq tradeId symbol side price qty
```

本题不校验 tradeId 的跨消息唯一性。

### 3.4 未知类型

未知类型仍必须满足通用长度、版本和校验和要求。

Body 作为不透明字节处理，可以为空或含任意字节，包括零字节，以及与合法 Header 相同的字节片段。

合法时输出：

```text
UNKNOWN seq type totalLength
```

type 输出为**两位大写十六进制**，不带 `0x` 前缀。其余数字按十进制输出。

## 4. 文本输入命令

为了方便准备测试数据，命令行使用十六进制文本表示输入字节。实际解析对象是文本解码后的二进制字节，而不是十六进制字符。

每条命令占一行，命令与参数之间可以有多个空格或制表符。

### 4.1 输入字节分片

```text
FEED hex
```

hex 是一个非空、连续、长度为偶数的十六进制字符串：

- 字符只能为 `0～9`、`A～F` 或 `a～f`。
- 不带 `0x` 前缀，不含内部空白。
- 每两个字符表示一个字节。例如 `00FF` 表示两个字节 `0x00`、`0xFF`。

必须先验证整行文本与整个 hex 参数。若文本非法，输出：

```text
INPUT_ERROR lineNumber
```

非法文本行不得向字节流追加任何字节，也不得改变流状态。即使 hex 的前半部分看似可解码，也不能先处理它。

合法且处于运行状态时，该分片追加到当前字节流。每条完整且合法的消息都立即产生对应输出；未完成消息保留到后续分片。

### 4.2 结束当前字节流

```text
END
```

- 若当前流仍在运行且有未完成消息，输出 `TRUNCATED` 错误。
- 若没有剩余字节，不输出。
- 执行后当前流停止，只有 `RESET` 可以开始新流。
- 已停止的流再次收到合法 `END` 时，不输出。

### 4.3 开始新字节流

```text
RESET
```

丢弃当前未处理字节，清除停止状态，开始一条新的独立字节流。新流偏移从零开始。

合法 RESET 不输出；丢弃旧流残留时也不报告截断。

程序启动时等价于已经执行一次 RESET。物理 EOF 到达时，若当前流仍在运行，按 END 的规则处理；已停止则不再输出流错误。

### 4.4 文本错误

空行、未知命令、缺少或多余参数、非法 hex，均输出 `INPUT_ERROR lineNumber`，并继续处理下一行。

行号按整个文本输入从 1 开始计算，空行、END 和 RESET 都占一个行号；RESET 不重置文本行号。

文本层校验始终执行。当前流已经停止时，合法 FEED 被忽略；非法 FEED 仍按文本错误处理。

## 5. 二进制错误及判定顺序

二进制流错误输出：

```text
ERROR offset code
```

offset 为出错消息第一个字节在**当前字节流中的零基偏移**，与文本行号无关。RESET 后重新从零计算。

| code | 含义 |
| --- | --- |
| `LENGTH` | totalLength 小于 10 或大于 1024 |
| `VERSION` | version 不是 1 |
| `CHECKSUM` | Trailer 校验和不正确 |
| `BODY_LENGTH` | 已知类型的 Body 长度与规定布局不符 |
| `FIELD` | 已知类型字段值非法 |
| `TRUNCATED` | END 或物理 EOF 到达时，仍有未完成消息 |

错误判定时机及优先级如下：

1. 剩余字节不足 2 个时等待后续分片；否则校验 totalLength，非法立即报告 LENGTH。
2. 长度合法但 Header 尚不足 8 字节时等待。Header 完整后校验 version；非法立即报告 VERSION，不必等待 Body 和 Trailer。
3. Header 合法但尚未收到 totalLength 个字节时等待。
4. 完整消息到齐后，先校验 CHECKSUM。
5. 校验和正确后，验证已知消息的 Body。

对于 H，Body 非空时报 BODY_LENGTH。

对于 Q/T，Body 验证顺序为：

- 若连 symbolLength 字段本身都不存在，报 BODY_LENGTH。
- symbolLength 不在 1～8 时，报 FIELD。
- Body 长度与该 symbolLength 对应的长度不相等时，报 BODY_LENGTH。
- 之后才检查 symbol 字符、买卖价关系、数量、tradeId 和 side 等字段；不合法时报 FIELD。

未知类型不进行已知 Body 的长度或字段校验。

每条消息最多报告一个二进制错误。错误发生后：

- 当前流立即停止。
- 该错误消息不产生正常消息输出。
- 当前 FEED 中位于错误消息之后的字节，以及后续合法 FEED 的字节，均忽略。
- 错误发生前已经完整处理的消息输出仍然有效，包括同一条 FEED 中的合法前缀消息。
- 直到 RESET 才恢复解析。无需重新搜索或猜测下一条消息边界。

## 6. 输出与正确性要求

- 每条合法消息恰好输出一行，保持其在字节流中的原始顺序。
- 合法消息的输出结果不得受分片位置影响。分片可以发生在长度、序号、字符串、整数和 Trailer 的任意字节之间。
- 只有完整消息通过全部校验后，才能输出该消息的正常结果。
- 不得读取超出当前已收到字节或当前帧边界的数据。
- 十进制输出不保留前导零；负数使用一个前导减号。
- 字段之间恰好一个空格，不得有行末空格、浮点格式、调试日志或额外解释。
- 不要求实现真实网络连接、消息构造器或行情序号恢复。

## 7. 数据规模

- 每条 FEED 解码后最多 4096 字节。
- 所有合法 FEED 提供的字节总数不超过 2 MiB，包括停止状态下被忽略的分片。
- 输入最多 `2 × 10^5` 行。
- 单条消息总长度最多 1024 字节。
- 只允许使用 C++ 标准库。
