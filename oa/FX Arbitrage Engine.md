# FX Arbitrage Engine（外汇套利负环检测）

> 自拟 C++17/20 两小时 OA 综合题，**不是已核实的 DRW 真题**。
> 重点：有向图建模、Bellman-Ford、Negative Cycle、动态报价更新。
> 建议用时：120 分钟。P0。

## 1. 背景与任务

交易系统维护多种货币之间**可执行的有向兑换报价**。一条报价 A -> B、兑换率 r 的含义是：在不考虑数量上限的理想条件下，持有 x 单位 A，可以兑换成 x*r 单位 B。

报价具有方向性：A -> B 不意味着 B -> A 存在，更不意味着反向兑换率是 1/r。实际 Bid/Ask 需要分别转换成可执行方向；本题输入已经完成此处理。

如果存在一条从某货币出发、沿若干有向兑换边返回同一货币、最终金额**严格大于初始金额**的回路，则认为当前图存在理论上的 FX 套利。

系统支持新增/替换报价、删除报价，以及检查**任意币种**是否存在套利。所有操作按输入顺序生效；每次 CHECK 针对最新报价快照。

本题不考虑资金规模、成交滑点、固定手续费、对手方信用、订单簿深度或行情时间戳。

## 2. 输入格式

~~~text
N Q
currency1 currency2 ... currencyN
command1
...
commandQ
~~~

- 货币代码由 1~8 个大写 ASCII 字母构成，彼此唯一。
- 每个命令独占一行。

| 命令 | 含义 |
| --- | --- |
| SET from to numerator denominator | 设置 from -> to 的有效兑换率 numerator/denominator；如已存在则完全替换 |
| DEL from to | 删除对应有向报价；不存在则无操作 |
| CHECK | 判断当前图的任意位置是否存在套利回路 |

SET 两端货币必须不同，分子分母均为正整数。与反方向报价彼此独立。

## 3. 输出格式

每条 CHECK 恰好输出一行：

~~~text
YES
~~~

或：

~~~text
NO
~~~

本题基础版只判断套利是否存在，不要求返回具体货币路径。

数学定义：

- 某条有向回路的总兑换倍数 R = r1*r2*...*rk。
- 存在 R > 1 的回路时输出 YES，否则 NO。
- 单个币种无自环，因此有效回路至少包含 2 条边。

## 4. 样例一：报价更新使套利消失

输入：

~~~text
3 8
USD EUR JPY
SET USD EUR 9 10
SET EUR JPY 160 1
SET JPY USD 7 1000
CHECK
SET JPY USD 69 10000
CHECK
DEL USD EUR
CHECK
~~~

输出：

~~~text
YES
NO
NO
~~~

解释：

- 最初 USD -> EUR -> JPY -> USD 的乘积是 0.9*160*0.007=1.008，存在约 0.8% 理论套利。
- 更新后乘积变成 0.9*160*0.0069=0.9936，不盈利。
- 删除 USD -> EUR 后不再形成该回路。

## 5. 样例二：不相连的图中也可能存在套利

输入：

~~~text
4 5
USD EUR JPY SGD
SET USD EUR 1 2
SET EUR USD 2 1
SET JPY SGD 2 1
SET SGD JPY 3 4
CHECK
~~~

输出：

~~~text
YES
~~~

解释：USD/EUR 回路乘积等于 1，不构成套利；JPY -> SGD -> JPY 乘积为 1.5，构成套利。不能只从 USD 出发查找。

## 6. 约束与浮点数规则

- 1 <= N <= 100；1 <= Q <= 20000。
- 1 <= numerator, denominator <= 1000000。
- 最多同时存在 2000 条有向报价。
- CHECK 总数不超过 20，且各次 CHECK 的 N*E 之和不超过 4000000。
- 为避免边界舍入争议，测试保证：任何存在的简单有向回路，其兑换乘积若不等于 1，则与 1 至少相差 10^-6；不会设置必须依赖小于此数量级利润才能判对的用例。
- 按实数数学语义判定。允许使用 long double 与合理的浮点容差；不要求精确大整数有理数运算。
- 输入合法，不要求处理未知币种或非法命令。

## 7. 正确性要求

- 不能把简单的 Cycle Detection 当作 Arbitrage Detection：一般有向环可能亏损或恰好不赚不赔。
- 不能先把所有报价当作双向图。
- 不能直接相乘大量兑换率：长回路容易产生上溢/下溢。
- 更新已有报价不能保留旧权重；DEL 后报价必须真正失效。
- 必须检查不连通的所有分量。
- 只需要判断**某处**存在套利，不要求从 USD 或任何特定货币可达。

## 8. 算法目标

可使用权重变换：

~~~text
weight(A -> B) = -log(rate(A -> B))
~~~

套利回路当且仅当对应的权重和为负。CHECK 可用 Bellman-Ford 判断图中是否存在负环：等价于添加一个对所有货币都有 0 权重边的超级源点，或者把所有初始距离置 0。

目标：单次 CHECK 为 O(N*E)，SET/DEL 使用合适的数据结构维护最新有向边。

## 9. 加分扩展（不属于必做）

1. 返回一条真实套利货币路径，包括首尾相同的货币；说明如何利用第 N 轮松弛更新的 parent 恢复负环。
2. 给每条边增加比例手续费 f：有效兑换率为 r*(1-f)，且 f 在 [0,1)；分析为什么仍然能做对数变换。
3. 报价中加入 sequence、timestamp、ttl，解释同序号冲突、stale quote 和快照一致性的处理。
4. 支持路径需要至少 K 单位基础货币或每条边有容量上限的情况；说明单纯的负环检测为何不足以保证实际可执行套利。
5. 如果更新极多、CHECK 极少，讨论“更新时缓存结果”与“查询时重算”的权衡。

## 10. 自测清单

- 零条边；仅一条有向边；没有环；多连通分量。
- 环倍率恰好 1；大于 1；小于 1。
- 反向报价缺失；两货币有双向报价但不套利。
- 更新引入负环；更新移除负环；删除边破坏负环。
- 负环不从第一个货币可达；多个负环同时存在。
- 自测大、极小有效汇率，以及 logarithm 的数值稳定性。
