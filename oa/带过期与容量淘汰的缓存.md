# 带过期与容量淘汰的缓存

**TTL & LRU Cache**

> 自拟 C++17 OA 练习，建议限时 120 分钟，并非已核实的 DRW、Tower Research 或其他公司的原题。缓存语义以本文为准。

## 题目

实现一个单线程缓存，键为字符串，值为整数，同时支持：

- 按条目设置有效期（TTL）。
- 容量不足时，按最近最少使用（LRU）规则淘汰。
- 读取、只读查看、删除和动态调整容量。
- 查询当前缓存内容及其访问顺序。

从标准输入逐行读取命令，直到 EOF。所有命令严格按输入顺序处理，使用题目定义的逻辑时间。

## 1. 数据与初始状态

### 1.1 字段与范围

| 字段 | 含义与范围 |
| --- | --- |
| `key` | 长度 1～16，仅含 ASCII 字母、数字或下划线，区分大小写 |
| `value` | 有符号整数，范围 `-10^12～10^12` |
| `capacity` | 最大条目数量，整数，范围 `0～2 × 10^5` |
| `ttl` | 本次写入的有效时长，整数，范围 `1～10^9` |
| `now` | 全局逻辑时间，整数，范围 `0～10^12` |

容量按**条目数量**计算，与值的大小无关。每个键最多对应一个当前条目。

### 1.2 初始化

程序初始尚未初始化。只有合法的 `INIT` 命令可以初始化缓存。

初始化后，当前时间为 0，缓存为空。重复初始化属于错误，不能用 `INIT` 清空或重置已有状态。

## 2. 核心规则

### 2.1 有效期

每次成功存储 `PUT key value ttl` 时，该条目的过期时刻为：

```text
expiresAt = 当前 now + 本次 ttl
```

条目仅在 `now < expiresAt` 时有效。当 `now == expiresAt` 时，条目已经过期。

- TTL 从成功写入时计算，不从首次读取时计算。
- 覆盖已有键时，完整替换值和过期时刻，即使新值与旧值相同。
- 读取、查看、删除其他键、调整容量和查询缓存内容，都不会延长有效期。
- TTL 为 0 属于错误，不表示立即删除，也不表示永久有效。
- 过期条目必须移除，不再占用容量。
- 同一个键被覆盖、删除后重建或淘汰后重新写入时，只以**当前条目的最新过期时刻**判断有效期；此前版本的过期时刻不应影响新条目。

只有合法的 `TIME` 命令会改变时间。不使用机器时钟，处理其他命令也不会自动推进时间。

### 2.2 LRU 顺序

缓存中的有效条目具有一个从最近使用（MRU）到最久未使用（LRU）的完整顺序。

以下操作会把目标条目移到 MRU：

1. 成功存储的 `PUT`，包括插入新键和覆盖已有键。
2. 命中的 `GET`。

其他操作均不把条目移到 MRU，包括：

- 未命中的 `GET`。
- `PEEK`，无论是否命中。
- `DUMP`。
- `TIME` 与 `RESIZE`。
- `ERASE`；删除目标后，其他条目的相对顺序保持不变。

最近使用顺序由**输入命令的处理先后**决定，与逻辑时间是否变化无关。同一逻辑时刻的多次成功访问仍依次刷新顺序，不存在并列的最近使用位置。

条目过期、被删除或被淘汰时，将其从顺序中移除，不改变其他条目的相对顺序。

### 2.3 容量与淘汰

每条合法命令处理完毕后，缓存条目数量不得超过当前容量，且所有条目都必须有效。

写入时：

- 容量为 0：不存储新值。
- 键已存在：覆盖该键，不因覆盖而淘汰其他键。
- 键不存在且有空余容量：直接插入。
- 键不存在且缓存已满：淘汰当前 LRU 条目，然后插入新条目。

淘汰是永久移除；之后增加容量或推进时间，都不会恢复被淘汰的条目。

容量判断只考虑当前未过期的条目。推进时间时，必须在该条 `TIME` 命令结束前完成全部到期条目的移除。

## 3. 输入命令与输出

字段以空格或制表符分隔，允许行首、行尾有空白。每条命令占一行，命令名区分大小写。

### 3.1 初始化

```text
INIT capacity
```

设置初始容量，当前时间为 0，缓存为空。

输出：

```text
INIT capacity
```

初始化前执行其他任何命令，或初始化后再次执行 `INIT`，均属于错误。

### 3.2 推进时间

```text
TIME t
```

要求 `t >= now`，否则属于错误。

将当前时间设置为 `t`，移除所有满足 `expiresAt <= t` 的当前条目。

输出：

```text
TIME t expiredCount
```

`expiredCount` 为本条命令实际移除的条目数量，不包含此前已被删除、覆盖或淘汰的旧版本。

过期移除不输出逐条记录，也不输出 `EVICT`。重复设置相同时间是合法操作。

### 3.3 写入

```text
PUT key value ttl
```

按照第 2 节规则进行插入或覆盖，并刷新成功存储条目的 LRU 位置与过期时刻。

成功存储时先输出：

```text
PUT key STORED
```

若本次为了插入新键而淘汰了一条旧条目，随后追加一行：

```text
EVICT evictedKey evictedValue
```

每条 `PUT` 最多淘汰一个条目。覆盖已有键或使用空余容量插入时，不输出 `EVICT`。

容量为 0 时，不存储条目，输出：

```text
PUT key SKIPPED
```

即使容量为 0，也必须完整校验键、值和 TTL。非法写入输出错误，不能输出 `SKIPPED`。

### 3.4 读取并刷新最近使用顺序

```text
GET key
```

命中时，将该条目移到 MRU，输出：

```text
GET key value
```

未命中时输出：

```text
GET key MISS
```

命中不会改变过期时刻。整数值 `-1`、`0` 均为普通有效值，不表示未命中。

### 3.5 查看但不刷新最近使用顺序

```text
PEEK key
```

命中时输出：

```text
PEEK key value
```

未命中时输出：

```text
PEEK key MISS
```

无论是否命中，都不改变 LRU 顺序或过期时刻。

### 3.6 删除

```text
ERASE key
```

键存在时，将其移除，输出：

```text
ERASE key REMOVED
```

键不存在时输出：

```text
ERASE key MISS
```

删除不存在的键是合法操作。手动删除不输出 `EVICT`。

### 3.7 调整容量

```text
RESIZE capacity
```

将容量设为给定值。

若当前条目数量超过新容量，反复移除当前 LRU 条目，直到数量满足新容量。每次淘汰的对象都按移除前的 LRU 顺序确定。

先输出：

```text
RESIZE capacity evictedCount
```

随后按实际淘汰顺序输出恰好 `evictedCount` 行：

```text
EVICT evictedKey evictedValue
```

增加容量或重复设置相同容量是合法操作，不刷新任何条目的最近使用顺序或有效期。

容量设为 0 时，必须淘汰全部条目。之后重新增加容量，缓存仍为空。

### 3.8 查询全部内容

```text
DUMP
```

先输出：

```text
CACHE now capacity size
```

随后按 **MRU 到 LRU** 的顺序，输出恰好 `size` 行：

```text
ENTRY key value expiresAt
```

缓存为空时只输出首行，不增加空行。查询本身不改变任何状态。

输出中的所有整数均使用十进制，不保留前导零，不输出 `-0`。

## 4. 错误处理

错误命令输出：

```text
ERROR lineNumber
```

`lineNumber` 为整个输入中的行号，从 1 开始。错误行和空行均计入行号；空行本身属于错误。

错误包括：

- 未知命令、字段数量不匹配或键格式非法。
- 数字格式或范围非法。
- 初始化前执行其他命令，或重复初始化。
- 时间倒退。

容量、TTL 和时间只接受十进制数字串；值允许一个可选的前导负号。所有数字字段均不接受前导加号、小数点或指数形式。合法数字允许前导零，值的 `-0` 与 `0` 相同。

一行存在多个错误时，只输出一行错误，不要求区分错误类型。

**错误命令必须完全不改变状态**，包括当前时间、容量、条目内容、过期时刻和 LRU 顺序，也不能产生任何淘汰记录。

输出错误后继续读取下一行。EOF 只结束输入，不隐式推进时间，也不输出额外内容。

## 5. 输入规模

- 总输入行数不超过 `2 × 10^5`，每行不超过 256 字节，不含换行符。
- 不同键的数量不超过 `2 × 10^5`。
- 所有 `DUMP` 输出的 `ENTRY` 行数之和不超过 `10^6`。
- 时间与过期时刻可能超过 32 位整数范围；`expiresAt` 可以大于允许输入的最大 `now`，所有数值及计算结果均在 64 位有符号整数范围内。
